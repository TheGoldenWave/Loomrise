### 执行耐久层建设顺序（R1→R5a）

R1/R2 是 S2-a 既有持久化与恢复 Gate 的实现拆分；R3/R4 是既有 Worker/业务治理要求的验证子项，R5a 对应云恢复与迁移。矩阵行不创设独立的新 Gate，也不新增平行业务状态。Task 的 [§7.1 重启裁决](TASK-SYSTEM-DESIGN.md#71-重启恢复裁决表2026-10-21-定) 优先于 Adapter replay：本地 `running` 旧尝试记失败，新尝试经重验后才可复用安全 checkpoint；等待态可恢复，执行端可完整查询的委派才重挂。

| 批次 | 先做什么 | 必须证明 | 暂不宣称 |
|---|---|---|---|
| R1 | `Run`、可选 `TaskAttempt` 关联与执行进度/store 接口；无副作用步骤的事务提交可见性、重启裁决、事件 lineage、旧 generation 拒绝。Checkpoint 是候选机制，非强制 API | 请求/幂等/事件不丢，旧中断事实保留；输入/版本兼容的已提交纯计算结果可复用，未提交纯计算可重算，同一业务事实不重复；JSONL 仅夹具/导出 | 没有业务写入 exactly-once、没有多 worker 安全，不要求完整 Task 调度 |
| R2 | 人工确认 suspend/wake、取消请求/确认、模拟或可回收工具副作用、`UNKNOWN` 对账、只读运行检查 | 确认上下文重新授权；副作用使用稳定幂等键和 `result_id`；未知不自动重写 | 不把 Adapter 成功当业务成功，不把 abort 当外部撤销 |
| R3–R4 | 后台 Worker 接管、嵌套 task/phase、有限重试与 crash-loop parking；真实工具沙盒与评测/审批联动 | stale worker 无法写入；parking 可查询、可人工恢复；RunEvent 与 Adapter 证据可互查 | 不宣称生产云恢复或供应商跨系统恰好一次 |
| R5a | 多进程/多 worker、备份恢复、升级迁移和云端存储替换 | 干净实例恢复、迁移校验、旧版本/旧 worker 处理有记录 | 未通过云 Gate 前不宣称自有云耐久执行 |

最低故障集固定为：事务提交前后崩溃、旧 `running` 尝试裁决与兼容结果复用、重复提交、确认等待恢复、R1 旧 generation 拒绝、R2 取消竞争/迟到执行输出拒绝、工具未知结果对账。纯计算是否重算按是否越过提交线区分，不将模型调用或实时检索假定为纯步骤；跨进程 Worker 接管留 R3/R4。具体测试文件、证据路径与不做边界见 [实施计划](superpowers/plans/2026-10-23-durable-run-adapter.md)。

## S1 细化方案：被动响应纵向样例

S1 只证明“用户发起对话后，Agent 能在证据、权限和业务结果约束下完成一次可回放任务”。线上实践中常见的阶段、路由、规则和工具配置，在 S1 中只抽象为公开、虚构、可审计的配置层，不复制任何真实业务配置。

### S1 配置分层

| 配置层 | S1 要表达的内容 | 约束 |
|---|---|---|
| `ContextSnapshot` | 当前阶段、已知事实、事实来源与有效期 | 已知事实不可由模型补造；过期信息需显式标记 |
| `RequestRouting` | 当前消息为何进入某个业务请求、唯一下一步 | 每轮只选择一个主请求；路由理由写入事件 |
| `Skill/SOP` | 目标、适用条件、下一步、退出与转人工条件 | Skill 只描述策略，不授予权限 |
| `HardRule` | 身份/权限、禁止动作、确认要求、停止和去重 | 在模型外执行；违反即阻断；按全局/任务/Skill 作用域和稳定规则 ID 管理，不把每个 badcase 直接变成新规则 |
| `ToolPolicy` | 工具输入、权限、确认、幂等、超时和结果 | 写工具必须有模拟副作用和结果 ID |
| `Outcome` | 任务状态、业务结果、失败/未知原因 | 模型声称完成不算业务完成 |

### S1 渐进式上下文加载

渐进式加载是执行机制，不是第七个业务配置层。它解决的是“哪些信息在当前阶段进入模型上下文”，而不是“哪些规则具有约束力”。`HardRule` 仍始终在模型外裁决；只有与当前任务相关的有效约束摘要才需要注入模型。

S1 只实现三段式最小策略：

1. **常驻基线**：会话身份、输出合同、全局安全/确认要求和当前任务摘要。
2. **任务局部**：路由确定后，仅加载当前任务和命中的一个 `Skill/SOP`，不把所有 Skill 与全部资料放入上下文。
3. **按需证据**：模型或执行内核需要回答事实、调用工具或解释结果时，才加载相关知识片段、字段说明或工具结果。

每次加载、跳过、过期或预算截断都写入 `RunEvent`，至少记录来源引用、作用域、选择原因、版本/哈希和 token 估算。S1 不实现自动摘要、跨会话记忆优化、复杂检索编排或按效果自动调参；这些留到 S2 及以后。

### S1 工作包

1. **合同与夹具**：实现一个虚构课程咨询 `ScenarioPack`，冻结 `AgentSpec`、`AgentVersion`、`ServiceRequest`、`RunEvent`、`ToolManifest`、`Case` 和 `EvalSet` 的最小可验证样例，并为上下文片段标记作用域、触发条件、优先级和 token 预算。
2. **被动文本运行**：固定一个模型和一个 AgentScope 版本，完成路由、知识引用、确认、模拟写入和结构化事件。
3. **网页语音入口**：固定一条 Pipecat 最小链路；只负责输入、打断、生成、发送和播放状态，业务请求仍进入同一 `ExecutionService`。
4. **事实与证据**：保存配置版本、知识引用、上下文加载/跳过决定、工具调用、确认、结果 ID、失败、取消和成本；外部 Trace 只作为投影。
5. **人工验收与回放**：已准备 11 个正反例，覆盖成功、资料缺失、拒绝、重复提交、工具失败、超时未知、模拟语音、上下文预算和确认点取消。只做固定案例隔离回放，不建设候选版批量发布门禁。
6. **可迁移交付包**：导出虚构资料、配置、模拟工具、案例、依赖清单和运行说明；不含密钥、真实数据或私有业务字段。

### S1 退出 Gate

- 文字和语音使用同一个 `request_id`、`AgentVersion`、权限判断和业务结果。
- 同一确认最多产生一次模拟业务写入，并有稳定 `result_id`。
- 失败、取消、超时、未知播放状态均能在 `RunEvent` 中被区分。

### 主动触达的后续边界（S1 只预留，不实现）

条件触达的 `OutreachPolicy` 是专家任务蓝图内的约束，不是独立共享策略对象；触发、优先级、冷却/频控、许可条件、去重、停止、回执与完成判据随 AgentVersion 冻结。规则或 Agent 先提出候选，经采用判定和最新权限/频次/占用重验后进入同一 `ServiceRequest/RunEvent` 体系；不能另建业务状态、绕过许可或修改硬规则。完整初始化、版本与实例调整合同以[Task 设计](TASK-SYSTEM-DESIGN.md)为准。

## S2-c 可控改进验收

S2-a 开始保存版本与运行证据，S2-c 验收“运行证据 → 轨迹归一化 → 失败归因 → Candidate Skill/ChangeProposal → 沙箱验证 → 审批发布”的最小自进化链路。候选只允许修改 Skill/SOP 文本、示例、澄清顺序和有限检索参数；工具权限、业务承诺、价格条款、硬规则、工具副作用、结果语义和代码执行不允许静默自改。

候选 Skill 必须记录来源 Run/Case、父版本、结构化 diff、依赖的知识/工具版本、验证环境、token/工具成本变化和拒绝/回滚原因。提议者、执行 Agent 与评估/审计者逻辑隔离；候选只能进入 `candidate → validated → approved → released` 的版本流程，不能由生成它的同一轮上下文直接宣布有效。

评测至少分开开发、验证和盲测样本，并固定评审规则；还要覆盖旧案例回归、分布外/迁移样本、硬规则与副作用裁决，以及 token、工具调用、延迟和失败回退成本。候选必须经过同版本固定集回放、独立规则或人工复核和显式审批；坏候选不能发布，评测失败时保留旧版本也是正常结果。

S2 的发布 Gate 采用冻结资料/工具模拟环境的旧版与候选版配对批量回放。`Case` 的 ground truth 优先描述业务状态、必须/禁止动作和预期持久副作用；确定性规则裁决越权、重复写入、未确认写入与结果缺失，机评只补充软质量并由人工校准。各场景质量/成本阈值要在跑候选版前登记，不能根据本次结果回填；通过离线门禁后仍需审批，真实渠道另做契约与小范围验证。

## 开源传播节奏

按真实工件公开：场景包 → 单机启动视频 → 文字/语音同场景对照 → Trace 到改动提案 → 回放/回滚 → 可复现交付包。公开数据需标注“模拟”，性能数字需注明设备、模型、网络、样本和采集方法。

首版不会宣称生产级、真实企业合作、统计显著或已证明自主进化。公开仓库不发布个人品牌策略、预算演算、未确认商业化假设和私人研究材料。
