# 配置化优化需求 · 新布局对现状差距 v0.1

日期：2026-10-26。状态：**需求提案，待评审排期**。范围：把 [线框预览 v0.2](CONFIG-UI-PREVIEW.md) 的新布局与 `prototypes/console-next` 当前实现逐页对照，列出要改什么、改到什么程度算完成。上游裁决见 [配置重构与编排画布产研需求](PRODUCT-CONFIG-OPTIMIZATION.md)，运营原始诉求见 [运营视角配置需求清单](OPERATOR-CONFIG-REQUIREMENTS.md)。不改六层合同、ROADMAP Gate 与 ROUTE-GRAPH v1.0。

## 0. 本轮已定的决策

| 编号 | 决策 | 理由 | 影响 |
|---|---|---|---|
| DEC-1 | **"专家"不改名** | 平台覆盖客服、销售两类岗位的托管，落到行业叫法各异（顾问、专员、客服、管家），"专家"作上位概称 | 行业叫法放在专家名称里（例："课程咨询顾问"）；线框预览 v0.2 已撤回改名提议 |
| DEC-2 | 界面用词按 [线框 §1](CONFIG-UI-PREVIEW.md#1-界面用词表) 执行 | 内部词只留在文档、接口与"技术详情" | 合同与代码标识不改，只改界面文案 |
| DEC-3 | 流程图必须做，且是一等页面 | 见产研方案；与列表共用同一份数据 | 当前没有任何画布代码，属于新建 |

| 测试 | "案例与回放"：从运行提名坏例、编辑真值、人工复核、回放；状态有待复核 / 待重新回放 / 通过 / 失败 | `surfaces.js:174-182` |
| 上线 | 版本页三个独立动作：运行沙盒检查 → 人工批准 → 绑定到入口；冻结版本可"恢复为新草稿" | `surfaces.js` `renderVersions`；动作 `sandbox-check/approve/publish`、`version-restore` |
| 待办 | 分散在 5 处：配置模块徽标、"当前优先处理"、专家列表、版本页"去处理"、就绪清单 | `editor.js:83`、`:120-135`；`domain.js:70-91` |

**结论**：新布局里，可以直接改造现有代码的是导航、专家列表、知识库问答、测试、上线、试一试、依据面板；需要**新建**的是核对新资料、关键信息、可编辑红线、流程图、待处理队列。另外，所有"真实"能力（解析文件、真实工具、真实模型）都卡在前端还没接后端这一处。

## 3. 需求明细

格式：现状 → 要求 → 验收。P0 是新布局成立的前提，P1 是体验完整度。

### 3.1 壳层与全局

**CG-01 导航扁平化（P0）**
- 现状：`shell.js` 4 组 16 路由；专家下挂"业务概览 / 专家配置"子页；顶部三档深度 tab。
- 要求：选中专家后，导航为 首页 / 知识库 / 红线 / 业务办理 / 对话流程 / 测试 / 上线，底部是设置。网站客服窗、联系页、会话收件箱归入"上线"页的"接在哪"区，或者作为专家外的工作区页面；物料库、模型连接、部署与维护进设置。**取消三档深度 tab**，改为各区块就地"更多设置"。
- 验收：选中专家后导航一级项 ≤ 8；全站没有"业务概览 / 业务配置 / 详细配置"切换；原 16 个路由都有新归属，映射表进 PR 描述。

**CG-02 统一待处理队列（P0）**
- 现状：待办来自 `validateConfig` 文本、`readiness()` 就绪项、模块徽标，各算各的；模块归属用正则匹配报错文本（`editor.js:90-96`）。
- 要求：新增一个 `pendingItems(agent)`，返回结构化条目 `{ id, level: 'block' | 'suggest', page, target, text, fix }`。`validateConfig` 改为返回带字段路径的对象，不再靠正则归属。导航红点、首页"现在先做"、专家列表"要处理的事"、上线页"能上线吗"全部从这一处取数。顶栏显示"待处理 N"，点开即队列。
- 验收：删掉 `issueFor` 正则后，所有原有缺项仍能落到正确页面；同一草稿下，5 个位置的计数一致（单测断言）。

**CG-03 全局"试一试"面板（P0）**
- 现状：独立"试用台"页面；配置页右侧另有"编辑预览"tab。
- 要求：顶栏"试一试"在任何专家内页面打开右侧面板；问答页"试这一条"预填问题打开同一面板。面板每次显示一轮答复、一行依据（几处知识、是否命中红线）、"对 / 答错了"；"答错了"进待处理队列，同时可一键转为测试题。试用台页面保留为"看完整对话"的落地页。
- 验收：从 7 个一级页面都能打开且不丢当前页状态；"答错了"后待处理计数 +1。

### 3.2 专家列表与首页

**CG-04 专家列表改列（P1）**
- 现状：列为 专家/服务目标、草稿 r、资料数、入口绑定、操作。
- 要求：列改为 名称 / 状态（"线上运行中""有未上线修改""未上线"）/ 接在哪 / 要处理的事（取 CG-02 第一条 block，否则第一条 suggest）/ 下一步。修订号不在列表出现。名称下可加行业角色副标题（DEC-1）。
- 验收：列表上不出现 `r\d+`；"要处理的事"与首页"现在先做"一致。

**CG-05 首页空态与汇总（P0）**
- 现状：`renderOverview` 有就绪清单和"当前优先处理"；新建后落在表单上。
- 要求：没有任何资料时，首页就是三步引导（放资料 / 核对 / 试一试），带拖放区、"从示例模板开始"、"导入"。有资料后显示"现在先做"一件事 + 四列文字汇总（知识库 / 红线 / 业务办理 / 对话流程）+ 最近改动（带"依据"）。新建专家后直接进首页，不进表单。
- 验收：新建专家 → 首页空态 → 拖一个文件 → 进入核对页，全程不经过任何配置表单。

### 3.3 知识库

**CG-06 问答为一等列表（P0）**
- 现状：知识页按"资料（Source）"列出，一份资料一行；FAQ 类资料自带一问一答；状态标签是授权类（缺少授权、缺少来源、缺少有效期、仅登记）。
- 要求：知识库默认 tab 为"问答"，一行一个问答，记录它来自哪份资料。状态写全词：已审 / 待审 / 不一致 / 缺出处。授权类问题合并为"这批资料还没声明授权"，挂在资料批次上，不逐条显示。保留三个 tab：问答 / 关键信息 / 标准话术。"资料"作为来源视图放在"＋放资料"旁边的"按资料看"。
- 验收：一份资料拆出多条问答时，问答列表按条显示，资料列表仍为一行；授权缺失只在批次层报一次。

**CG-07 批量放资料与拆分（P0，依赖 CG-23）**
- 现状：一次一条表单；PDF/DOCX/XLSX 只登记，不解析（`knowledge.js:57`）。
- 要求：拖放多文件；XLSX/CSV 按行拆问答或关键信息，DOCX/PDF/TXT 按段拆问答候选；整批进入"核对新资料"。前端阶段可先支持 CSV/XLSX/TXT/MD（浏览器内解析），PDF/DOCX 经后端解析。授权按批声明一次（坚持项 U1），**不默认勾选**。
- 验收：拖入 1 份 30 行价格表和 1 份 10 段政策文本，系统生成 ≥ 35 条候选进入核对，不需要逐条填表。

**CG-08 核对新资料（P0）**
- 现状：无。不一致检测只看"问题完全相同、答案不同"（`domain.js:37-44`）。
- 要求：
  - 风险分组：含价格或金额、含承诺词（保证、一定、全额、免费）、与已有资料不一致的进"逐条看"；其余进"风险低"，随机抽 2 条展示，可整组确认。
  - 不一致检测扩展为三类：同一问题不同答案；同一关键信息不同数值；数值相同而限定不同（"3980"与"3980 起"）。命中后给"以哪个为准"单选。
  - 操作：对 / 改一下（就地编辑）/ 不该由 AI 答；键盘 1/2/3、←/→。
  - 整组确认 10 秒内可撤销（见 CG-22）。
- 验收：用注入样例跑（三类不一致各 3 例，共 9 例），检出 ≥ 8；风险低组里不出现含金额的条目。

**CG-09 关键信息对象（P0）**
- 现状：不存在，价格写在答案文本里。
- 要求：新增对象 `{ id, name, value, unit, effectiveFrom, sourceRef }`。问答答案用 `{关键信息名}` 引用；红线条件和办理入参也可引用。点值即改，改动框列出全部引用处，默认全选、可排除。缺出处的关键信息进 CG-02 的 block 级。映射到六层的 ContextSnapshot，不新增合同层。
- 验收：改一次价格，引用它的问答、红线、办理全部更新；试一试的答复里出现新值；依据面板记录这次改动和受影响的处数。

### 3.4 红线

**CG-10 业务红线可编辑（P0）**
- 现状：只有 3 条平台级锁定规则；业务方只能 `rule-propose`；转人工是独立配置（触发词 + 接收方）。
- 要求：分两类：
  - **我的红线**：随专家版本发布，可新增、改、停用。结构为"当 [条件] → [处理方式]"。条件 = 字段下拉 + 算子 + 值，或由模板提供的一句话。处理方式是闭集：转人工（带接收组）/ 请客户确认 / 不回答并说明 / 结束对话 / 稍后回复。
  - **平台底线**：只读、可见，写明原因；保留现有 3 条，并补齐模板里的通用底线。
  - 原转人工配置迁移为"处理方式 = 转人工"的红线；触发词变成"客户说了 [词]"条件。
- 裁决仍在模型外执行，复用 `loomrise/rules.py`。条件深度受 `validation.py` 限制，界面上不允许拼出超限的条件。
- 验收：运营新增"客户情绪是投诉 → 转人工"，发到测试环境后，试一试输入投诉语句时命中该红线；平台底线在界面上没有编辑入口。

**CG-11 红线模板与命中次数（P1）**
- 要求：提供"从常用里选"（退款转人工、投诉转人工、报价超额需确认、资料无价格不报价等 ≥ 8 条）；每条显示近 7 天命中次数，0 次时进 suggest 级待处理。前端阶段，命中数从本地运行记录统计。
- 验收：从模板加一条只需 ≤ 2 次点击加填一个参数。

### 3.5 业务办理

**CG-12 办理卡合一（P0）**
- 现状："业务动作"与"结果与验收"是两个模块；结果是两段自由文本。
- 要求：一项办理一张卡，字段为：要问客户（入参，可从关键信息选值）/ 办之前是否需客户确认（写入类强制开启，保持 `store.js:239` 的约束）/ 办成标志（必选一个结果 ID 字段）/ 办不成时（处理方式闭集）/ 结果不明时（默认"先查一次，不重复提交"）。超时、幂等键、接口地址收进"技术详情"。
- 验收：写入类办理无法关闭"需客户确认"；未填办成标志的办理进 block 级待处理。

**CG-13 至少一个真实办理（P0，依赖 CG-23）**
- 现状：全部模拟。
- 要求：试听预约接一个可回滚的真实沙盒接口，结果走 `durable_store.commit_write`，三种结果分开统计，"结果不明"单列。
- 验收：跑 20 次（含 2 次人为超时），统计里成功、失败、结果不明分开，结果不明的不会被重复提交。

### 3.6 对话流程

**CG-14 流程数据升级为图（P0）**
- 现状：`config.flow` 是线性数组 `{ id, title, instruction }`；`skills` 另存。
- 要求：按 [ROUTE-GRAPH](ROUTE-GRAPH-AND-UNITS.md) v1.0 存为节点 + 边。节点类型闭集：开始 / 判断 / 办理 / 回复 / 转人工，没有万能节点和代码节点。判断节点的出边带意图名和例句（≥ 3 句）。红线通过规则 ID 挂到边或节点上，不复制规则内容。现有线性 `flow` 自动迁移为"开始 → 回复链"，`skills` 迁移为回复节点的说明。流程图和列表读写同一份数据。
- 验收：老草稿打开后自动迁移，内容不丢；导出 JSON 能通过 ROUTE-GRAPH 九条校验中已实现的部分。

**CG-15 流程图视图（P0）**
- 现状：无。
- 要求：按 [编排视图前端方案](S2-ORCHESTRATION-UI.md) 选型实现。默认只显示路径；"显示红线""显示实际走向"两个开关默认关。节点前写类型字，不用符号图例。选中节点后底部条显示"要问什么 / 办成标志 / 编辑 / 依据"。
- 验收：在 1440 宽屏下，5 个分支、12 个节点的流程一屏放下，不需要缩放。

**CG-16 结构化加分支与非阻断校验（P0）**
- 要求：判断节点下"＋加一个分支"弹出三问（客户想做什么 / 例句 / 然后：用知识库答、办一件事、转人工），确认后系统生成节点和边；拖拽只用来调位置。草稿随改随存；校验问题（缺转人工出口、写入前缺确认、孤立节点）只进 CG-02 的 block 级，**不阻止保存**，只阻止上线。
- 验收：5 名未接触过的运营只拿到一句任务描述，≥ 4 人能完成"加一个分支"（[线框 §18](CONFIG-UI-PREVIEW.md#18-上手度量评审时用) 的度量）。若达不到 80%，按产研方案的否决条件，把流程图降为只读评审视图，编辑走列表。

**CG-17 流程列表带层级（P1）**
- 现状：线性列表，只能上移、下移、删除。
- 要求：缩进表示分支层级，列为 步骤 / 做什么 / 用到的知识或办理 / 红线 / 办成标志；批量加红线、批量改确认要求；键盘 ↑↓ Enter 可操作。不显示读写字段。
- 验收：20 个节点以上时，用列表完成"给 5 个分支各加一条红线"比在流程图上少 50% 以上的操作步数。

### 3.7 测试与上线

**CG-18 测试题变差决策（P0）**
- 现状：案例有待复核 / 待重新回放 / 通过 / 失败；从运行记录提名坏例、编辑真值。
- 要求：界面改称"测试题"，状态"变差"替代"失败"中的回归部分。点开一条显示 输入 / 期望 / 这次答 / 判定，变差时必须二选一：答案错了（上线时拦下）/ 测试题过时了（以这次为准，记录为真值修订，走人工复核）。列表加"最近 5 次"。
- 验收：存在未决定的变差题时，上线页"申请上线"不可用；选"题过时了"会在依据里留下修订记录。

**CG-19 上线页简化与回滚（P0）**
- 现状：沙盒检查 / 人工批准 / 绑定入口三个按钮；冻结版本可"恢复为新草稿"。
- 要求：两个主按钮"发到测试环境"（自动跑检查，无需批准）、"申请上线"（人工批准，保持 U2）；另加"回到上一线上版"，把入口绑定切回上一个冻结版本，不改草稿。改动摘要用业务语言（新增几条问答、哪个关键信息从几改到几、新增了哪条红线、流程加了哪个分支）。
- 验收：从草稿到测试环境 1 次点击；回滚后入口引用上一版本，草稿不变。

**CG-20 依据面板（P1）**
- 现状："版本与变更依据"是第 10 个配置模块，显示字段路径（如 `handoff.condition`）。
- 要求：移出模块列表，改为右侧面板，与"试一试"共用位置。显示五问：从哪来 / 哪一版 / 谁改的 / 影响谁 / 凭什么，每问一行；"凭什么"能跳到具体运行记录。版本号、批次号、运行 ID、字段路径收进"技术详情"。
- 验收：问答、关键信息、红线、办理、流程节点 5 类对象都能打开依据；默认视图里不出现字段路径。

### 3.8 横切

**CG-21 界面用词约束（P0）**
- 现状：术语测试只查 8 个英文词。
- 要求：把 [线框 §1](CONFIG-UI-PREVIEW.md#1-界面用词表) 左列的中文内部词（装载、编排、验收、守卫、沙盒、口径、事实、结果承诺、运行叠加、证据抽屉、修订 r 等）加入 `terminology-browser-check.js`，"技术详情"折叠区内的文字除外。合并重复的免责文案，只留顶栏一处环境标识。
- 验收：走完 7 个一级页面，界面内部词命中 0。

**CG-22 保存与撤销（P0）**
- 现状：写操作后已调用 `save()`，但界面仍有"保存草稿"按钮和"有未保存修改"状态。
- 要求：删除手动保存按钮，顶栏显示"已自动保存"或"保存失败 · 重试"；保留导出草稿。整组确认、关键信息批量同步、批量改红线三类操作给 10 秒撤销条。
- 验收：全站没有"保存草稿"按钮；三类批量操作都能在 10 秒内撤销并恢复原值。

**CG-23 前端接通后端（P0，阻塞 CG-07 / CG-13 和真实试一试）**
- 现状：`console-next` 只用 localStorage；`loomrise/web.py` 有独立页面，两者没有连接。
- 要求：在 `loomrise/web.py` 上提供最小 API：草稿读写、文件解析、试一试（真实模型）、办理调用、运行记录读取。前端保留本地模式作为离线演示。接口不对外网暴露，**仅本机监听**；若要对外，需另加鉴权。
- 验收：同一草稿在本地模式和接后端模式下行为一致；后端模式下试一试产生的运行记录可被依据面板打开。

## 4. 落版建议

与产研方案的 V1 / V2 对齐，按依赖排序。

| 批次 | 需求 | 出口 |
|---|---|---|
| **V1-a 壳层与文案**（不依赖后端，先做） | CG-01、02、03、04、05、21、22 | 导航 7+1；待处理统一；空态可用；内部词 0 |
| **V1-b 知识与红线** | CG-06、08、09、10、12，CG-07 的浏览器内解析部分 | 冷启动 ≤ 90 分钟（OAT-1）；业务红线可编辑 |
| **V1-c 流程图与上线** | CG-14、15、16、18、19 | 加分支成功率 ≥ 80%；测试题变差可决策；可回滚 |
| **V1-d 接通** | CG-23、13，CG-07 的 PDF/DOCX 部分 | 一个真实办理；真实试一试 |
| **V2** | CG-11、17、20，CG-08 扩到全量 5 类不一致，流程图运行叠加 | 见产研方案 V2 出口 |

V1-a 可以和 V1-d 并行。V1-b、V1-c 前端部分先在本地模式完成，接通后再补真实数据。

## 5. 明确不做

- 不改"专家"一词（DEC-1）。
- 不新增合同层。关键信息落 ContextSnapshot；红线落 HardRule；办理卡落 ToolPolicy + Outcome；流程落 ROUTE-GRAPH v1.0。
- 流程图不做万能节点、代码节点、自由表达式条件。
- 测试题变差时不自动改真值，必须人决定。
- "申请上线"不能合并进"发到测试环境"。
- 任务与主动服务不进本轮配置主流程（R-21）。

## 6. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 数据迁移 | `flow`、`skills`、`handoff`、`rules`、`sources` 都要改形状，老草稿在 localStorage 里 | CG-14 / CG-10 带迁移函数和回归测试；迁移前自动导出一份 |
| 测试大面积失效 | 19 个前端测试文件里，导航、知识、术语相关的会失效 | V1-a 同步改测试，不跳过；`navigation-ui`、`knowledge-ui`、`terminology` 先改 |
| 流程图成本 | 新引入画布库，打包体积与无障碍都要处理 | 列表视图同时交付，作为无障碍和降级路径 |
| 后端暴露 | CG-23 新增本机 API | 默认只监听 127.0.0.1；对外前单独评审鉴权 |
| 不一致检测误报 | 规则太宽会让"逐条看"组膨胀，失去分组意义 | 用 CG-08 的注入样例同时测漏报和误报；逐条看组占比 > 40% 时调规则 |
