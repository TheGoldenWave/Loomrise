# 实时语音与后台任务协同验证计划 v0.1

状态：规划、待固定版本和运行实测，2026-09-26。2026-10-21 增补：全双工决策落点已定 **harness 工程式**，模型内全双工列为后续兼容方向（见下文候选表后注）。本文件不代表 Pipecat、Qwen Audio Agent 或 Gander 已在 Loomrise 接入，也不承诺任何上游项目提供开箱即用的双模型协同接口。候选项目的最新 API、许可证、资源要求和功能范围均须在实验前重新核对。

## 产品边界

已确认的 Loomrise 产品路线仍是单一交付工作台、统一 `ExecutionService`、分类适配器和首版单 Agent。网页文字与网页语音共享业务请求、权限、工具、取消语义和持久结果。双模型协同属于语音体验的**可选实验**，不是第二套业务内核，也不是 S1 纵向样例的前置条件。真实电话和批量外呼不属于此实验。

| 候选项目 | 本计划中的研究角色 | 不直接交给上游的责任 |
|---|---|---|
| [Pipecat](https://github.com/pipecat-ai/pipecat) | 默认网页语音工程链路候选：传输、流式音频、轮次、打断和模型/服务接入 | 业务 `ServiceRequest`、工具权限、确认、结果持久化和发布版本 |
| [Qwen Audio Agent](https://github.com/QwenAudio/qwen-audio-agent) | 前台实时交互与后台任务分工的限时对照 | 业务状态、成本账本和生产写入授权 |
| [Omni-Interaction-Agent / Gander](https://github.com/Omni-Interaction-Gander/Omni-Interaction-Agent) | 全双工交互、目标变更及过期结果处理的研究与体验对照；具体机制待源码核对 | Loomrise 的运行权威、业务工具和默认部署选择 |

比较的是能否满足同一组产品验收条件，不把不同定位的项目简单视为可互换的完整底座。上游的演示效果、框架可编排性或论文指标都不等于 Loomrise 已有可复现的集成。

> **全双工决策落点（2026-10-21 定）：harness 工程式。** 是否/何时/如何说话由工程链路承担——Pipecat 轮次策略 + 自建播出回执，模型保持可替换；模型内全双工（Qwen-Audio-3.1-Realtime、GPT-Realtime 类）列为**后续兼容方向**，登记观察点但不作为当前主选。理由：当前阶段与各家 LLM 的兼容契合度优先，模型内全双工是未来。因此本计划的退出门指标（打断恢复、首响等）测量的是 harness 自身行为，验收必要性上升而非下降。决策依据见[架构对照提案](QWEN-AUDIO-3.1-REALTIME-ALIGNMENT.md) D2；该提案其余四项待确认项（交互契约落点、委派阶段、共情维度、pinned 刷新）见其 §8。

## 拟验证的前后台分工

1. **S1 基线**：先以一条语音链路完成虚构课程咨询。媒体适配处理输入、输出、打断与播出状态；所有业务请求交给同一个 `ExecutionService`。记录首响、成本、确认和一次且仅一次的模拟预约结果。
2. **可选协同实验**：仅在基线的延迟、交互连续性或复杂任务等待暴露明确问题时，让前台低延迟模型处理简短回应和澄清；后台模型处理需较长时间的检索、比较或任务建议。两者通过有版本的任务请求/结果交接，不直接共享可写业务状态。
3. **结果回流**：后台结果携带 `request_id`、`run_id`、发起时的任务代次、版本和有效期限。回流前校验任务仍有效、目标未改变、权限与确认仍成立；失效的结果可留审计记录，但不得继续播报或触发副作用。业务工具最终由执行内核再次校验并执行。

前台停止播报、模型生成被取消、后台任务被确认取消、外部工具的实际结果是四种不同事实。用户打断或改目标时，应停止过期的待播内容并请求取消相关后台工作；若写入已发起，必须查询或等待外部结果，不能把“取消请求已发送”写成“业务动作已撤销”。播出状态未知也不能记为用户已听见。

## 对照实验与退出门

在同一虚构场景、相同授权资料与模拟工具条件下，至少覆盖普通咨询、需要后台检索的比较、用户在等待时改变目标、打断播报、重复确认、弱网/超时和取消后工具回执。记录固定依赖与模型版本、设备和网络、首个可听响应、轮次时延、打断恢复、过期结果误播报、任务成功、重复写入、资源占用及单位成功任务成本。主观语音质量由人工审阅；硬规则、任务状态与副作用由确定性检查裁决。

只有在基线存在可复现的体验缺口、协同方案显著改善该缺口，且没有引入越权、旧结果误播报、重复写入、取消状态混淆或不可接受的成本/部署负担时，才考虑将双模型协同纳入后续路线。若候选上游需要侵入 Loomrise 业务合同、资源超出 Lite 的预期，或没有提供可验证的打断/回流语义，则保留为研究参照；不得同时维护多条默认生产语音链路。阈值须在测试前登记，不根据结果倒填。

### 全双工交互指标与登记口径（2026-10-21 增补）

前提：全双工决策已定在 harness（见上文），因此下列指标测量的是**系统级行为**（harness + 模型 + 网络 + 设备），与 Full-Duplex-Bench 等**模型 benchmark 分数不可直接比较**。原始三个指标按业务语义拆解后进门禁（决策与理由见[语音架构决策记录](VOICE-ARCHITECTURE-DECISIONS.md)）：

| 原始语义（benchmark） | Loomrise 业务口径 | 判据类型 | 测量方法 | 登记方式 | **阶段** |
|---|---|---|---|---|---|
| 打断响应率（越高越好） | ① 打断 → **必须**停止播报 | 确定性（触发）+ 统计（时延） | 播放状态机埋点：barge-in 事件时间戳 → 最后一帧停止时间戳 | 触发率 **100%**；停止时延 p95 上限**按下方 §0 规则登记** | **S1（R0）** · `M-S1-13` |
| 同上 | ② 打断后**不播过期内容、不抢话** | 确定性（过期片段）+ 业务案例（处置恰当性） | 待播片段失效计数；处置进业务 `EvalSet` 人评 | 过期片段误播 **0 容忍**；处置不在模态 Gate 裁决 | **S1（R0）** 触发项；处置恰当性归 **S2-c** |
| 背景人声误响应率（越低越好） | 非指向人声**不触发响应** | 确定性（注册语料回放） | 自建中文噪声语料：电视/旁人交谈/键盘声，固定设备与网络矩阵 | 注册集上误响应 **0 容忍**；同时报**漏响应率**，防 VAD 过严把用户真话滤掉 | **P0 声学级 → S1（R0）**；P1/P2 → **S2-c** |
| 同上（配对项，2026-10-21 增补，同日修正为分层） | 非指向人声**不打断播报**：噪音、旁人说话、**本人对第三人说话**都不使当前播报中断 | 确定性（声学级）+ 统计（说话人/语义级） | 播报中回放噪声与旁人交谈语料；另录"本人对第三人说话"语料（如"快递放门口就行"） | 声学级误停 **0 容忍** → `M-S1-14`；说话人/语义级**允许误停**，改登记三项：误停恢复时延 p95、**恢复后复读率 0 容忍**、**漏判抢话 0 容忍** → `M-S1-15/16` | 声学级 **S1（R0）**；说话人/语义级 **S2-c** |
| 附和延迟（越低越好） | **附和不中断播报**；误判归属才是真实风险 | 确定性（非预期中断） | 脚本语料：附和词（嗯/对/是的）夹在播报中 | 非预期中断 **0 次**；若设计选择暂停响应，则另登记恢复时延 p95 | **S1（R0）** |

> **2026-10-23 执行状态（负责人决定，不改上表阶段归属）**：`M-S1-13`（停止时延）与 `M-S1-14`（声学级误停）**本轮不做，延后**——语料需真人录制，用合成音频冒充会让"0 次误停"变成自证。登记为挂账 `G-6`（[R0 证据摘要 §5](reports/R0-EVIDENCE.md)）。
>
> 因此**上表不是"已在 R0 验过"的意思**：S1 侧的声学级三项（39/41/42 行）本轮只有埋点与阈值登记，零样本。已验的是**链路**（真实麦克风采集 + 固定 STT/TTS + 可懂度人工确认），不是**鲁棒性**。这两个词在 R1 期间不得混用。
>
> 另：浏览器音频栈的"自动化不可用"不再是阻塞理由——人工实测已通（`M-S1-08`）；真正缺的是语料与采样轮次。

#### §0 阈值登记规则（2026-10-22 增补，用于 Gate 可判定）

绝对上限（如"停止时延 p95"）**不在本表预写数字**，但也不能"有数据就算过"。登记表必须逐项写清六件事，缺一即 Gate 不成立：

1. **登记时间戳**（必须早于该轮跑测的第一次采样）；
2. **绝对上限**（p95 毫秒数）与**零容忍项清单**；
3. **语料版本**（哪套中文噪声/附和/对第三人说话语料，含条目数）；
4. **设备与网络矩阵**（机型、浏览器、麦克风、带宽档位）；
5. **样本量与采样方法**（每场景最少条数、是否含重复轮次）；
6. **未覆盖声明**（P1/P2 若本轮不验，显式写"未覆盖"而不是留空）。

**Gate 判据 = 「登记表六项齐全且时间戳早于采样」 ∧ 「结果未超上限」 ∧ 「零容忍项计数为 0」**。只满足后半句叫"有数据"，不叫"通过"。判据行号见 [Gate 追溯矩阵](RELEASE-GATE-MATRIX.md) `M-S1-13…16`。

三条登记纪律：

1. **不照抄厂商数字**。Qwen 的 84.5% / 13.0% / 1.700s 是不同管线、不同语料、厂商自报且未在 Loomrise 复现，写进阈值即违反"测试前登记、不倒填"。正确顺序：先跑 S1 现有最小链路取基线，再登记**绝对上限**（p95）与**零容忍项**。
2. **附和的真实风险不是延迟，是归属误判**：把附和当打断（乱停、反复确认）或把打断当附和（用户说停还在说）。因此两边配对登记——误中断率与误忽略率，只压一边必然把另一边顶上去。
3. **模态层与业务层分开裁决**。本表属语音模态 Gate，与业务内容 `EvalSet`（机评 + 人工校准）分开；符合"确定性裁决优先、机评只评软质量"的分工，避免用一条混合分数掩盖确定性违规。
4. **归属判定分 P0 / P1 / P2 三级，不许混报**。**P0 声学级**覆盖短促杂音与环境噪音（连续帧迟滞 + 最短语音时长 + 能量门限），确定可做；**P1 说话人级**覆盖"旁人有内容的说话不打断"，依赖说话人归属能力；**P2 语义级**覆盖"本人对第三人说话不打断"，依赖语义归属判定。P1/P2 须在 S2-c 内验证，验不出即退回上一级并在验收记录写明未覆盖项。同理，声学级误停按 0 容忍，说话人/语义级误停按 §3.3"停—判—续"允许发生，改测恢复时延、复读率与漏判抢话。分级与处置策略见[语音架构决策记录 D-03](VOICE-ARCHITECTURE-DECISIONS.md)。

阶段：S1 语音退出 Gate 用本表补齐现有残留项（真实音频可懂度、首响、打断恢复即为本表内容）；S2-c 语音应用验收复用同一口径；S4 外呼复用并另加通话回执项。**分级与阶段绑定**：S1 只承担 **P0 声学级**（误停 0、误响应 0、触发率 100%、停止时延 p95 登记制）；**P1 说话人级与 P2 语义级一律留 S2-c**，S1 验收记录须显式写"未覆盖"，不得用"声明"替代"验证"。本表同时定义"基线存在可复现体验缺口"的语音判据——协同实验的启动条件不变。
