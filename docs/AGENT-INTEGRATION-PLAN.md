# 第三方 Agent 接入与后台改进开发计划 v0.4

> 执行说明：本文件登记开发优先级、依赖与验收工作包；实施时按工作包细化正式合同、模块和可运行步骤，再按项目开发流程执行。本次只更新计划，不启动 SDK 安装、定时任务、外部写入或代码实现。

**目标**：第三方 Agent 可通过 MCP 与配套 Skills，在授权范围内帮助用户创建客服草稿、诊断失败和验证改动候选；CLI、网页与 API 共用同一业务合同。Loomrise 可选择通用 harness 承担后台作业，继续掌握业务执行、验收与发布权威。

**架构**：统一应用服务／API → 网页、MCP 与 CLI 适配；配套 Skills 指导第三方 Agent 使用工具，独立的后台 Worker 按授权调用一个通用 harness Provider。在线客服仍使用有限执行流程，所有入口共用版本、权限、幂等和证据。

**技术基线**：保留现有 Python 核心和 AgentScope 运行适配。MCP、Agent Skills 及 Codex／Claude 接入方式按官方文档选定并锁版本，SDK、传输和首个 Provider 尚待联调，不预写兼容性。

状态：**2026-10-27 回填：接入方向、高优先级排期及最小语义工具面／贯穿 Harness 的渐进式披露原则已确认。R1 配置后端已部分实现统一配置应用服务、loopback HTTP、受限 stdio MCP 与最小 CLI；专家设置中的服务端版本工作面已接入 HTTP，并完成本机 fixture 浏览器联调。但正式来源/摄入合同、Skills、首个真实 host 联调、任务工作集、动态工具披露、Worker 与 Provider 仍规划未实现。** S1 仍固定注册两个业务工具，未接任务工具或动态披露；工作台其他知识、物料、评测、上线页面仍不是该配置服务的客户端。下述更多工具名、来源字段、预算参数、支持矩阵与 Provider 选择待实施验证；没有改变 AgentScope 运行基线。阶段权威见[验证路线](ROADMAP.md)，R1 代码证据见[R1 证据摘要](reports/R1-EVIDENCE.md)，UI 关系见[配置后台体验优化](CONFIGURATION-UX-OPTIMIZATION.md)。

## 1. 已确认的接入方向

1. **统一应用服务／API 是业务权威**：网页、MCP 和 CLI 使用相同的资料授权、草稿／版本、候选、运行、评测与发布规则，不分别实现三套状态。
2. **MCP + 配套 Skills 是第三方 Agent 的主要接入方向**：工具提供动作与结构化结果，Skills 提供步骤、参考与失败处理；第三方 Agent 通过自己的 host/harness 调用工具。
3. **CLI 是高优先级可选通道**：服务本地材料、批量操作、开发与 CI；初次用户不必安装 CLI、Codex 或 Claude 才能使用网页创建。
4. **分开管理两种 Skill**：外部 `SKILL.md` 教第三方 Agent 使用 Loomrise；内部 `SkillManifest` 定义客服业务策略。各自版本化并记录依赖，加载外部 Skill 不授予业务权限。
5. **通用 harness 用于后台创建、诊断、候选改进与治理辅助**：先接一个 Provider，另一 Provider 后做同合同对照；不取代在线 `ExecutionService` 或创造另一套发布权威。
6. **人工完整路径继续可用**：助手、MCP 与 Worker 故障不阻断手动编辑，线上继续使用原已发布版本；生成、采用、试用、验收、批准和发布分别留证。
7. **任务及主动服务定义属于专家自己的配置**：建议由 `AgentSpec.task_blueprints` 和专家内稳定 `blueprint_key` 表达，随 `AgentVersion` 评测、审批、发布与回滚；不建设跨智能体共享策略库。事项实例调整与蓝图编辑分开，具体权威和初始化规则见[Task 设计](TASK-SYSTEM-DESIGN.md)。
8. **少量语义工具与渐进式披露共同约束 Harness**：系统先装配有界输入，按事项／Skill 披露所需内容和获准工具 Schema；减少常驻内容不等于放松权限，所有读取和动作仍由服务端裁决。

首个端到端成果是：**获授权资料 → 第三方 Agent 读取工作方法 → 受限客服草稿／候选 → 人确认并采用 → 校验与沙盒答疑 → 工作台可查看完整配置和证据**。不要求先接真实写工具，不直接发布公网客服。

### 1.1 最小语义工具面（原则已确认，名称与合同提案未实现）

模型面向业务意图，不按数据库表暴露 CRUD。以下是任务接入的建议入口；草稿、候选、校验等既有 AGI 用例仍各自限权，不合并为万能入口。

| 模型入口 | 必要语义 | 明确不做 |
|---|---|---|
| 系统装配的 `task_workset` | 按本次主体、目的和角色直接提供有界事项／候选与阻断摘要 | 不是 Tool，不要求 Agent 先调用 `list_tasks/get-list`，不装入完整历史 |
| `inspect_context` | 共用的按需读取／展开能力；按获准对象引用展开事项、相关事实、精确蓝图／Skill、证据和结果，限制范围、分页与预算 | 不任意查询别的主体，不返回全量策略／工具目录，不执行动作或透传任意查询语句 |
| `manage_tasks` | 唯一任务管理意图 Tool；类型化 `propose/adjust/request_cancel`，分别提出候选、调整批准范围内的单个实例、请求取消 | 不拆增删改查工具，不 `set_status/mark_completed/mark_sent`、硬删除、写 cron／代码或改蓝图权限；取消请求不等于执行停止确认 |
| 具体业务 `ToolManifest` | 查询、发送或业务写入保持语义明确的输入／结果合同，经 `ExecutionService` 执行并保存结果证据 | 不折叠成万能 `invoke/execute/RPC`，不借任务采用或候选创建授予执行许可 |

`manage_tasks` 的建议操作名尚待正式合同登记；每次变更必须携带基础 revision、幂等键、来源／依据引用和作用域，服务端校验人工锁定、允许调整范围、当前权限与代次。取消及替代沿用[Task 设计](TASK-SYSTEM-DESIGN.md)的可靠阻断规则，不能由模型直接设置终态。应用服务内部可有查询、修订、领取等接口，但不必逐一成为模型 Tool。

### 1.2 L0–L2 渐进披露（已确认原则，待实现）

披露覆盖输入、事项、Skill、工具 Schema 和工具结果，不只截短 Prompt。服务端先按权限过滤候选，再按本次任务选择；`inspect_context` 只是受限展开入口，不是授权器。

| 层级 | 本次可见内容 | 边界 |
|---|---|---|
| L0 常驻摘要 | 身份／租户／目的和必要安全、确认、停止摘要；当前相关、即将到期、逾期／待对账／阻断事项及近期相关完成／发送摘要；少量能力描述 | 不加载全部蓝图、Skill、工具 Schema 或历史结果；后台／外部角色只见其获准工作集 |
| L1 选中事项或 Skill | 仅加载该项所需的精确蓝图、可调字段／批准包络、有效事实，以及当前获准工具的精确 Schema | Skill 命中、发现工具或取得 Schema 均不授予权限；生产动作仍单独确认和重验 |
| L2 按需证据 | 有界展开来源、执行尝试、详细结果及必要历史，保留引用与版本 | 分页、摘要和结果裁剪留证，不把全部原始记录回灌每轮上下文 |

> **2026-10-22 已采纳引注**：引入"路由与能力单元"后，L0 需补一档**本层路由表摘要**（每个候选单元一行，模型据此路由），且**逐层下钻**——进入单元 body 后重新按 L0 处理下一层，而不是把下层全文塞进来。见[路由与能力单元](ROUTE-GRAPH-AND-UNITS.md) §7（v1.0，已采纳为正式合同；R1 落最小实现，嵌套在 R3）。本表三层结构与边界不变。

工作集窗口、上限和排序在实施时登记；模型未见的事项仍参与服务端的全局去重、频次、占用和停止检查。身份、触达许可、停止／退订、人工锁定、当前占用／代次等**安全必要事实不受预算截断**；缺失、失效或预算不足时缩小工作范围、等待补齐或阻止相关动作，不能用“摘要未展示”放行。

### 1.3 角色隔离、快照与 Provider 降级

| 角色 | 可见与可执行集合的边界 |
|---|---|
| 外部创作 Agent | 获准来源、草稿／候选和选定脱敏证据；可在登记范围提出 TaskProposal，不获得生产事项调整、客户触达、业务写入、真值或发布权 |
| 后台 harness Worker | 冻结作业输入及获准创作／诊断／候选工具；治理产物与业务结果分开，不借 Worker 身份执行在线客户业务 |
| 在线客服执行 Agent | 已发布专家版本、本次主体／目的相关事实和批准能力；只能在批准包络内调整单个 TaskItem，实际业务仍经原执行内核 |

三类角色共用应用服务，不共用无限权限。服务器对入口、角色、租户／专家／主体、用途、环境、版本和每次调用分别校验；隐藏工具名称不是授权机制。猜中未披露工具名、提交过期 Schema、复用旧许可或换到网页／CLI／MCP 入口试图绕过同一限制，都必须被拒绝；正常获准用例仍可跨入口复用。读取后撤权也不能沿用先前快照继续动作。

每次输入快照及审计记录实际披露的 Tool ID、合同／Schema 版本与 hash、授权版本／依据、Skill 和事实来源版本、加载／跳过／预算原因及实际用量，能够还原模型当时所见。披露事件与实际调用／结果事件分别记录，不能只留最终调用工具名；脱敏和保留策略仍适用。

Provider／host 不支持轮内动态装配工具时，每次 run 固定一个最小许可子集；需要新增 Schema 时建立显式新快照／run 边界并重新检查。不退回全量工具目录，也不使用万能调用器绕过限制；将此损失项记录进支持矩阵。当前 [`context.py`](../loomrise/context.py)仅有三段式上下文选择，[`service.py`](../loomrise/service.py)固定注册 `search_knowledge` 和 `create_booking`；上述任务工作集、工具发现与动态披露尚未实现。

| AGI-10 | P0／S2-c | 例行检查与受限迭代、审批辅助 | AGI-08–09，明确用户授权与触发条件 | 无新证据／预算不足不运行；报告、提案、批准、实际发布分开；拒绝候选留档，不自动扩权或发布 |

开发顺序：**共用合同与授权 → MCP／Skills 创建链 → CLI 与客户端扩展／只读诊断 → 受限 Worker → 候选评测及例行治理 → 云交付**。S2-a 的最小创建联调不依赖完整后台调度器或两个 Provider。

**版本归属（2026-10-23 补，只排批次、不改本表验收）**：AGI-01/02/03/05 → **R1**（05 是 P1 最小命令集）；AGI-04/06 → **R2**（依赖摄入与沙盒试用）；AGI-07/08（简版）→ **R3**；AGI-08（完整）/09/10 → **R4**；AGI-11 → **R5a**。详见[版本切分 §5.1](RELEASE-PLAN.md)。**出向 MCP（Loomrise 调外部 MCP server 当工具）尚未定版本**，登记在 RELEASE-PLAN §8 `P-6`。

AGI-02／03 先在来源、草稿和候选链验证最小披露与权限边界；TaskItem、服务初始化和任务意图扩展须等待[联合计划](TASK-MEMORY-INTEGRATION-PLAN.md)的 TM-01–03 合同／持久化，内部 TODO 切片衔接 TM-04，主动服务仍依 TM-07／08 的调度和授权渠道 Gate。AGI-08 复用这些合同，不提前实现另一套任务或记忆权威。

在线多模型节点与提示词自定义保留高优先级验证项：在 S2-c 评估单模型、条件节点和受限强模型升级的质量／成本／延迟，登记拓扑与提示词版本；不因采用通用 harness 就默认把在线接待交给开放式工具循环，也不预写多节点更便宜的结论。该实验不改变现有运行 SDK 选型。

## 4. 可执行验收工作包

### AGI-01／02：共用合同与 MCP 工具

- [ ] 登记正式输入／输出合同及版本、身份、作用域、基准 revision、来源引用与幂等键。
- [ ] 在服务边界验证越权读取、已撤销来源、旧 revision、重复提交和未知结果；错误返回修复信息，不自动放行。
- [ ] 提供选定场景／版本／授权知识资源；未消费 Gate 样本与凭据不进入资源目录。
- [ ] 提供新建草稿、提交候选 patch、配置校验、沙盒试用与结果读取；人工锁定项和采纳权继续由工作台控制。
- [ ] 第三方 Agent 能创建受限草稿并提交建议，不能原地覆盖已发布版或取得生产业务写／发布权限。
- [ ] 重复调用返回同一业务产物标识；网页与 MCP 展示同一版本和状态。
- [ ] 登记角色可见／可执行集合、`inspect_context` 的有界引用和 `manage_tasks` 的类型化意图；任务扩展先通过 TM 合同，不暴露 CRUD 或万能执行入口。
- [ ] 在服务端验证隐藏工具猜名、跨角色／租户／主体读取、换入口、过期 Schema 和读取后撤权；披露不构成授权。

当前已实现的配置用例与 CLI/MCP adapter 由 [R1-EVIDENCE](reports/R1-EVIDENCE.md) 记录；本节新增的知识来源、试用、Task/工作集与动态披露用例仍待合同登记，不能把现有配置端点等同于 AGI-01–03 全部通过。保存无效或不完整草稿与放行试用／发布分别处理。

内部配置试用冻结本次配置、知识与工具快照，通过来源／权限检查后进入隔离沙盒，业务写工具使用模拟。Widget／Contact Page 等外部测试入口继续绑定经人工批准的指定沙盒版本，不能引用可变草稿；内部试用成功不等于入口已发布或 S3 公网交付通过。

### AGI-03／04／06：Skills 与首次创建

- [ ] 分开记录 MCP 基础协议、Skills 扩展、host 的支持版本和实际能力，不根据“支持 MCP”推断支持 Skills。
- [ ] 将外部技能与工具 Schema／业务合同版本关联，提供触发描述、步骤、受限范围、状态说明、失败处理和示例。
- [ ] 原生扩展按能力声明使用 `skills/list`／`skills/get`，文件通过 `resources/read` 获取；来源身份与文件清单／摘要保留，按需读取。
- [ ] 不支持原生扩展的 host 使用明确安装的本地技能包或显式资源读取工作流；读取 Markdown 不冒充宿主完成技能激活。
- [ ] 对技能更新、同名不同来源、缓存失效和执行脚本的批准边界做检查；远程指导不隐式扩大本地工具权限。
- [ ] 按 L0 能力摘要 → L1 所需 Skill／精确 Schema → L2 证据与结果加载，核验未选内容、缓存与历史不会暗中回灌；必要安全事实缺失时阻断。
- [ ] 分开验证动态工具与每 run 固定最小许可子集；不支持动态装配时，新快照／run 边界可复核，不默认暴露全目录。
- [ ] 先在一个主流 host 完成“资料 → 草稿候选 → 采用 → 校验 → 沙盒答疑 → 工作台查看”；模型连接缺失时明确模拟或阻断真实答疑。
- [ ] 核验资料冲突、资料外问题、助手失败转手动、人工修改后迟到建议等反例。
- [ ] 第二 host 复用同一合同与技能资产，记录支持与损失项；未通过实测的不显示“已支持”。

### AGI-05／07：CLI 与只读诊断

- [ ] CLI 参照同一服务用例实现摄入／草稿／候选／检查／结果读取，保留 JSON 输出和明确退出状态。
- [ ] 本地读取范围由用户指定，来源授权和数据去向可见；真实凭据不写入产物或命令日志。
- [ ] 诊断 Skill 只能读取选定脱敏运行与审定案例，输出证据引用、根因候选与建议影响范围。
- [ ] 案例提名、事实修订和人工真值审定分开，不由诊断 Agent 改写历史事实、盲测或评分。

### AGI-08–10：Worker、候选改进与治理

- [ ] 后台作业冻结目的、身份、资料／工具快照、可改字段、预算和输出合同。
- [ ] 快照包含实际披露 Tool／Schema 的版本与 hash、授权版本、加载／跳过原因和预算；后台 Worker 无法借同名工具转成在线业务身份。
- [ ] 先用一个 Provider 对比直接结构化模型调用与通用 harness 作业，保存失败、用量和人工修订量；有收益才扩大使用。
- [ ] 隔离文件、网络与凭据，显式配置工具范围；上游 hooks／预批准列表不替代服务端权限校验。
- [ ] 实测取消、断线、重启、重复回调、子作业预算和迟到产物；取消中、已取消、失败、耗尽和未知分别留证。
- [ ] 候选只改登记范围，旧版与候选使用固定条件配对回放；未消费 blind 在独立 Gate 使用，golden 只证明不退步。
- [ ] 第三个 Skill 生成候选与调用受限开发回放；发布由独立权限和获授权的人批准，产物生成成功不能代替发布证据。
- [ ] 例行作业由用户明确配置触发范围与预算；先只读检查，再受限候选；无新证据或预算不足跳过。
- [ ] 生成治理报告和回滚建议；不自动改变权限、业务承诺、硬规则、评分、固定真值或审批权。

### AGI-02／03／08：工具披露与安全的共用验收

以下均为待执行测试，不是本轮通过记录；用原创虚构主体、固定时钟和模拟业务工具，不发送真实消息。

| 测试 | 必要证据 |
|---|---|
| 隐藏名与入口绕行 | 未披露工具猜名、跨角色／租户／主体越权及换到网页／CLI／MCP 重试同一越权意图均拒绝；错误不泄露未授权目录或数据 |
| 过期 Schema 与撤权 | host 缓存旧 Schema、版本／hash 不符、披露后撤权时拒绝；重建快照不复活旧许可 |
| 工作集与意图 | 当前／将到期／逾期阻断／近期完成摘要覆盖正确；缺项可受限展开；revision 冲突、重复意图、越界调整与取消未确认不产生额外副作用 |
| 预算与保护项 | 极小预算、结果过大或必要事实读取失败时保护项仍有效；不能完整提供必要摘要则阻止相关动作，并留跳过／阻断证据 |
| Provider 降级 | 动态与非动态 host 各有实测；固定最小子集及新快照／run 边界不扩大权限、暴露全目录或退成万能调用器 |
| full 与 progressive 对照 | 同专家配置／版本、获准能力集合、模型、样本、时钟、环境与预算，仅改变披露方式；比较任务质量、错误放行／阻断、上下文／Schema／结果 token、额外往返、时延及失败回退成本 |

对照前登记阈值，完整披露基线也只含同一获准范围，不能以越权的全目录作为基准。报告样本和限制，允许渐进披露因额外往返而无收益；未实测前不宣称效率、成本或质量提升。

## Task 与用户上下文的接口扩展依赖（原则已确认，合同提案未实现）

[联合计划](TASK-MEMORY-INTEGRATION-PLAN.md)的事项与记忆用例继续经过AGI-01共用应用服务：外部Agent可在登记范围读取相关事项/用户片段、提出TaskProposal或记忆候选，不能直接写任务/画像数据库、合并身份、扩大触达范围或执行生产联系/写入。后台抽取、复核与候选作业可复用AGI-08 Worker骨架，但与在线业务请求分开身份、预算、执行代次和结果。

任务及主动服务定义保存在单个专家的 AgentSpec，建议字段为 `task_blueprints` 和专家内 `blueprint_key`；AgentVersion 冻结定义、Skill、工具和许可约束，蓝图改变走专家候选版本的评测审批，不建立全局策略库。服务初始化按 `tenant + agent + subject + service_cycle` 判断已批准定义：身份、条件及记录权限齐备的低风险内部 TODO 可幂等登记；触达意图必须先 TaskProposal，再由已有批准规则／人工采用，实际动作前重验最新授权。候选、采用和执行许可是三件事。

Agent 仅能在已批准包络内调整单个 TaskItem，不能改变渠道、权限、频率上限、承诺或人工锁定；这些配置变化仍走版本提案。具体幂等、在途版本迁移、取消及替代以[Task 设计](TASK-SYSTEM-DESIGN.md)为准，AGI 工具不能用新 run、旧 Schema 或换入口规避。

前置为稳定 subject、字段／用途授权、严格时间／撤销、运行前事件 envelope、持久 revision 与幂等；`inspect_context/manage_tasks` 为建议名，正式 Task／Memory Schema 仍待登记。通用 harness 内建 TODO、memory 和 checkpoint 仅为适配器内部辅助状态，不能覆盖 TaskItem／ServiceRequest／RunEvent 或 Loomrise 画像权威。AGI 既有排期不据此宣称这些新用例已实现，详细依赖与阶段继续由 TM 工作包管理。

### 跨用户专家经验的采纳方向（2026-10-16 确认，依赖 AGI-07/08/09）

在 Agent 优化专家配置的流程建立后，**可由第三方 Agent 带入专家视角做洞察与复盘，形成专家经验**——把某专家的已发布配置快照、精选脱敏运行证据与既有 `accepted` 经验作为只读上下文交给外部 Agent，产出跨用户经验候选。该方向的完整设计、四条边界（只产 `candidate`／作者看不到未消费 blind／注入配置不等于授权／诊断不改配置）与依赖顺序见[专家-用户记忆体系 §6.3](EXPERT-USER-MEMORY-SYSTEM.md)（阶段 MEM-6，可选项）。

对本文的四点约束：**① 不新设 AGI 编号**，复用 AGI-07 诊断边界与 AGI-08 Worker 骨架；**② 不进入关键路径**——手工归纳通道（MEM-1…5）不依赖任何 AGI 工作包即可跑通；**③ 不转移权威**——引入外部 Agent 不改变「发布权与评测权威在 Loomrise」，它只产候选；**④ 不扩大角色边界**——外部创作 Agent 的可见与可执行集合仍按 §1.3 三类角色表，不因拿到专家配置而获得生产写入、触达、真值或发布权。

## 6. 计划完成与实现完成的区别

本轮完成的是：方向确认、高优先级工作包、专家版本内任务定义的接入依赖、最小工具面、L0–L2 披露及安全／质量／成本验收登记；接口、任务工作集、动态工具披露、技能包、Worker 和兼容矩阵均未实现。首个 Task／Harness 切片的范围与实施交接见[实施计划](superpowers/plans/2026-10-16-expert-task-harness.md)，不启动真实触达或外部业务写入。

只有正式合同、鉴权、实际联调、持久化产物、正反例和失败恢复记录齐备，才能逐项把 AGI 工作包标为已验证。S1 历史回放、本地原型或供应商文档不能代替这些证据。
