# 物料库、内容理解与客服文件发送 v0.3

状态：2026-10-14，**独立物料库、业务录入、处理/简介检索、人工与 Agent 自动发送方向已确认；本轮本地前端扩展已实现并验证，真实后端能力规划未实现**。本文件定义该能力，不改变 S1 构件、发布纪律或六层配置。

## 1. 产品分工

物料库承载业务常发的图片、视频与文档；知识资料承载答疑所需的事实和可引用材料。两者分别管理，允许建立关联引用，但上传物料不自动把内容变成业务事实。

采用“独立物料库 + 经审阅的简介索引 + 受控发送”方案。合并进知识 File 页会混淆事实引用与文件交付；建立新通用资源平台则超出当前客服目标。物料库作为知识域内独立入口，工作区共享，配置可用专家/环节，初始化不强制先上传物料。

业务录入原件、名称、简介或用途、标签、来源/授权、有效期和可用范围。资料本身可人工维护；自动理解只生成有依据、带版本的简介候选，业务审阅后供 Agent 检索与上下文选择。未经审阅的模型描述、文件名推断或演示文案不能成为已确认事实。

## 2. 生命周期与界面

```text
业务录入 → 原件保存 → 可选处理（压缩、封面、OCR/转写/内容理解）
                     → 简介候选/人工编辑 → 审阅发布 → 人工或Agent检索选择
                     → 权限/范围/版本/渠道再检查 → 发送 → 回执留证
```

文件可读、压缩作业、简介审阅、索引可用与发送送达分别记录。图片/视频压缩保留原件和派生关系，压缩失败不丢原件；文档可抽取文本/结构帮助简介，但发送物料与知识事实摄入仍是两条合同。

界面以列表和筛选为主：名称、类型、标签、用途、版本、可用范围、处理/简介/发布状态；详情可查看原件、派生文件、处理参数与失败原因、简介候选和版本差异。人工可直接写简介，避免必须等待 AI 才能配置。

## 3. 检索与发送边界

Agent 检索已发布、获授权、有效且范围匹配的简介、标签和适用说明，返回物料引用与具体版本。上下文默认只加载这些摘要，不把图片/视频二进制或 Base64 拼进 Prompt；需要多模态理解时另登记授权的数据流。

可检索与可发送是不同权限。人工发送前选择原件或已生成的派生版本；Agent 自动发送需要明确启用策略、物料允许自动发送、客户请求/适用场景满足、数量与渠道类型/大小限制满足，并重验会话占用。人工接管后不能继续沿用 AI 的旧发送权限。

正式线上使用批准的 `AgentVersion/ToolPolicy`，发送属于带副作用的业务工具，不由模型单独批准。选中后撤回、过期、版本或范围变化、旧任务/占用代次，都使旧选择失效。没有确认的处理文件不得冒充实际压缩产物；是否允许原件回退由策略明确规定。

发送消息保存文件版本、选择的派生版本、简介快照、发送者、请求/会话和回执关联。原件后续改名或简介修改不改写历史；撤回阻止新检索/发送，不宣称可以追回客户已收到或下载的文件。

## 4. 领域与后端责任（目标规范，未实现）

- `MaterialAsset/MaterialVersion` 为应用资产目标合同，记录来源、授权、有效期、可用范围、原件与派生引用、简介与版本；具体字段/接口仍待正式合同登记。
- 对象存储管理实际文件，数据库管理版本/权限；异步媒体处理、内容理解和检索适配分别有作业 ID、预算、取消、重试与产物证据。它们不构成平台内创建 Agent Worker 已实现。
- 经治理的物料摘要可进入 `ContextSnapshot`，不新增第七层，也不能授予工具权。文件发送通过 `ToolManifest/ToolPolicy` 与同一 `ServiceRequest/RunEvent` 留证。
- 发布物料/简介与发布客服版本分别管理；Agent 可用范围/发送策略变化进入草稿和必要重验。文件缓存、浏览器模式或 CDN 地址不是访问权限权威。

后端须验证上传完整性、格式/安全处理、真实图片视频参数及压缩产物、OCR/转写/多模态简介依据、撤回失效、渠道大小/类型与短期授权下载、重试幂等、消息送达/失败/未知、占用变化与迟到回执。

## 5. 本轮前端范围与验收

延续[第二轮前端](S2-FRONTEND-ROUND2.md)。新增独立物料库和会话选择器，原件仅在浏览器 IndexedDB 缓存，元数据保存在既有本地状态；不上传供应商、模型或云。原有知识 File 的文本/复杂解析限制不混用。

压缩与自动简介用明确的演示状态/候选表达，不报告虚假压缩率，不生成虚假可下载的“压缩文件”。本轮同时提供当前草稿策略下的 Agent 检索/自动发送模拟；实际外部发送和内容理解尚未接入，送达/已读/解决保持未知。

必要验收包括：

1. 图片、视频、文档录入和原件跨刷新预览；旧 schema1 与文本消息保留。
2. 未审简介不供 Agent，压缩/理解失败保留原件和人工编辑。
3. 选择后撤回/过期/版本/范围变化阻断发送；历史消息快照不变。
4. 人工未承接、Agent策略关闭/无明确请求、人工占用、只读或旧代次发送被阻断。
5. 文件读取/缓存/发送异步期间切换上下文，迟到结果不串对象或错发。
6. 物料登记不改变 FAQ 事实/冲突与知识试用计数；原有验证继续通过。

阶段建议：S2-a 建独立资产/授权/版本及最小文件交付，S2-b 补媒体后处理、经审阅简介检索与客服渠道文件能力，S2-c 验收策略化 Agent 自动发送、占用/幂等/回执与结果证据。前端先表达三阶段能力，不用本地演示关闭服务 Gate。

验收结果（2026-10-14）：57/57 状态与控制器测试、9/9 物料浏览器任务通过；原有 11 项主流程与 5 项反例回归通过；16 路由两视窗共 32 个布局检查无页面横向溢出/page error。已通过独立代码复审，具体脚本与局限见[交付报告第 7 节](S2-FRONTEND-ROUND2.md#7-物料库与-agent-自动发送扩展)。本地检查不替代对象存储、媒体处理、多模态理解、服务端权限、语义检索或真实渠道验收。

## 6. 访客接收与查看（本地前端已验证）

2026-10-14：物料发送已接入客服试用台、Widget 页面及配置侧栏预览。两个入口使用独立访客会话，访客索取后按已审简介/类型/关键词检索并校验策略，再从 IndexedDB 读取冻结原件；图片、视频、文本与 PDF 能实际查看，普通 Office 文件提供原件下载。该过程仍为当前草稿的确定性脚本，压缩/内容理解和真实渠道未接入。

本地 DOM 收件、打开、发起下载与外部送达分开；无文件或迟到轮次不能制造收件附件，下载失败不登记成功。Run 保留固定附件、请求来源与策略，不改 Inbox，不因物料试用授权知识批准。否定请求、人工等待、取消、改稿、撤回及缓存缺失均有行为验收。

该批全套 86/86 Node 测试、新访客 10/10 浏览器任务、旧流程与物料任务回归通过；布局覆盖 16 路由两视窗。细节、复现入口与局限见[交付报告第 8 节](S2-FRONTEND-ROUND2.md#8-访客物料试用与-widget-预览扩展)。原第 5 节的 57/9 计数属于上一批，不移作本批验证。
