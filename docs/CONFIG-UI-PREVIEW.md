# 配置后台新结构 · 页面线框预览 v0.2

日期：2026-10-26。状态：**线框预览（ASCII），用于结构与易用性评审，不是视觉设计稿**。v0.2 是对 v0.1 做易用性复盘后的修订：界面用词换成业务语言、导航扁平化、重复入口合并、补上冷启动和"怎么改"的交互。依据不变：[配置重构与编排画布产研需求](PRODUCT-CONFIG-OPTIMIZATION.md)、[运营视角配置需求清单](OPERATOR-CONFIG-REQUIREMENTS.md)。不改六层合同，不改 ROADMAP Gate。

**范围**：核心配置页 11 页 + 右侧面板 + 待处理队列。测试域（测试题/回放/人工评分）、设置、客服应用、云部署沿用现有页面，本轮不画。

## 0. 复盘结论

v0.1 的结构方向是对的：四类资产、流程图独立成一级、依据随处可查。问题出在界面这一层，读起来仍像工程师写给运营的说明。按对上手的影响排序：

| # | 问题 | v0.1 表现 | v0.2 处置 |
|---|---|---|---|
| E-1 | 导航用平台词 | 装载 / 编排 / 验收，守卫、投影、沙盒、运行叠加 | 换成业务词；内部词只留在文档和"技术详情"里（§1） |
| E-2 | 导航多一层分组 | 4 个分组 + 7 个子项，分组本身没内容 | 扁平 6 项 + 设置，顺序就是搭建顺序 |
| E-3 | 冷启动没画 | 每页都假设已有 137 条问答 | 首页空态就是三步引导，不另做向导页 |
| E-4 | 同一件事多个入口 | "试"有 3 处（试这一条 / 试跑 / 验收）；"待处理"有 5 处（底部条 / 概览 / 列表 / 发布 / 画布校验） | 测试统一进右侧面板；待处理统一成顶栏一个计数 + 一个队列 |
| E-5 | 只画了"看"，没画"改" | 画布没有加分支的动作；审阅点"错"之后去哪没定义 | 流程图用"＋"结构化添加；核对页就地改 |
| E-6 | 校验阻断编辑 | 画布"必须修，不允许保存" | 草稿自动保存；错误只拦上线，不拦保存 |
| E-7 | 符号太多 | 画布图例 10 个符号 | 节点直接写类型字，叠加信息用文字标签 |
| E-8 | 状态缩写难读 | "✔ 审""⚠ 冲""⚠ 无" | 全词：已审 / 不一致 / 缺出处 / 待审 |
| E-9 | 工程字段混进运营视图 | 超时 8s、幂等键、r37、批次 B-07、RUN-8f2c | 收进"技术详情"折叠区或依据面板 |
| E-10 | 审阅不分轻重 | 137 条每条都按三次键 | 有风险的逐条看，无风险的抽查后整组确认 |
| E-11 | 两档深度靠全局开关 | 切到"向导"后用户不知道藏了什么 | 取消全局开关，每块就地"更多设置" |
| E-12 | 发布按钮语义重叠 | 存草稿 / 提交审批 / 发布到沙盒 | 自动保存；只剩"发到测试环境""申请上线" |
| E-13 | 没有撤销 | 价格同步 9 处、整组确认都不可逆 | 批量操作 10 秒内可撤销；上线后可回到上一线上版 |

**坚持不改的部分**。这些是产品相对 Knocket / Delight / ElevenLabs 的优势，不因为"更简单"拿掉，只换说法：

- 依据可查：从哪来、哪一版、谁改的、影响谁、凭什么。改名叫"依据"，入口位置不变。
- 红线在流程图上可见；平台底线可见、不可改。
- 业务办理有三种结果，"结果不明"单独统计，不混进成功。
- 上线要人批准；发到测试环境不需要。
- 资料授权按批声明一次，不默认填。
- 错误拦上线；测试题变差时由人决定，并留下记录。

## 1. 界面用词表

规则：界面上只出现右列。左列只出现在文档、接口和"技术详情"里。

| 内部 / v0.1 用词 | 界面用词 | 说明 |
|---|---|---|
| 装载（分组） | 删除 | 子项直接升为一级 |
| 编排 | 对话流程 | |
| 画布 / 清单投影 | 流程图 / 列表 | 同一份数据的两种看法 |
| 验收 / 案例 | 测试 / 测试题 | |
| 发布 | 上线 | 只指正式环境 |
| 沙盒 | 测试环境 | |
| 专家 | 专家（**保持不变**，2026-10-26 产品确认） | 覆盖客服与销售两类岗位，落到行业叫法各异，"专家"作上位概称；行业叫法放在专家名称里，如"课程咨询顾问" |
| 事实 | 关键信息 | 价格、时效、名额这类会变的值 |
| 口径 | 标准话术 | |
| 守卫 / 硬规则 | 红线 | |
| 平台锁定 | 平台底线 | |
| 动作 / 工具 | 业务办理 | 能替客户办的事 |
| 结果承诺 / Outcome | 办成标志 | 例：拿到预约号 |
| 确认点 | 需客户确认 | |
| 未知（结果态） | 结果不明 | 不用"没确认"，避免和"需客户确认"撞词 |
| 冲突 | 说法不一致 | 列表标签用"不一致" |
| 缺口 / 未覆盖 | 没有出口 / 没人接 | 用具体后果描述，例："其他问题没有转人工出口" |
| 运行叠加 | 显示实际走向 | 流程图上的开关 |
| 证据抽屉 | 依据 | |
| 草稿 r37 / v12 | 草稿 / 线上版 | 编号只在依据面板出现 |
| 批次号、RUN-ID | 不显示 | 依据面板里可点进 |
| 幂等键、超时、读写字段 | 技术详情（折叠） | |
| 节点类型 入口/判断/办理/说话/交接 | 开始 / 判断 / 办理 / 回复 / 转人工 | |

**写文案的三条规矩**：

1. 状态写全词，不缩写成一个字。
2. 报错写后果和下一步（"其他问题没有转人工出口 → 加一个转人工"），不写规则名或字段路径。
3. 一个概念一个词，全站统一；新词先进本表再上界面。

**读法**：`●` 有待处理，`✔` 已通过，`⚠` 需要处理，`🔒` 平台底线。流程图里不再用符号表示节点类型，直接写字。

- "资料范围不包含价格"这种难组装的条件改成一句写好的话，由模板提供，不让用户拼三个下拉。
