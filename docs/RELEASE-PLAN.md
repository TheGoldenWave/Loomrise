## 1. 审视：六个问题

### 问题 1 · 合同迁移没有归属

`Behavior`（`ALLOW`/`DENY`/`ASK`）到 `Verdict` 四层、`ServiceRequest` 加 `subject_id`，这两件**既不在 S1 退出 Gate，也不在 S2-a 工作包**。它们会动已经留证的 11/11 回放和 `adapters/agentscope_runtime.py` 的映射。不单独排期，就会在 S2-a 实施时被当成"顺手改"，风险与功能开发叠在一起。

### 问题 2 · S2-a 一个 Gate 验不完

现有 S2-a 包含：持久化、幂等、摄入、物料、Widget、Inbox、MCP 受限创建、最小沙盒发布、配置版本。再加上今天新定的硬规则 v0.2、单元清单、条件深度校验、`subject_id`，会变成**既改形状又加功能**。

而且它的验证方式本来就是两类：**配置可信**靠"保存/提交校验 + 字段级 diff"，**运行可信**靠"重启恢复 + 幂等 + 只写一次"。两类混在一个 Gate 里，任一失败都会拖住另一个。

### 问题 3 · 图的落点前后矛盾

RG-1 原写"IA 17 → 18 页"，[前端方案](S2-ORCHESTRATION-UI.md) §1 已更正为"不新增二级页"。**已修**（RG-1 行）。但更要紧的是：**S2-a 只交清单+规则、画布到 S2-b**（RG-F10），这意味着 **S2-a 的 `Unit` 契约必须预留 `body` 字段**，否则画布上马时要迁草稿。

### 问题 4 · 语音 Gate 换了指标，但还判不了过/不过

D-03 已经给出四条硬指标，比"采集过数据"进一步。但三处仍然缺：

1. **停止时延 p95 的上限是空的**（[语音验证计划](VOICE-COORDINATION-VALIDATION.md) 写"阈值待 S1 基线登记"）——Gate 现在只能判"登记了没"，不能判"过没过"；
2. **R0 只继承了四条交互指标，漏掉了 S1 Gate 原有的另外四项**：真实网页音频、一条固定中文 STT/TTS 组合、中文可懂度、真实模型驱动的 SSE 消费（[客服方案 §3](CUSTOMER-SERVICE-DELIVERY-PLAN.md) S1 行明写）；
3. **P1 说话人级与 P2 语义级指标没有分列阶段**——它们按 D-03 属于 S2-c，放在 R0 会变成一个永远过不了的退出条件。

**修法**：Gate 判据改成"**阈值已登记（带时间戳）且结果未超**"，并且 S1/S2-c 分行登记。这样今天就能当基线用，不必等实测。

### 问题 5 · EL 30 项是清单，不是计划

"可借 30 项"散落在总纲 §8.1 与 §13.7，没有一项写明"哪一版做"。清单不落版本，就永远不会进计划。**v0.2 补一条**：每项不绑用户问题与验证指标者，一律保持**候选**，不构成范围承诺（见 §5）。

### 问题 6 · 记忆与 Task 的接入点已变

`subject_id` 从"待定"变成"已裁决"，但 TM-01 至今写的是"主体/服务周期"——**具体字段没有指到 I1 的结论**。而 C6（证据不得自证）是评测期才验得动的，不属于 Task 基础片。

**为什么不是 R0–R5 六段**：R5 的两半依赖完全不同（R5b 要复用 R5a 已验的发行包），共用一个退出判据就会出现"首云没验完却按扩云过了"。

### 2.1 三层视图：产品能力 / 前端 / 后端

同一个版本，三种读法。**产品能力**是对外可感知的差别（用户能不能多做一件事）；**前端**是可点的界面与交互；**后端**是合同、存储与执行。三者不同步是常态——R1 的产品能力很轻，后端却很重。

|---|---|---|---|

## 7. 关键路径与风险

**唯一硬串行**：R0 合入 → R1 配置器（要 `Verdict` 与 `subject_scope`）→ R2 发布（要真实版本）→ R3 图（要真实配置验过）→ R4 路径断言（要图有路径）→ R5a 发行 → R5b 扩云。

**四个真实风险**

1. **R0 拖长**：语音证据是外部依赖（固定 STT/TTS 组合），一旦选定就锁版本。已有处置：合同代码分支并行，**不合主干**；验收顺序仍是证据先。
2. **R1 的 `Unit` 契约定错**：九字段里 `body` 与 `on_event` 最容易漏。漏 `body` → R3 迁数据；漏 `on_event` → 边界事件要改合同。**Unit 已于 2026-10-22 采纳为正式合同**，不再是提案。
3. **R3 的画布变成"必须品"**：RG-6 判据是"分支间权限/知识范围/合规处置是否真的不同"。若真实配置里 90% 的图都不满足，画布就只是展示品。**处置：任务测试基线不达即降级为可选视图。**
4. **"工件齐全"式的自我认证**：最容易发生的是把五组工件当成五条 Gate。处置：退出判据只认矩阵行号。
