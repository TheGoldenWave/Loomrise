## Design Context

### Users
Builders and strategy operators configure, inspect, compare, and validate customer-service and sales agents. They need to find configuration gaps, understand routing and version changes, and preserve a clear path from draft edits to server validation and approval.

### Brand Personality
Calm, pragmatic, and accountable. The interface should reduce uncertainty and make configuration consequences easy to inspect without feeling promotional or theatrical.

### Aesthetic Direction
Use the existing light, compact operations-workbench style: system Chinese fonts, neutral surfaces, restrained blue for primary actions, fine separators, and compact fixed-scale typography. Reference ElevenLabs Workflow for node summaries, a persistent inspector, and progressive disclosure. Do not copy its configuration authority or probabilistic control semantics. Avoid marketing layouts, decorative card grids, external font/image dependencies, and color-only status cues.

### Design Principles
1. The canvas, unit list, rules, inspector, and version comparison remain projections of the same server-backed draft.
2. Keep the keyboard-equivalent list and rule views complete; graph interaction is not the only way to inspect configuration.
3. Make validation errors textual and actionable, with object-level context and a path to the relevant field.
4. Keep canvas coordinates and temporary layout in session view state, never in configuration, revisions, or diffs.
5. Preserve compact responsive layouts and explicit text labels for status at desktop and narrow widths.
