# Loomrise 的 Agent 自迭代：长效方案与分期规划 v0.1

> 状态：**方案提案，未实现、未验证**。2026-11-04。
> 本文不新增产品阶段、不改 ROADMAP 的阶段与 Gate、不新增第七层配置合同、不替代 [S2 治理设计](S2-DESIGN.md) 与 [评测门禁提案](S2-EVAL-GATE-PROPOSAL.md)；它做的是把三处已有材料合成一条**可分期执行的长线**：Loomrise 自己的治理设计、作者在另一处已投产的对话式 AI 托管业务中的迭代实践（脱敏后只保留方法论，来源与原文留 `private/`，不随公开仓发布）、以及 [Agent Autoloop 运行时研究](AGENT-AUTOLOOP-STUDY.md) 的执行纪律。
> 文中所有"已实现"均指有验收证据的工件；其余为设计、提案或规划。

## 0. 一页纸

**两件事必须分开，否则永远做不成。**

- **L-Run（运行时 Loop）**：访客说一句，Agent 在证据、权限、业务结果约束下做完一件事。S1–R3 建的是这个。
- **L-Evolve（进化 Loop）**：优化器观察 L-Run 的产出，改动它的配置。这是元 Loop，现在是空的。

自迭代不是"让 Agent 自己改自己"，而是**把人的调优动作拆成六个可替换的角色**：感知、诊断、假设、修改、验证、决策，每个角色都有独立的证据要求和权限上限。人从"逐条改"退到"审批 + 兜底"，但**永远保留上线权**。

**一条铁律**：`证据等级`不能跳级。L1 线索只能产候选根因，L2 配对回放才能说"离线有效"，L3 线上实验才能说"真的提升了"。任何把 L1 写成结论、把相关性写成因果的候选，一律不进候选池。

**五个阶段**（对齐现有版本，不新增阶段）：

| 阶段 | 目标 | 落在哪个版本 | 一句话判据 |
|---|---|---|---|
| E0 基座 | 运行事实可回放、案例可分层、评测可复现 | R1–R3（部分已有） | 同一版本同一批次回放两次，结论一致 |
| E1 诊断 | 只读诊断能定位到具体节点，且敢说"非责任方" | R3 简版 → R4 完整 | 诊断结论能反查到具体 `RunEvent`，且有对照证据 |
| E2 候选受控 | 改动小步、单单元、过八道门 | R4 | 跨单元候选被拒；过拟合候选被泛化门拦下 |
| E3 审批发布 | 审批有依据清单，自治分三档 | R4 | 低风险可自动灰度，高风险必须人批 |
| E4 记忆复用 | 失败不再重犯，门自身有体检 | R5a | 同类驳回不重复出现；泛化门拒绝率不为 0 |
| E5 外层复盘 | 季度回看"我们的判断标准还对不对" | R5a 之后 | 每季度产出一次风险分级的重划结论 |

## 1. 先把"自迭代"拆开：三层 Loop 与当前缺口

沿用三层 Loop 的划分（内层执行、中层开发者反馈、外层真实反馈），Loomrise 的缺口分布很不均匀：

| 层 | 它回答的问题 | 证据来源 | Loomrise 现状 |
|---|---|---|---|
| **内层 · 执行** | 这一次做对了吗 | `RunEvent`、硬规则、确定性裁决 | **有**。S1–R3 已落，702 项 Python / 340 项前端回归 |
| **中层 · 开发反馈** | 系统为什么没按设计执行 | `Case`、诊断、配对回放 | **半有**。`Case` 合同在，AGI-07 只读诊断有 R3 简版；配对回放、泛化审查没有 |
| **外层 · 业务反馈** | 这套设计本身还对不对 | 灰度、实验、周期性复盘 | **近乎空**。`Rollout` 只有合同，没有实验协议、观察窗口与复盘制度 |

这解释了一个反复出现的错觉：**内层越扎实，越容易以为自迭代快成了。** 实际上内层只保证"这一轮没跑错"，不保证"下一版更好"。三层各自的验收物不能互相顶替——这是本方案的第一个约束。

第二个约束来自另一个方向的实践：**诊断不得只吃失败样本。** 只有失败案例时，无法区分"机制有缺陷"和"这次用户情况特殊"，据此改出来的东西能通过 Target 门，却过不了泛化门。所以诊断必须带**对照证据**（同动作的成功样本），且必须允许结论是"非责任方"。

| 已投产业务的迭代实践（脱敏） | 三组回放（Target / 同分布留出 / 跨场景）、八道门（含泛化门）、七个进化单元、失败修改记忆、审批依据清单、三档自治、门自身体检 | 具体业务配置、指标口径、组织流程——不入公开仓 |
| [Agent Autoloop 研究](AGENT-AUTOLOOP-STUDY.md) | 运行纪律：挂起零消耗、跳数熔断、在途版本冻结、写错降级、`unknown` ≠ `failed`、逐轮记账 | 形态：单机中台、`rules.json` 即权威、回执模型 |

三者不重叠：前者管**判断**，中者管**验证**，后者管**跑得住**。任缺一角，闭环都会在真实节奏里散架——只有判断没有运行纪律，等待三天就丢了上下文；只有运行没有验证，改得越多错得越快；只有验证没有判断，门禁会退化成盖章。

## 3. 目标形态：一条证据链，六个角色

```text
观测（RunEvent / Case / 指标）
   │
   ├─► 提名 CaseNomination（L1：线索，附可观察证据）
   │        └─ 人审定 ─► Case（真值：期望业务状态 + 必须/禁止动作）
   │
   ├─► 诊断（只读）──► 候选根因 + 对照证据 + is_culprit（允许为 false）
   │
   ├─► 假设 ──► ChangeProposal（evolution_unit + changed_scopes + applicability）
   │
   ├─► 修改（受控编辑）──► 候选版本（父版本冻结，单单元，预算内）
   │
   ├─► 验证（L2）──► 八道门 ──► EvalResult
   │        └─ 拒绝 ──► RejectedEdit（失败记忆）
   │
   ├─► 决策（人）──► 审批依据清单 ──► Release ──► Rollout
   │
   └─► 线上（L3）──► 观察窗口 ──► 全量 / 回滚 ──► 经验回写
```

六个角色与现有对象的对应关系，全部复用已有名字，只补字段：

| 角色 | 现有对象 | 需补什么 |
|---|---|---|
| 感知 | `CaseNomination` | 信号来源标记（确定性 / 行为异常 / 业务发现） |
| 诊断 | AGI-07 只读诊断 | 对照证据引用、`divergence`、`is_culprit`、诊断价值分层 |
| 假设 | `ChangeProposal` | `evolution_unit`、`changed_scopes[]`、`applicability` |
| 修改 | 配置服务 + AGI-08 Worker | 受控编辑协议（允许范围 + 单轮预算） |
| 验证 | `EvalSet` / `EvalResult` | 八道门结果、`GateResult`、三组回放分组 |
| 决策 | `Release` / `Rollout` | 审批依据清单、自治档位、观察窗口与样本量下限 |
| 沉淀 | — | 新增 `RejectedEdit`（失败记忆），成功记忆沿用 `Case` 归档 |

## 4. 分期规划 E0–E5

### E0 基座：先把 Oracle 做成可调用的

> 命门。没有可程序化调用的"回放 + 评测"，后面全是空中楼阁。

- **已有**：SQLite 持久运行事实、`ExecutionService`、配置版本、R3 的评测/诊断/治理作业四表（由 v21/v22 引入；当前 `SCHEMA_VERSION = 23`，v23 为服务周期生命周期增量）。
- **要补**：把回放与评测包成稳定调用面（AGI-01 的同一套服务合同），**同一 EvalSet 版本 + 同一批次 + 同一阈值快照**可复现两次一致；`EvalResult` 必带 `case_set_version` / `batch_id` / `threshold_snapshot`（[评测提案](S2-EVAL-GATE-PROPOSAL.md) 已有字段要求，需真正落库）。
- **退出判据**：同一候选版本在冻结环境回放两次，逐例结论一致；不一致时能定位到模型非确定性、工具模拟差异还是案例问题。
- **不做**：不做自动候选、不做线上实验。

### E1 诊断：敢说"不是这里的问题"

- **要补**：诊断输入加入**对照证据**（同动作成功样本 1–3 条），匹配优先级 `action_id` 必须相同 → 阶段相同 → 画像/上下文相近 → 时间接近；无对照时标 `contrast_unavailable`，**降级为单侧诊断并在结论上显式标注，不得假装有对照**。
- **要补**：诊断输出三个必填字段 `divergence`（从哪一步分叉，引用序号）、`counterfactual`（有没有具体改动能让它转好）、`is_culprit`（是否责任方）。**`is_culprit = false` 必须被允许并鼓励**——产不出候选时，正确答案是"非责任方"，不许凑数改动。
- **要补**：诊断价值分层——同批内同动作既有成功又有失败的（可配对）优先；只靠历史成功轨迹可配对的次之；只有坏例且无任何成功参照的**不做根因归因**，转补证据或走能力缺失排查。
- **退出判据**：任取一条诊断结论，能反查到具体 `RunEvent` 序号与对照样本；抽查中至少存在被判"非责任方"的案例且经人工确认合理。
- **不做**：诊断不写库、不改配置、不确认真值（AGI-07 边界不变）。

### E2 候选受控：小步、单单元、过八道门

这是本方案与现有设计差别最大的一段。三条硬规则：

1. **单单元**。改动必须落在一个进化单元内，跨单元必须拆成独立候选、各自独立过门，**不允许打包验证**。依据是公开文献的实测：[ModularRSI](https://arxiv.org/abs/2609.14857) 报告联合全模块进化 **44.19 低于基线 47.57**，而模块化独立进化后集成达到 **52.43**——一次性大范围改会主动造成伤害，且无法归因（改好了不知道是哪处起作用）。
2. **受控编辑**。按风险分档给出可改范围与单轮预算：低风险（措辞、格式、局部提示）最多 3–5 条；中风险（单个 Skill 局部、SOP 顺序、物料替换）1 个；高风险（人设、目标、合规、价格承诺）**只出建议，不自动改**。
3. **新增分支必须声明适用面**。任何新增条件分支要附 `applicability`（预计覆盖的真实流量比例 + 适用人群边界），未声明不进门。

**七个进化单元**（与 Loomrise 六层对齐，不新增层）：全局取向、任务与路由、动作执行策略、资产与知识、上下文构建、工程与链路、模型侧。**模型侧默认不进候选池**——推理错误只产工程需求（换模型/加校验/加护栏），不产配置候选。

- **退出判据**：构造一批跨单元候选，全部被前置检查退回拆分；构造一批样本特定条件（用户名、课程名、日期、话术原文）的候选，全部被泛化门拒绝。
- **不做**：不做多候选合并、不做"改大一点一次到位"。

### E3 审批与发布：把审批人的直觉写下来

- **审批依据清单**（审批页必须逐项展示，而不是只给"分数达标 + Diff"）：人设与合规红线、历史踩坑相似度（查 `RejectedEdit`）、当期业务优先级是否仍匹配、目标属于硬目标还是有 Oracle 局限的软目标、影响面是否超出当前灰度观测能力。缺项必须标"待观察"，不能默认通过。
- **三档自治**：A 建议（高风险，只产建议与报告）、B 半自动 + 闸门（中风险，停在人工审批）、C 自动灰度 + 事后审计（低风险）。**放行顺序只能是 A → B → C**，且 C 的前置是 E0–E2 全部有证据。
- **观察窗口分级**：低风险 3 天 / ≥200 会话，中风险 5 天 / ≥100，高风险 7 天 / ≥50 且需人工抽检。**未达样本量标"证据不足"，不强行判定成功**；这是试运行下限，不是统计意义上的因果样本量。
- **退出判据**：审批页五项依据齐全可核；低风险自动灰度出现确定性红线时自动回滚并留证。
- **不做**：不做全自动上线；不做跨版本自动回溯修补。

### E4 记忆复用：让第二次犯同一个错变得不可能

- **失败记忆 `RejectedEdit`**：`attemptedChange` / `failedGate` / `regression`（是否修 A 坏 B）/ `reason` / `retryPolicy`（下次禁止重复 or 允许换假设）。启动新一轮时**先检索**，不允许无视历史直接重试同一改法。
- **成功记忆**：通过的候选与灰度结论归档，附适用范围，避免"下一轮又把它改回去"。
- **门自身的体检**（这一段最容易被忽略）：泛化门拒绝率、配对可用率、跨单元拆分占比、集成轮次检出冲突数、L1→L2→L3 证据升级率。**若泛化门拒绝率长期接近 0，说明门形同虚设**，要么改门，要么改诊断——而不是庆祝"候选质量高"。
- **退出判据**：同一驳回原因在 N 轮内不再重复提出；门的体检指标有基线并可比较。

### E5 外层复盘：问"我们的标准还对不对"

每季度对本季所有已全量版本做一次回看，逐条回答三问：

1. 有没有某次"低风险"改动，回头看其实造成了隐性伤害，只是没触发回滚阈值？
2. 出现的新失败类型/新口径，是否已经喂回案例集与验证门槛？
3. 风险分级（哪些可自动/哪些必人审）是否还匹配当前业务重心？

结论落三处：改自治档位归类、改明确不做清单、改**门本身**。复盘记录与 `RejectedEdit` 同库归档，形成"内层失败记忆 + 外层方向复盘"的完整闭环。

**这一层是 Loomrise 目前完全空白的一层，也是最容易被长期忽略的一层**——因为它不产生功能，只产生"下一版的方向是否还成立"。

## 5. 合同增量（尽量少动）

| 对象 | 变更 | 理由 |
|---|---|---|
| `ImprovementRun`（提案中） | 加 `awaiting_human`、`waiting_on`、`resume_ref`、`chain_depth`、`spent`（轮/token/金额/缺失四项并列） | 等待语义、熔断、成本归因（来自运行时研究） |
| `ChangeProposal` | 加 `evolution_unit`、`changed_scopes[]`、`applicability`、`generalization_basis` | 单单元、适用面、泛化依据 |
| `EvalResult` | 加八门 `GateResult`（逐门结论 + 拒绝理由 + 审查者身份） | 门的结论要能被复核 |
| 新增 `RejectedEdit` | 五个字段 | 失败记忆 |
| `Release` | 加审批依据核对结果（五项，可留白待观察） | 让审批可审计 |

**不新增层、不新增阶段编号。** 上述都是字段级增量，可在 R4 的数据模型稿里一次落定。

## 6. 八道门（按顺序判，前门不过不进后门）

| # | 门 | 判什么 | 不过怎么办 |
|---|---|---|---|
| 0 | 单元完整性 | `changed_scopes` 是否只落一个单元 | 退回拆分，不进任何门 |
| 1 | 目标修复门 | 目标案例配对回放是否达阈值 | 回假设 |
| 2 | 回归门 | 同分布留出、跨场景、高风险边界不退化 | 回假设 |
| 3 | 引用门 | 知识/物料/工具引用合法、未过期 | 修引用 |
| 4 | 越权门 | 硬规则、工具权限、价格承诺、结果语义未被改写 | 直接拒 |
| 5 | 解释门 | 人可读的理由、改动范围、预期收益、不确定性 | 补解释 |
| 6 | 实验设计门 | 案例集版本、批次、阈值快照、分层、分流完整 | 补设计 |
| 7 | 最差分层门 | 总体提升不能抵消关键分层退化 | 拒 |
| 8 | 泛化门 | 改动是否只对这批样本成立 | 拒 |

**第 8 门必须在，因为第 1 门必然通过**——改动就是冲着目标集做的，回放全绿说明不了任何泛化能力。三条硬要求：审查**不看**第 1 门结果（避免被"已经修好了"锚定）；审查者不得复用生成该 Diff 的同一上下文；必须给出 `generalization_basis`，空话不接受。

## 7. 度量：七组业务 + 四项门体检

| 组 | 指标 |
|---|---|
| Loop 健康度 | 迭代吞吐、一次通过率、证据不足率、人工干预率、回滚率 |
| 实验可信度 | 案例集版本/批次完整率、配对回放覆盖率、证据升级率 |
| 业务效果 | 各场景完成率/转化率（总体与分层）；**未随机化的历史对比不得称为净效果** |
| 质量护栏 | 三门通过情况、最差分层退化、硬规则触发、人工接管与投诉风险 |
| 资源 | token、延迟、重试、人工成本；质量提升必须同时报成本代价 |
| 归因质量 | 配对可用率、泛化门拒绝率、跨单元拆分占比、集成冲突数 |
| 门体检 | 上述四项的季度趋势与基线对比 |

指标一律带**标识、粒度、分子分母、观察窗、版本、证据状态**；证据不足写"缺失"，**不能填零**。

## 8. 首个试点建议

选一个"目标明确、坏例易收、Oracle 好定义、改动范围可控"的场景，建议用仓库既有的**虚构成人课程咨询**场景包的"试听邀约"局部：

| 维度 | 建议 |
|---|---|
| 允许改的范围 | 只改"邀约 Skill"的局部规则，不动人设、全局目标、价格承诺 |
| 样本 | 首批 20–50 条高质量案例用于调试 Harness，正式样本量按分层与基线再定；**用途在生成假设前冻结**，防止答案泄漏进留出集 |
| 首轮交付 | 建议卡 + Diff + L2 证据 + 不确定性；**先只做 A 档（建议模式）** |
| 验收 | 五项审批依据齐全；跨单元与样本特定条件的候选被拒；高风险字段越界 0 次；人工采纳率仅作观察 |

## 9. 明确不做

- **不做模型微调/训练**：只迭代策略配置，不碰权重——成本、可控、可回滚。
- **不做实时在线学习**：不在单次会话内改策略，迭代以批次 + 离线回放进行。
- **不做全自动上线**：至少 E3 之前不放开；C 档只对低风险场景，且带自动回滚。
- **不做跨单元合并验证**：范围小不等于可以合并验证。
- **不做复杂因果平台先行**：能配对就先配对，能随机就先随机；只有无法随机化且数据满足条件时才评估准实验。
- **不把模型自述当证据**：模型说"提升了 30%"不算，必须挂回放或实验数据，否则标"未验证"。

## 10. 风险与止损

| 风险 | 表现 | 止损 |
|---|---|---|
| 过拟合目标集 | Target 全绿、线上不动 | 泛化门 + 同分布留出 + 季度复盘 |
| 门形同虚设 | 通过率接近 100%、拒绝率接近 0 | 门体检指标 + 定期换审查者 |
| 真值污染 | 因候选失败而回填案例 | 真值修正只允许源于业务判断变化或标注错误（现行约束不变） |
| 理解力腐蚀 | 长期自动改，人看不懂配置为何如此 | 每次改动强制人可读理由 + Diff + 证据；工作台可追溯 |
| 成本失控 | 回放次数随单元数线性膨胀 | 按风险差异化：低风险单单元直通、跳过集成轮次 |
| 外层长期缺位 | 每年都在优化一个已过时的目标 | E5 季度三问制度化，写进运营日历而非文档 |
