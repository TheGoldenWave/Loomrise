# S2 范围讨论记录 v0.3

状态：**范围讨论中；以下为已确认的产品方向，不代表已设计完成或已实现**。2026-09-28。

本文件增量记录 S2 人机协同与受控改进的范围决策。阶段总目标与退出 Gate 仍以[验证路线](ROADMAP.md)为准；对象和权限边界见[架构与对象权威](ARCHITECTURE.md)。讨论结束后再形成完整设计和验收方案。

## 已确认方向

1. **发布责任：S2 采用版本级人工审批。** 系统可汇总低风险候选及其验证证据，人在一次审阅中批准或拒绝整个候选版本；高风险变更单独逐项审批。预先授权范围内的自动发布是后续探索方向，不属于 S2 承诺。
2. **候选修改范围：先覆盖表达与执行策略。** 系统可提出措辞、示例、重复内容整理、任务步骤、澄清顺序、Skill/SOP 和有限检索参数的候选修改。对硬规则、工具权限与副作用、价格或业务承诺、业务结果语义的修改不得进入该自动候选范围；以后是否扩大为独立的待审建议，另行决策。
3. **人的坏例标注：确认业务真值，不要求配置归因。** 标注者确认期望业务状态、必须做与禁止做的动作；原因可选填。系统负责先分析运行证据并建议失效环节与修改位置，但其归因不代替人工审定的真值。需要持久副作用和结果 ID 的案例仍按[产品定义](PRODUCT.md)中的评测规范补足。
4. **坏例来源：人工标记与系统提名并行。** 系统可根据可观察的运行失败、反复纠正或配置冲突等信号提名可疑案例；提名不等于确诊。进入正式评测集之前，业务真值仍须人工确认。
5. **提案组织：按共同原因归并。** 系统把相关案例及运行证据关联到一处尽可能小的候选修改，并保留每个来源案例的追溯关系。允许候选删除或合并重复的表达与执行策略内容，而不只是追加配置；必须用旧案例回归检查退步。
6. **提交校验的阻断权：确定性优先。** 硬规则冲突、越权或缺少必要证据等确定性问题阻断版本提交；模型识别出的重复或语义冲突先作为建议，交由人审阅，不直接阻断。
7. **审批证据与差异展示：版本级可审阅。** 审批页至少展示改动摘要、关联案例、旧版与候选版的配对回放对比、硬规则检查结果和成本变化；版本差异采用类似 VS Code 的 diff 形式，详细运行轨迹按需展开。
8. **编辑与审批责任：区分记录，按团队规模加强。** 系统分别记录编辑者与审批者；单人项目允许自审，多人团队可启用强制复核。确定性的安全门禁始终有效，不因单人自审或人工豁免而绕过。
9. **评测门槛：人登记初始值，阈值本身受版本管理。** 系统在跑候选版之前读取已登记的阈值，不得在运行中为了让本次通过而临时放宽；系统可以提出阈值调整建议并附证据（如机评与人工校准的一致率、误报率、成本漂移），但阈值改动必须与候选版本走同样的审批流程。硬规则违规、关键退步和缺少必要证据**不是评分项**，而是一票否决项，不进入打分阈值体系。
10. **回滚：确定性红线自动回滚，其余由人决定。** 这里「发布」指候选版本成为场景当前生效的版本。硬规则违规、重复写入、结果缺失和关键退步等可确定性判定的信号命中时，系统自动把生效版本切回上一个已发布版本并告警；软质量下降与成本漂移由人决定是否回滚。自动回滚只回退到上一个已发布版本，不做跨版本搜索或自动修补；回滚产生带证据的事件记录，人可以推翻，推翻同样需要审批。
11. **风险分类：内置默认 + 场景级覆盖，默认只能收紧，放宽以带时限的临时授权实现。** 系统内置一份低风险/高风险分类基线，场景可以在默认基础上把某类内容**升级**为高风险；内置高风险项**不能**被永久降级为低风险。业务在不同时段关注点不同，因此允许放宽，但放宽必须以**临时授权**形式存在：显式写明有效期、理由与适用范围，到期自动恢复到默认分类，不续期即失效。放宽只影响「由谁审批、是并入版本审批还是逐项审批」这一层，不影响确定性安全门禁和一票否决项。所有覆盖与放宽动作都要审批并留证，审批页需显著显示当前是否处于临时放宽窗口。
12. **策略档位（Policy Profile）是一等对象。** 一整套「风险分类 + 阈值 + 审批要求」打包为命名档位（如日常档、大促档、风控收紧档），可复制、可 diff、受版本管理；切换需审批并留证，可携带有效期自动回落。临时放宽不再是配置上的一次性补丁，而是「切换到某个档位 + 到期时间」。S2 alpha 只预置两档（默认档与一个收紧档），先跑通「切换 → 审批 → 生效 → 到期回落」链路，档位数量后续扩展。
13. **档位切换权只属于人。** 系统可以提议切换并附证据，但不能自行切换，**收紧方向也不自动执行**。允许「预设切换时间」：人提前设定切到某档与切回的时刻，到点由系统执行；这属于人工决策的延后执行，不等同于系统根据运行信号自行决定切档。
14. **预设切换到点直接生效，但带基线校验与观察期。** 授权时记录基线快照（当时生效版本、阈值、资料与工具版本）；若到点时这些已发生变化，则不直接执行，转为待审批项由人确认。切档生效后进入强制观察期，确定性红线命中照样触发自动回滚，预设切换不豁免安全门禁。

## 仍待细化

- 内置高风险清单的初始项与增减：目前为硬规则、工具权限与副作用、价格或业务承诺、业务结果语义四类，是否加入身份与授权范围、外部写入等仍待确认。
- 临时授权与策略档位的有效期上限、是否允许续期，以及窗口期内的额外证据要求。
- 观察期时长、判定信号与超期处理。
- 多人团队强制复核的具体配置方式。
- 自动提名的信号、归并依据、误报处理与案例优先级。
- 各场景质量与成本阈值的初始值怎么定，以及首批基线的采集方式。

上述方向不改变 S1 退出 Gate，也不意味着自动发布、真实外部写入或生产适用性已经得到验证。公开案例只使用原创虚构或明确获授权的材料。
