# 实时语音与后台任务协同验证计划 v0.1

状态：规划、待固定版本和运行实测，2026-09-26。本文件不代表 Pipecat、Qwen Audio Agent 或 Gander 已在 Loomrise 接入，也不承诺任何上游项目提供开箱即用的双模型协同接口。候选项目的最新 API、许可证、资源要求和功能范围均须在实验前重新核对。

## 产品边界

已确认的 Loomrise 产品路线仍是单一交付工作台、统一 `ExecutionService`、分类适配器和首版单 Agent。网页文字与网页语音共享业务请求、权限、工具、取消语义和持久结果。双模型协同属于语音体验的**可选实验**，不是第二套业务内核，也不是 S1 纵向样例的前置条件。真实电话和批量外呼不属于此实验。

| 候选项目 | 本计划中的研究角色 | 不直接交给上游的责任 |
|---|---|---|
| [Pipecat](https://github.com/pipecat-ai/pipecat) | 默认网页语音工程链路候选：传输、流式音频、轮次、打断和模型/服务接入 | 业务 `ServiceRequest`、工具权限、确认、结果持久化和发布版本 |
| [Qwen Audio Agent](https://github.com/QwenAudio/qwen-audio-agent) | 前台实时交互与后台任务分工的限时对照 | 业务状态、成本账本和生产写入授权 |
| [Omni-Interaction-Agent / Gander](https://github.com/Omni-Interaction-Gander/Omni-Interaction-Agent) | 全双工交互、目标变更及过期结果处理的研究与体验对照；具体机制待源码核对 | Loomrise 的运行权威、业务工具和默认部署选择 |

比较的是能否满足同一组产品验收条件，不把不同定位的项目简单视为可互换的完整底座。上游的演示效果、框架可编排性或论文指标都不等于 Loomrise 已有可复现的集成。

## 拟验证的前后台分工

1. **S1 基线**：先以一条语音链路完成虚构课程咨询。媒体适配处理输入、输出、打断与播出状态；所有业务请求交给同一个 `ExecutionService`。记录首响、成本、确认和一次且仅一次的模拟预约结果。
2. **可选协同实验**：仅在基线的延迟、交互连续性或复杂任务等待暴露明确问题时，让前台低延迟模型处理简短回应和澄清；后台模型处理需较长时间的检索、比较或任务建议。两者通过有版本的任务请求/结果交接，不直接共享可写业务状态。
3. **结果回流**：后台结果携带 `request_id`、`run_id`、发起时的任务代次、版本和有效期限。回流前校验任务仍有效、目标未改变、权限与确认仍成立；失效的结果可留审计记录，但不得继续播报或触发副作用。业务工具最终由执行内核再次校验并执行。

前台停止播报、模型生成被取消、后台任务被确认取消、外部工具的实际结果是四种不同事实。用户打断或改目标时，应停止过期的待播内容并请求取消相关后台工作；若写入已发起，必须查询或等待外部结果，不能把“取消请求已发送”写成“业务动作已撤销”。播出状态未知也不能记为用户已听见。

## 对照实验与退出门

在同一虚构场景、相同授权资料与模拟工具条件下，至少覆盖普通咨询、需要后台检索的比较、用户在等待时改变目标、打断播报、重复确认、弱网/超时和取消后工具回执。记录固定依赖与模型版本、设备和网络、首个可听响应、轮次时延、打断恢复、过期结果误播报、任务成功、重复写入、资源占用及单位成功任务成本。主观语音质量由人工审阅；硬规则、任务状态与副作用由确定性检查裁决。

只有在基线存在可复现的体验缺口、协同方案显著改善该缺口，且没有引入越权、旧结果误播报、重复写入、取消状态混淆或不可接受的成本/部署负担时，才考虑将双模型协同纳入后续路线。若候选上游需要侵入 Loomrise 业务合同、资源超出 Lite 的预期，或没有提供可验证的打断/回流语义，则保留为研究参照；不得同时维护多条默认生产语音链路。阈值须在测试前登记，不根据结果倒填。

本计划与[产品形态与开放接入规范](PRODUCT-FORM-AND-INTEGRATION.md)、[架构边界](ARCHITECTURE.md)、[验证路线](ROADMAP.md)及[参考项目采用边界](REFERENCE-PROJECTS.md)并行使用。正式路线仍以这些文档的阶段 Gate 为准，实验结论需有可复现记录才能升级为已验证事实。
