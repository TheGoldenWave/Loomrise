# 策略运营人员后台配置说明（营销运营视角）v0.1

日期：2026-10-19。状态：依据当前后台设计编写的运营参考；不代表真实后台服务已实现。

本文面向负责客服、销售智能专家配置与效果治理的运营人员。Loomrise 将此角色称为“策略运营”。Loomrise 不是批量营销外呼工具；电话触达也不在当前可运行范围内。

## 建议的配置顺序

1. 在“专家列表”选择一个专家，再从“业务概览”确认当前版本、主要缺项和下一步。
2. 在同一个专家草稿中配置服务目标、依据资料、流程和业务动作。保存草稿不会创建用户事项。
3. 只有业务确实需要跨会话跟进，且任务服务通过相应 Gate 后，才配置“任务与主动服务”。目前该模块尚未实现；一般 FAQ 不要求先设置主动策略。
4. 用获授权资料和固定模拟情景试用，检查答复、等待、阻断和转人工是否符合预期。
5. 规划中的正式流程是根据运行证据建立案例或改动候选，经评测和审批后发布。当前原型中的审批和发布操作仅为本地演示；发布新版本不会自动迁移未完成事项。

## 三种配置深度

| 深度 | 用途 | 运营人员查看什么 |
|---|---|---|
| 业务概览 | 判断当前专家状态和下一步 | 当前版本、主要缺项、试用或治理入口 |
| 业务配置 | 编辑日常业务含义 | 服务对象、回答范围、流程、字段、策略和任务蓝图 |
| 详细配置 | 核对技术依据和依赖 | 当前原型可查看部分字段标识、引用和版本来源；类型化条件编辑器属于待实现设计 |

三种深度查看同一个草稿或只读版本。展开详细信息不会增加权限；条件摘要说明规则表达，不代表具体用户已命中。

## 专家配置模块

专家配置写入当前专家的同一草稿，历史版本只读；知识资料、物料和模型连接保留各自的对象与生命周期，由专家版本引用或选择。以下十个模块已有本地交互原型；“任务与主动服务”是最新方案新增的模块设计，尚未加入原型或正式服务。

| 模块 | 功能定义 | 配置要求 |
|---|---|---|
| 接待与回答 | 定义专家服务谁、处理什么问题、如何表达以及何时转人工 | 写明服务对象、范围、目标和无法处理时的出口；价格、政策和承诺必须有获授权依据 |
| 依据资料 | 管理专家回答可引用的事实来源 | 记录来源、授权范围、有效期、审阅和可用状态；撤回后不得继续检索；知识资料与可发送物料分开管理 |
| 服务流程 | 描述当前请求的步骤、回退和转人工路径 | 每一步对应清楚的条件和出口；流程说明不能授予业务动作权限 |
| 业务字段 | 定义需要收集或由业务动作返回的信息 | 只收集必要字段；当前原型可录名称、来源、必填和唯一标识；类型与完整校验按正式字段合同确定后配置；用户实际值不写入专家配置 |
| 处理策略 | 维护适用条件、处理步骤、示例和退出方式 | 说明何时使用、如何处理及何时结束或转人工；自然语言可指导处理，但不能代替可执行条件或权限规则 |
| 必须遵守的约束 | 管理权限、确认、停止和不可突破的业务边界 | 由模型外规则裁决；使用已批准的类型化字段和算子，不用自由文本、脚本或任意 JSON 定义执行规则；完整规则编辑合同仍待确认 |
| 业务动作 | 配置专家可请求的业务工具及确认要求 | 只接入必要动作；区分只读与写入，明确输入、授权、确认、预算、幂等和结果证据；注册工具不等于专家获准使用 |
| 结果与验收 | 定义事项或业务请求如何判定完成、失败、取消或未知 | 为每种结果指定证据；生成、发送、送达、问题解决和业务办理成功分开记录；口头声称完成不算结果证据 |
| 模型与预算 | 选择版本使用的模型连接并设定调用预算 | 使用凭据引用，不在页面暴露密钥；区分平台默认、专家版本和试用临时值；模型选择不增加工具权限 |
| 版本与变更依据 | 查看草稿的来源、有效值、修订和人工修改 | 保存草稿、试用、提交评测、审批、发布和迁移是不同动作；冻结版本只读；提交前查看差异与受影响事项 |
| 任务与主动服务（新增设计） | 定义该专家的默认服务义务与触达规则 | 按单个专家配置并随 `AgentVersion` 冻结；明确适用主体与服务周期、触发条件、采用方式、时段与时区、渠道、冷却期与频次、去重、停止和退订、允许调整范围和完成证据；触达先形成候选，再分别检查采用与执行许可 |

## 主动服务配置要求（规划，未实现）

每条蓝图描述一个明确的服务目标。配置时先说明目标和适用对象，再选择事件或条件；条件只能使用当前专家版本提供的字段、事件和算子。分别定义无蓝图、空条件、未命中和条件未知时的结果，不能把空条件默认为适用于所有人。

触达蓝图还要明确有效渠道、用户许可、可联系时段、时区、频次与冷却、跨事项去重、人工接管后的停止方式、退订处理、允许的改期范围和完成证据。只能选择已接入且获授权的渠道；没有可用渠道时等待或转人工，不能静默换渠道。用户画像、偏好或 Agent 判断都不能单独构成联系许可。缺少身份、许可、有效渠道或完成判据时，事项应阻断或等待，不得由 Agent 补造。

初始化预览使用固定的虚构主体、服务周期、事件和时钟。静态规则摘要只解释条件逻辑，不表示任何用户已命中；预览命中也不创建真实事项、不启动调度或发送消息。Agent 只能在蓝图批准的范围内调整单个事项；修改默认规则、联系许可、次数或承诺须走专家版本、评测和审批。

## 运行与治理模块

| 工作面 | 功能定义 | 操作要求 |
|---|---|---|
| 服务事项 | 管理具体用户和服务周期下的义务、候选、等待原因与结果 | 区分事项候选和已采用事项；改期只改实例；取消是请求，须等停止确认；未知结果先核验，不能随意勾选完成 |
| 客服应用（网站客服窗、联系页、会话收件箱） | 管理访客入口、会话接待和一线处理 | 入口绑定已批准的指定版本；渠道设置与专家蓝图分开；会话接管不等于义务已完成或取消 |
| 主体上下文（规划） | 查看当前服务对象的授权事实、来源、新鲜度和冲突 | 配置只管理字段定义和用途；用户值不写入专家配置；记忆不授予联系许可 |
| 试用台与运行记录 | 检查输入、版本、实际披露的能力、尝试和结果 | 模拟结果与真实运行分开；记录所用版本和证据；权限阻断、取消待确认和未知状态不可隐藏 |
| 案例、回放与改进提案 | 审定业务真值，比较版本表现并提出配置改动 | 一线反馈只是提名，不是真值；硬规则和权限不能由模型评分或优化作业静默修改；候选通过固定评测并经人工审批后才能发布 |
| 版本与发布 | 比较基准版和候选版，审阅发布及在途影响 | 先看蓝图差异和受影响事项；发布与迁移分别授权；不自动重建服务周期，不因回滚重置频次或恢复已撤销许可 |
| 连接与部署 | 管理模型、工具、渠道连接和运行环境 | 凭据由受控服务保管；变更连接或合同版本后重新检查相关专家版本；部署状态不能代替业务权限或发布审批 |

## 当前可用范围

第二轮后台是本地交互原型。十个专家配置模块、知识资料、物料库、试用、运行、案例、候选、版本和部署页面不能证明后端持久化、真实权限、真实触达或线上发布已实现。“任务与主动服务”“服务事项”、Harness 渐进披露、真实调度和在途迁移均为规划，按各自 Gate 验收后才能作为生产操作流程使用。

详细设计与状态见[配置后台体验优化 §12](CONFIGURATION-UX-OPTIMIZATION.md#12-专家任务与-harness-的后台增量设计)、[工作台 IA §8](S2-IA-NAV.md#8-taskharness-后台增量落点)、[后台启动方案 §8](S2-CONSOLE-KICKOFF.md#8-taskharness-后台增量工作包)、[Task 体系设计](TASK-SYSTEM-DESIGN.md)和[验证路线](ROADMAP.md)。
