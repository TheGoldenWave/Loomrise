# Loomrise 终态侧边栏菜单设计规范 v0.1

日期：2026-10-26。状态：**设计规范候选稿**——菜单形态、名称、作用域、出现条件与分期在此定稿；**对象权威仍是 [工作台 IA](S2-IA-NAV.md) 与 [架构与对象权威](ARCHITECTURE.md)**，本文件不新增领域对象、不改六层合同、不改 ROADMAP Gate。

## 0. 结论先行

1. **两个平面，不共享菜单。** 未选专家时是**工作区平面**（3 项）；选中专家后是**专家平面**（8 项 + 1 个底部固定项）。参考项目把两套菜单做成同一根侧栏的两态，我们沿用这个**形态**，但拒绝它在两级复用同名项的做法（§3.3）。
2. **专家平面扁平，不分组。** 8 项以内不设分组头——分组头的存在前提是「组内 ≥2 项且组间不同类」，8 项拆 3 组会让每组只剩 2–3 项，组头本身成为噪声（线框复盘 E-2 已记过同一条）。
3. **一级＝对象域仍然成立，只是六域被分到两个平面。** [IA](S2-IA-NAV.md) 的 6 域没有消失：专家域下沉为专家平面的 8 个工作面，变更／知识／设置上浮为工作区平面。**17 页／23 面继续作为对象覆盖对账口径，不再作为菜单形态。**
4. **菜单只回答"去哪"，不回答"做了什么"。** 依据、试一试、待处理队列、版本对比、搜索、审批动作都不占菜单位（§6），一律走右侧面板、顶栏与页内抽屉。
5. **一个对象只有一个可见名、一个入口。** 禁止参考项目的"Knowledge Base 在两级各有一个"（§3.3）。

**终态菜单树**（`←` 标出现条件 / 版本）：

```text
〔未选专家〕工作区平面
  搜索与新建 ⌘K（S2-b）
  专家列表            ●   S2-a
  变更                     S3（S2-a 期间内嵌在「上线」页，不占菜单）
  平台设置                 S2-a（工具与连接、模型与语音）· S3（成员与权限、发布记录）

〔已选专家〕专家平面
  搜索与新建 ⌘K（S2-b）
  ← 专家列表
  [专家名称 ▾]  [草稿 / 线上运行中]      ← 专家切换器 + 状态
  首页                S2-a
  知识库          ●   S2-a
  红线            ●   S2-a
  业务办理            S2-a（本地模拟）· S2-c（真实办理）
  对话流程        ●   S2-a（清单与判定规则）· S2-b（画布完整）
  任务与主动服务      S2-c
  测试            ●   S2-a
  上线            ●   S2-a（本地）· S2-b（沙盒渠道）· S3（首云）
  ─────────────
  专家设置            S2-a
```

`●` = 可有角标，数据来自唯一的 `pendingItems()`（§7）。

## 2. 与 ElevenLabs 的四类裁决

### 2.1 规划中（含版本与落点）

| ElevenLabs 项 | 我们的落点 | 版本 | 差异 |
|---|---|---|---|
| `Agents`（agent 列表） | 工作区平面·**专家列表** | S2-a | 我们用业务岗位名作列表项，不用"专家/专员"作集合名（IA §4.5 配套规则） |
| `Home` / `Spotlight` | 专家平面·**首页** | S2-a | 它首页是入口宫格 + 部署清单；我们首页是"现在先做一件 + 四列汇总 + 最近改动"，空态即三步冷启动 |
| `Procedures` + `Workflow` | 专家平面·**对话流程** | S2-a 清单与判定规则 / S2-b 画布 | **两对象合成一页**：单元清单、判定规则、编排图是同一份草稿的三个投影（ROUTE-GRAPH v1.0） |
| `Guardrails` | 专家平面·**红线** | S2-a | 它四类护栏是自然语言 + 轻量模型（概率、Alpha、不校验工具参数）；我们是模型外确定性裁决，且平台底线只读 |
| `Tools`（agent 级） | 专家平面·**业务办理** | S2-a 本地模拟 / S2-c 真实 | 它管"调什么工具"；我们管"能替客户办成什么事"，含办成标志与三态结果 |
| `Knowledge Base`（agent 级） | 专家平面·**知识库** | S2-a 本地解析 / S2-b 完整摄入 | 它以"资料（Source）"为行、检索可关；我们以问答为行、引用必须可溯源 |
| `Tests` | 专家平面·**测试** | S2-a 测试题与变差决策 / S2-b 分桶 / S2-c 盲测 Gate | 它三类测试判据全自然语言；我们有确定性断言 + 人评分层 |
| `Version Control` + `Channels` | 专家平面·**上线** | S2-a 本地 / S2-b 沙盒渠道 / S3 首云 | 它合并靠分支 + 可选提案，测试不通过也能合；我们上线必须人批准 |
| `Settings`（agent 级） | 专家平面·**专家设置** | S2-a | 它三个子页全是运行参数；我们还含人设与接待、收集信息，**且改配置走草稿** |
| `Proposals`（Version Control 内页签） | 工作区平面·**变更** | S3（S2-a 内嵌在上线页） | 它是可选流程 + 管理员可绕过；我们是强制门禁（评测→审批→发布） |
| `Analysis`（判据配置） | 测试页内·**判据 / 评价标准** tab | S2-b | 它独立成页（判据即为配置对象）；我们判据随案例集版本冻结，不单开页 |
| `Issues`（工单板） | 顶栏**待处理 N** + 待处理队列 | S2-a（队列）/ S2-b（提名器） | 它四状态带 assignee 认领；我们只分 block / suggest，不做派单 |
| `Dashboards` | 首页下钻 + 依据面板 | S2-a 指标 / S2-b 成本与配额 | **不设独立"数据看板"页**（与 IA 原设计不同，见 §13-3） |
| `Users` | 无页；按主体作用域在会话／事项内呈现 | S2-b | 它把用户当实体列表；我们的主体是查询键不是 CRM（记忆体系 §10.1） |
| `Integrations` | 平台设置·**工具与连接** | S2-b | 它独立成页并列 400+ 集成；我们收进平台注册表，避免单页一级 |
| `Voices` | 平台设置·**模型与语音** | S2-b | 它做音色市场 + 多音色；我们固定选型、只切换档位 |
| `Search & create`（⌘K） | 全局**搜索与新建** | S2-b | 见 §8：只做"打开 / 新建"，不做"一句话改配置" |
| `Channels` | 上线页·**接在哪** | S3 | 它渠道一半是别人的客服台（Zendesk / Genesys）；我们不以渠道寄生为形态 |
| `Architect`（AI 助手） | 页内**可选协助**，不占菜单 | S2-b | 它独立成一级且带 Alpha；我们只做"给建议、出候选"，改配置仍要有依据与审批 |
| `Invite team members` | 平台设置·**成员与权限** | S3 | 它把邀请卡片放侧栏底部做增长；我们只做权限，不做增长位 |

### 2.2 不需要做

| 项 | 为什么不做 |
|---|---|
| `Upgrade` / 套餐与计费 | 不是自助订阅产品。企业交付与私有化部署不走侧栏 |
| `Developers`（API key / webhook 页） | 接入面在仓库文档与 CLI（AGI-01…11），不做面向开发者的控制台 |
| `Phone Numbers` | 不自建号码资源；若未来接运营商，是渠道适配器的事，不是工作台菜单 |
| `WhatsApp` | 同上，S4 渠道评估前不预留菜单位 |
| `Outbound`（CSV 批量外呼） | 我们的主动服务是"按主体与周期的事项"，不是名单批量拨号；不承诺外呼产品 |
| `Voices` 独立页 | 选型已定（阿里云端到端），不提供音色市场 |
| `⋯ More`（侧栏内 agent 溢出） | 专家列表就是切换入口；侧栏不再内嵌第二套列表 |
| 分支选择器 / `Create new branch` | 我们没有分支模型：坐标是**版本**（草稿 / 线上版），线上版只读（§3.3） |
| 底部营销位（邀请卡 / 升级按钮） | 侧栏只放导航与账号，不放增长位 |
| `Alpha` 标签进菜单 | 能力状态写在页面内说明与版本钉里；菜单文字不稳定会训练用户忽略标签 |

### 2.3 思路不一致、需要坚持的项

| # | 它的做法 | 我们的做法 | 坚持的理由 |
|---|---|---|---|
| 1 | 同名项在两级各有一个（Knowledge Base / Tools / Conversations / Tests / Users / Settings / Channels / Outbound 八组词根） | **一个对象一个入口**；跨专家聚合用"范围切换"，不用第二菜单项 | 同一对象两个入口必然出现"两个入口权限不一致"（IA §1.2 不能照搬 3）。用户也不该靠位置记忆区分"库"与"这个 agent 的接入" |
| 2 | 4 个分组头承载 17–18 项 | 专家平面 ≤8 项**不分组**；分组阈值见 §3.2 | 分组只解决"项多到扫不动"；组内 2–3 项时组头是纯噪声（线框复盘 E-2） |
| 3 | `Tests` 放 Monitor 组（看结果，不在发布主路径上） | 测试在专家平面主序列里，且是上线的**前置** | 它的分组是"评测不进合并门禁"的结构性原因（总纲 §8.2-9）。我们反过来：评测必须在门禁内 |
| 4 | 分支即工作副本：改一处即时生效，`Publish` 才推生产 | 草稿自动保存 → 申请上线 → 人批准；线上版只读 | 分支模型下"半成品对同分支所有人都是生效的"，无法满足"改到一半不污染线上"（总纲 §8.2-8） |
| 5 | 模型 / 话轮 / 语音参数在配置页直接下拉切换 | 模型档走草稿，覆盖档随版本冻结，平台只设默认档 | 模型直接影响成本与回答质量，绕过审批改它等于绕过审批改成本（IA §4.2 ⑥ 硬约束） |
| 6 | 护栏 = 自然语言 + 轻量模型，违规动作是 `End conversation` / `Retry` | 红线 = 模型外确定性裁决 + 四类裁决 + 冲突偏序 | 概率性判定 + 不校验工具参数，不能作为合规底线（总纲 §8.2-1） |
| 7 | ⌘K 面板内直接给"改提示词 / 改语气 / 写流程"的 AI 动作 | 搜索与新建只到"打开 / 新建"；AI 只出**候选**，落草稿后仍走提交 | 同一能力多入口语义不一致是它自认的病（总纲 §8.2-15）。我们不复制这个入口 |
| 8 | 两级 `Settings` 同名 | `专家设置` / `平台设置` 两个名，且**不会同屏出现** | 一个对象一个用户可见名（IA 原则 6）。同名双设让"我在改哪一层"变成隐式状态 |

### 2.4 我们特有（它没有对应项，且必须留在菜单语义里）

| # | 我们的东西 | 在侧栏怎么体现 |
|---|---|---|
| 1 | **待处理队列单一数据源** | 唯一的 `pendingItems()` 驱动：导航角标、顶栏"待处理 N"、首页"现在先做"、列表"要处理的事"、上线页"能上线吗"（CG-02） |
| 2 | **依据随处可查** | 右侧面板固定入口，七个工作面共用；菜单不设"依据"页 |
| 3 | **红线在流程图上可见 + 平台底线只读** | 红线是独立一级项；平台底线在页内只读标 `🔒`，不进设置 |
| 4 | **业务办理三态结果** | 办成 / 失败 / 结果不明 分列统计，结果不明单独计（不混进成功） |
| 5 | **上线须人批准；发测试环境不需** | 上线页两个动作语义分离；菜单只有一项 |
| 6 | **测试快照与签名** | 上线前必须真跑已人工复核的测试题；改稿后"答案错了"持续阻断 |
| 7 | **资料授权按批一次声明** | 知识库页"＋放资料"批次授权，**不默认勾选**；菜单不体现（属页内动作） |
| 8 | **撤销与回退** | 批量操作 10 秒撤销；上线后可回到上一线上版；撤销记录在专家设置 |
| 9 | **段落协议 locked / mutable** | 红线与知识引用为 `locked`，话术与示例为 `mutable`；菜单不分组，但**红线独立成项**就是这个协议在导航层的投影 |
| 10 | **案例集三池 + 盲测** | 测试页三个 tab（待审 / 基准 / 盲测），不进菜单 |

## 3. 结构模型

### 3.1 两级平面：为什么必须是两层

| 判据 | 工作区平面 | 专家平面 |
|---|---|---|
| 没有选中对象时能否打开 | 能 | **不能** |
| 回答的问题 | 我手上有几个专家、有什么等我批、平台连了什么 | 这一个专家做得对不对、怎么改、能不能上 |
| 数据作用域 | 跨专家 / 平台 | 单个专家（及其版本） |
| 项数 | 3 | 8 + 1 |

**为什么不做成一层**：专家配置一旦全部上浮，"这是谁的配置"就变成页面内的隐式筛选器，而八处页面各写一套筛选。**专家是坐标，不是筛选**——与参考项目把 agent / 分支放顶部是同一个判断。

**为什么不做成三层**（工作区 → 专家 → 版本）：版本不占层。版本选择在**页头**（`草稿 · 已自动保存` / `历史版本 r12 只读`），因为"我在改哪一版"必须常驻可见，而不是靠再进一层。IA 的"版本详情三 tab"在此被**下沉**：人设进专家设置，流程进对话流程，边界进红线与业务办理（§13-6）。

### 3.2 为什么专家平面不分组

定量规则（写死，避免下次重开讨论）：

| 主组项数 | 处置 | 依据 |
|---|---|---|
| ≤ 9 | **不分组**，单一序列 | 一屏可扫；分组头会占掉 3 行且每组只剩 2 项 |
| 10 – 14 | 分 2 组，每组 ≥ 3 项 | 分组头开始有信息量 |
| ≥ 15 | 分 3 组，每组 ≥ 4 项 | 参考项目在此区间用了 4 组 × 4–9 项 |

**顺序即搭建顺序**，不按字母、不按对象类型：`首页 → 知识库 → 红线 → 业务办理 → 对话流程 →（任务与主动服务）→ 测试 → 上线`。理由是新人第一次进来就是照这个顺序做（先有资料、再定不许做的事、再接能办的事、再串流程、测完上线）。这条与"一级＝对象域"不冲突：**分类看归属，排序看流程**。

> **触发重议的条件**：主组涨到 10 项，或出现"两个项 90% 时间要一起看"。届时按上表分组，不新开一层。

### 3.3 拒绝参考项目的三处结构

| 它的结构 | 我们为什么不照抄 | 我们怎么做 |
|---|---|---|
| 同名双入口 | 必然出现两处权限不一致；用户靠位置记忆区分"库"与"接入" | 一个入口 + 范围切换；跨专家聚合只在工作区平面出现，且是**另一个对象**（如"发布记录"不是"版本"） |
| 分支作为常驻坐标 | 分支内改动即时生效，与"保存 ≠ 提交"直接冲突 | 坐标为版本；页头常驻"草稿 / 线上版"，历史版本只读 |
| 导航里放账号与增长动作 | 侧栏同时承担对象导航与增长，形态混杂 | 底部固定区只放**设置**与账号；不做邀请卡、不做升级按钮 |

## 4. 终态菜单总表

### 4.1 工作区平面（未选专家）

| # | 条目 | 路由键 | 作用域 | 角标 | 优先级 | 版本 | 一句话职责 |
|---|---|---|---|---|---|---|---|
| 1 | 搜索与新建 | `⌘K` | 全局 | — | P1 | S2-b | 找专家、找页面、新建专家 |
| 2 | 专家列表 | `experts` | 跨专家 | ● | P0 | S2-a | 我手上有几个专家、各卡在哪 |
| 3 | 变更 | `changes` | 跨专家 | ● | P1 | S3 | 有什么等我批、发了什么、退过什么 |
| 4 | 平台设置 | `settings` | 平台 | — | P1 | S2-a 部分 / S3 完整 | 平台连了什么、用什么模型 |

**变更的三个 tab**（S3，不占菜单）：待我审批 · 发布记录 · 审批档位。S2-a 期间这三块内嵌在**上线**页（单专家视角），不出现工作区级入口。

### 4.2 专家平面（已选专家）

| # | 条目 | 路由键 | 角标来源 | 优先级 | 版本 | 一句话职责 |
|---|---|---|---|---|---|---|
| 1 | 首页 | `overview` | 无（汇总其它项） | P0 | S2-a | 现在先做哪一件 |
| 2 | 知识库 | `knowledge` | 待核对 / 不一致 | P0 | S2-a | 它能答什么、依据哪份资料 |
| 3 | 红线 | `redlines` | 未上线红线 / 冲突 | P0 | S2-a | 绝不许做什么 |
| 4 | 业务办理 | `business` | 未接通 / 结果不明 | P0 | S2-a（模拟） | 能替客户办成什么 |
| 5 | 对话流程 | `flow` | 校验错误 / 没有出口 | P0 | S2-a / S2-b 画布 | 一件事怎么被分流、谁来说 |
| 6 | 任务与主动服务 | `tasks` | 待采用候选 | P1 | S2-c | 什么时候主动找客户、办到哪一步 |
| 7 | 测试 | `test` | 变差 / 待复核 | P0 | S2-a | 改完退步了没有 |
| 8 | 上线 | `release` | 能上线吗 / 待批准 | P0 | S2-a / S2-b / S3 | 发到哪、谁批、怎么退 |
| — | 专家设置 | `settings/agent` | — | P0 | S2-a | 人设与接待、收集信息、导出、停用 |

`▾` 专家切换器 + 状态 chip（`草稿` / `线上运行中` / `有未上线修改`）在导航之上、不占菜单位。

### 4.3 两平面的关系

```text
工作区平面 ──选中专家──> 专家平面 ──←专家列表──> 工作区平面
    │                        │
    └─ 平台设置（对象：平台）  └─ 专家设置（对象：这个专家）
```

- **同一屏只出现一个平面**，不做"上层菜单常驻 + 下层展开"的两栏嵌套。
- **平台设置与专家设置不同名、不同屏**，各自只出现一次。
- 返回位置：`← 专家列表` 回到列表并保留原来的筛选与滚动位置（离开列表再回来，筛选不丢——IA §5.3-3）。

## 5. 逐项定义

### 5.1 首页 `overview`

| 项 | 规定 |
|---|---|
| 管什么 | 这个专家**此刻**的状态与唯一一件该先做的事 |
| 结构 | 空态：三步冷启动（放资料 / 核对 / 试一试）；有内容：`现在先做` 一件事 → 四列汇总（知识库 / 红线 / 业务办理 / 对话流程，各一行数字 + 一行要处理的事）→ 最近改动（每条带`依据`） |
| 不含 | 图表聚合、入口宫格、部署检查清单 |
| 空态禁令 | 不渲染空表格；没有资料时首页就是三步引导，不跳向导页 |
| 与它的差别 | 不做 `Spotlight` 那种"三条入口 + View Dashboards"：入口宫格是把导航重复一遍 |

### 5.2 知识库 `knowledge`

| 项 | 规定 |
|---|---|
| 管什么 | **这个专家能引用的事实**：问答、关键信息、标准话术 |
| 三个 tab | 问答（默认）· 关键信息 · 标准话术；`按资料看` 作为来源视图挂在"＋放资料"旁 |
| 状态词 | 已审 / 待审 / 不一致 / 缺出处（写全词，不缩写） |
| 不含 | 物料（文件资产）→ 平台设置·物料库；模型 → 平台设置·模型与语音 |
| 归属说明 | 入口下沉到专家级，**归属不变**：知识仍是平台资产，专家只持有引用；跨专家共享的内容不在此复制（§13-2） |

### 5.3 红线 `redlines`

| 项 | 规定 |
|---|---|
| 管什么 | 绝不能做什么：禁止 / 必须 / 停止 / 去重 四类，按作用域分组 |
| 两类并存 | `我的红线`（可编辑，走草稿）与 `平台底线`（只读，标 `🔒`，不可覆盖、不可放宽） |
| 不含 | 触达频控（属专家设置的节奏参数，不是"绝不能做"） |
| 为什么独立成项 | 它是段落协议里唯一整体 `locked` 的业务面；与"效果面"（知识库 / 对话流程）分开，审批者才不会用同一副眼光看两类风险 |

### 5.4 业务办理 `business`

| 项 | 规定 |
|---|---|
| 管什么 | 能替客户办成什么事：入参、需客户确认、办成标志、三态结果 |
| 三态 | 办成 / 失败 / **结果不明**（单独统计，不并入成功） |
| 不含 | 工具目录与凭据（平台设置·工具与连接）；MCP 连接（同上） |
| 页面动作 | `试办一次` 只记本地模拟；真实办理与外部结果 ID 归 S2-c |

### 5.5 对话流程 `flow`

| 项 | 规定 |
|---|---|
| 管什么 | 一件事怎么被分流、每个分支谁来说、哪些条件不许越过 |
| 两个视图 | 流程图 / 列表（同一份草稿的两个投影，共用选中态） |
| 不含 | 红线规则本体（只读引用，图上可见）；人设（专家设置） |
| 与它的差别 | 它 `Procedures` 与 `Workflow` 是两个独立页签；我们合成一页两视图，因为**节点即能力单元**，拆开会变成同一对象两份数据 |

### 5.6 任务与主动服务 `tasks`（S2-c）

| 项 | 规定 |
|---|---|
| 管什么 | 什么时候主动找客户、按什么周期、办到什么算完（规则，随版本冻结） |
| 不含 | 事项实例。**事项不占侧栏**：它由首页待办、依据面板与客服应用收件箱承载（原则 4：必须先选一个事项才能看） |
| 出现条件 | 未开启主动服务的专家，该项**显示为"未开启"+ 一句说明**，不隐藏（隐藏会让用户以为产品没有这个能力） |

### 5.7 测试 `test`

| 项 | 规定 |
|---|---|
| 管什么 | 改完退步了没有 |
| 四个 tab | 测试题 · 回放 · 判据（评价标准，S2-b）· 人工评分（S2-b） |
| 快照语义 | 上线必须真跑已人工复核的测试题；改稿后"答案错了"持续阻断，直到当前版本回放通过 |
| 不含 | 运行流水（在首页下钻与依据面板）；盲测池（列表内 tab，不占菜单） |

### 5.8 上线 `release`

| 项 | 规定 |
|---|---|
| 管什么 | 发到哪、谁批、怎么退 |
| 两个动作 | `发到测试环境`（不需批准）· `申请上线`（需人批准）；语义不可混用 |
| 三块内容 | 能上线吗（取 `pendingItems` 的 block 项）· 接在哪（渠道与绑定）· 上一版（回退入口） |
| 不含 | 跨专家审批流（S3 上浮到工作区平面·变更） |
| 回退 | 可回到上一线上版；回退不恢复已撤回的授权 |

### 5.9 专家设置 `settings/agent`

| 项 | 规定 |
|---|---|
| 管什么 | 这个专家自己的低频设置：人设与接待（身份、服务目标、回答范围、表达方式、欢迎语、资料不足时）· 收集信息与记录要求 · 批量操作撤销记录 · 导出交付包 · 停用 / 删除 |
| 不含 | 模型连接、物料、部署（平台设置）；模型覆盖档（走草稿，在页头） |
| 位置 | 导航底部、分隔线以下，视觉上不属于主序列 |

### 5.10 平台设置 `settings`（工作区平面）

| 项 | 规定 |
|---|---|
| 分区 | 工具与连接 · 模型与语音 · 物料库 · 成员与权限（S3）· 系统诊断与部署（S3） |
| 不含 | 单个专家的任何配置（要改去专家平面） |
| 硬约束 | 只设平台默认档，不改任何版本的覆盖档 |

## 6. 不进侧栏的清单（十项）

| 载体 | 内容 | 为什么不做成菜单 |
|---|---|---|
| 右侧「试一试」 | 任何页面打开，一轮答复 + 一行依据 + 对 / 答错了 | 它是动作不是目的地；三处入口（页 / 条 / 顶栏）都进同一面板 |
| 右侧「依据」 | 从哪来、哪一版、谁改的、影响谁、凭什么 | 与内容同屏才有意义，独立成页会脱离上下文 |
| 顶栏「待处理 N」 | 唯一队列入口，按页面分组 | 导航红点只是它的投影，不另设页面 |
| 专家切换器 | 顶部 `名称 ▾` + 状态 chip | 它是坐标不是页面 |
| 版本选择 | 页头 `草稿 · 已自动保存` / `历史版本 r12 只读` | 与它对照：版本不占层（§3.1） |
| 版本对比 | 行内抽屉，必须有可引用 URL | 一次性动作 |
| 新建专家 | 列表页按钮 + 向导路由（不占菜单） | 单页不设域 |
| 依据 / 技术详情折叠区 | 幂等键、超时、字段路径 | 工程字段不进运营视图（线框 E-9） |
| 账号与工作区 | 头像菜单 | 非对象导航 |
| 开发者模式 | 全局开关，默认关 | 它是视图密度开关，不是目的地 |

## 7. 角标与待处理队列

| 规则 | 规定 |
|---|---|
| 唯一数据源 | `pendingItems(agent)` 返回 `{ id, level: 'block' \| 'suggest', page, target, text, fix }`；导航、顶栏、首页、列表、上线页**全部取这一处**，禁止各算各的（CG-02） |
| 角标含义 | 数量 = 该项的 `block + suggest` 条数；`block` 优先 |
| 上限 | 显示 1–9 与 `9+`；超过 9 不显示具体数（避免变成无意义的百位数字） |
| 颜色 | 只有一种颜色表示"有待处理"；**不区分红/黄**——优先级由队列里的 `level` 表达，不在导航上做第二套语义 |
| 禁止 | 角标不用于营销、不用于"新功能提示"、不在没有待处理的项上出现 |
| 计数一致性 | 同一草稿下五处计数必须一致（单测断言，CG-02 验收） |
| 与它的差别 | 它只给 `Workflow` 一项加了 `3`，且语义未公开；我们要求**角标必须能点进队列并定位到具体一条** |

## 8. 搜索与新建（⌘K）

| 项 | 规定 |
|---|---|
| 何时做 | **S2-b**。S2-a 用列表页 + 顶部"新建"即可 |
| 三段结构 | ① 输入行（`搜索专家、页面…`）② 快捷动作（`新建专家` / `全部专家`）③ 结果：专家、页面、知识条目（S3 起含事项） |
| 动作边界 | 只到**打开 / 新建 / 跳到某条**。**不做**"一句话改配置"（它面板里的 `Rewrite the system prompt` 一类）——改配置必须有依据、落草稿、走提交 |
| AI 的位置 | 若将来接"协助"，形态是**给出候选改动**（可在 diff 里看），不是直接改 |
| 不替代导航 | ⌘K 是加速器；所有目的地必须在侧栏或页内可达，不允许"只能在命令面板里找到" |
| 键盘 | `⌘K` / `Ctrl+K` 打开，`Esc` 关闭，`↑↓` 选择，`⏎` 进入 |

## 9. 导航行为规范

| 场景 | 规定 |
|---|---|
| 未选专家 | 工作区平面；点专家列表任一行进入专家平面 |
| 已选专家但页面属于工作区 | 工作区平面，且专家上下文**保留**（从平台设置返回时回到原专家原页） |
| 窄屏（< 900px） | 侧栏收为抽屉，打开时焦点进抽屉、`Esc` 关闭后焦点回按钮；当前项在抽屉内高亮 |
| 深链 | 每条路由可直接打开；无专家 id 的专家级路由 → 重定向到专家列表并提示"先选一个专家"，**不渲染空表** |
| 高亮 | 详情、抽屉、tab 全部用**路由前缀**回指一级项（`/experts/:id/test/*` → `test`），不手写第二份映射 |
| 记忆 | 不记忆"上次停在哪一页"——恢复上次位置会让"我明明刚上线"变成隐式状态。只记忆列表筛选与滚动 |
| 键盘顺序 | 侧栏在 DOM 顺序上先于主内容；当前项 `aria-current="page"`；角标文本为"3 件待处理" |
| 折叠 | 侧栏整体可折叠（用户级偏好），**分组头不可折叠**（≤9 项无需折叠） |

## 11. 分期：每一期侧栏长什么样

### S2-a · 单专家本地闭环（已部分实现）

```text
〔未选〕专家列表 · 平台设置（工具与连接、模型与语音）
〔已选〕首页 · 知识库● · 红线● · 业务办理 · 对话流程● · 测试● · 上线● ｜ 专家设置
```

- 变更相关（待我审批 / 发布记录 / 审批档位）**内嵌在上线页**，不占菜单。
- 依据 / 试一试 / 待处理在顶栏与右面板。
- 与原型差异：首轮 `设置` 含物料库、模型连接、部署；[导航跟进](CONFIG-UI-ROUND1-REPORT.md#6-两平面导航跟进2026-10-26)已将当前专家配置改名为 `专家设置`，三个资源移到工作区直达。**终态的"平台设置"聚合仍未实施**（§13-7），不与当前资源入口视为同一完成范围。

### S2-b · 摄入完整 + 画布 + 判据

新增：搜索与新建（⌘K）、测试页 `判据` / `人工评分` tab、对话流程画布、知识库完整摄入。**菜单项数不变**（新能力都落在已有项内）。

### S2-c · 主动服务 + 真实办理 + 发布 Gate

新增一项：**任务与主动服务**（主组 8 项）。业务办理接真实工具与外部结果 ID；上线接发布 Gate 与回退留痕。

### S3 · 首云、身份、跨专家

```text
〔未选〕专家列表● · 变更● · 平台设置（+ 成员与权限、系统诊断）
〔已选〕首页 · 知识库 · 红线 · 业务办理 · 对话流程 · 任务与主动服务 · 测试 · 上线 ｜ 专家设置
```

新增：工作区平面**变更**（三个 tab）、平台设置内**成员与权限 / 系统诊断**。侧栏首次出现两个平面并存的情形——这是 S3 的主要导航风险点，验收见 §12-11。

### S4 · 多云、多租户

新增：工作区切换器（最底部，与它同形）。**不新增菜单项**；若"运行总览"确有跨专家经营视角需求，届时按 §3.2 重新评估（当前不做）。

## 12. 验收清单

评审时逐条判定 yes / no，不允许"基本符合"。

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 未选专家时一级项 ≤ 4；已选专家时一级项 ≤ 9 | 数侧栏 DOM |
| 2 | 全站没有一个对象出现在两个菜单项里 | 列菜单项 × 承载对象，逐格查重 |
| 3 | 专家平面无分组头 | 看渲染 |
| 4 | 同一草稿下，侧栏角标 / 顶栏计数 / 首页"现在先做" / 列表"要处理的事" / 上线页 block 数**五处一致** | 单测断言（CG-02） |
| 5 | 每个角标都能点进队列并定位到具体一条 | 逐项点 |
| 6 | 侧栏任一项都能在不打开命令面板的前提下到达 | 断网 + 不用 ⌘K 走一遍 |
| 7 | 无专家 id 的专家级深链 → 专家列表 + 提示，**不渲染空表** | 直接访问 URL |
| 8 | 详情 / tab / 抽屉均高亮回指其一级项 | 逐个 tab 切换看高亮 |
| 9 | 离开列表再返回，筛选与滚动位置不丢 | 手工 |
| 10 | 窄屏抽屉打开后焦点进入、`Esc` 关闭后焦点回按钮 | 键盘走查 |
| 11 | S3 起两平面并存时，平台设置的任何改动都不写专家草稿 | 改一处平台设置，查草稿 revision 未变 |
| 12 | 界面无 §10 禁用词（含标题、按钮、空态、aria-label） | `npm run check:terms` 双视窗 |
