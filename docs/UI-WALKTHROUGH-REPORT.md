# 前端 UI 走查报告 v0.4

状态：**本地原型走查、密度重定与视觉细节深化均已验证；真实 S2 后台及真实渠道仍未实现**。2026-10-13（v0.3）/ 2026-10-14（v0.4）。

范围：`loomrise/web.html` 的 S1 网页入口、`prototypes/s2-console/index.html` 的原型索引，以及 `prototypes/s2-console/screens/` 下全部 15 个 S2 页面。样例均为原创虚构业务资料；本报告不包含私有资料、真实用户数据或截图。

## 结论

- **已修复**：规划能力占据菜单或形成禁用按钮、运行记录证据错位、跨专家数据串用、拒绝后派生草稿丢改动、试用刷新后卡在执行中，以及 S1 确认失败后无法重试等问题。后续复核又处理了新岗位无效入口、跨版本待确认请求、未生效的模型选择和操作记录跨岗位显示。
- **已验证**：15 个 S2 页面在 Chrome 1440px 与 390px 视窗逐页加载；两种宽度下均未发现页面横向溢出、空白页、失效链接或脚本异常。S2 本地 DOM／交互回归 **860 项断言通过**。S1 页面与原型索引另做窄屏加载及针对性交互验证。
- **交付边界**：S2 仍是浏览器本地状态原型。它没有真实模型、语音、审批、发布或外部业务写入服务。S1 的真实模型、网页音频和浏览器到后端完整链路不在本轮验证范围内。

## 重点问题与证据

| 优先级 | 原问题 | 影响 | 修复及验证 |
|---|---|---|---|
| P1 | 侧栏、试用、边界、案例、审批与发布露出不可用入口 | 用户会把规划能力误认为可操作能力 | 收起尚未接入的导航、tab 和操作；两种视窗逐页检查后，默认页面未发现可见的规划禁用按钮。状态依赖的只读或执行中控件仍按实际状态处理。 |
| P1 | 运行记录“查看证据”指向当前试用 | 点击历史记录可能看到另一条请求，造成证据误认 | 链接携带请求 ID，详情按 ID 与专家匹配；浏览器从列表点击后核对 URL 和证据请求 ID。 |
| P1 | 运行、标注、人评与待办使用全局最新数据 | 切换专家后可能出现别的岗位的内容 | 按专家隔离可见记录和操作来源；DOM 回归覆盖新专家隔离。 |
| P1 | 试用在“后台执行”阶段刷新后不再推进 | 用户被锁在不可继续的状态 | 页面恢复时继续本地状态转换；浏览器在发送后立即刷新，仍出现确认卡片。 |
| P1 | S1 确认接口失败后两个按钮保持禁用 | 一次网络错误后无法重试 | 失败时恢复确认／拒绝操作并给出重试提示；模拟 500 响应验证。 |
| P2 | 拒绝后新草稿从稳定版复制 | 被拒版本中的修改丢失 | 从被拒版本派生并保留目标；本地回归核对父版本和目标内容。 |
| P2 | S1 发送失败清空输入 | 重试需要重新输入 | 失败时恢复原输入；代码与页面交互检查。 |
| P2 | 空状态预先画出不可用表单；S1 不支持识别时显示禁用录音 | 增加“看得到却不能用”的操作噪声 | 空状态改为明确下一步，浏览器能力不足时收起录音。 |

## 排版 Token 重定（v0.3）

原型原先沿用 Apple 展示型排版令牌（`--text-3xl:56px`、`--text-4xl:80px`、`--section-y-desktop:100px`、`--container-max:1024px`、`--leading-body:1.47`），其中 22 个零引用，实际生效的却是另一套 14px／1.55 与 1280px 容器——两套并存，配置后台的密度被展示型尺度压低。

处理：**只保留 Apple 的色彩与系统字体栈**，字号、行高、间距、圆角、控件与表格按数据密集型后台重定，不分档、不加开关。基准 4px 网格（`--space-half`…`--space-8`）、7 级字号阶梯（`--text-micro` 11px … `--text-page` 20px）、三级行高（1.25／1.45／1.6）、桌面控件 32px、卡片内边距 12px、表格单元 8×12px、圆角 6／8／12px。字段标签与输入同行；卡片内常驻说明折进「说明」折叠块；页头描述收起后挂到标题旁 `?` 提示——信息不删除，只是不占首屏。入口页 `index.html` 是落地页不是配置后台，保留展示型排版。

| 指标（1440×900） | 改造前 | 现在 |
|---|---|---|
| 页头高度（人设页） | 114px | 51px |
| 页头高度（列表页） | — | 44px |
| 表格行高（人设页字段表） | 59px | 36px |
| 首屏可见字段（人设页） | 3 / 6 | 6 / 6 |
| 按钮高度 | 44px | 32px |
| 卡片内边距 | 24px | 12px |
| 正文／表头字号 | 14px / 12px | 13px / 12px |

| 指标（390×844） | 改造前 | 现在 |
|---|---|---|
| 页头高度（人设页） | 177px | 100px |
| 按钮高度（触控不降级） | 44px | 44px |

验证：15 页 × 两视窗在 Chrome 逐页加载，横向溢出均为 0，无脚本异常，控制台无报错；`.pagehelp` 提示在 15 页全部就位，折叠说明在 6 个页面生效。`check.cjs` 860 项断言通过。**未验证**：1440px 以外桌面宽度的观感、真实数据量（多于 3 个版本／3 个字段）下的列表密度、屏幕阅读器对折叠说明的朗读顺序、SF 字体缺失时的回退观感。

## 视觉细节深化（v0.4）

在 v0.3 密度重定的基础上做一轮视觉深化，只动 CSS 与两处 app.js 字符串模板，不改任何交互与断言目标。色彩全部由既有 token 派生（`color-mix`），不新增 hex。

| 改动 | 内容 |
|---|---|
| 空态统一 | `[data-od-id$="-empty"]`、`.expert-empty` 与新增 `.empty-note` 统一为暖底 + 虚线边界 + 居中引导；数据看板空态由孤立一句话升级为结构化引导块（app.js 包裹层） |
| 状态 tag 语义色 | 版本状态 pill 增加低饱和语义底色：草稿蓝、已发布绿、已提交黄、已拒绝红（`tag.state-*`，app.js 仅加类名） |
| 卡片微层次 | 卡片加 1px 极轻投影与标题下间距，与浅灰内容区分离更清楚 |
| journey 导航 | 顶栏单字导航补 `title` 提示（建=专家列表、试=试用台…），悬停加底色与圆角 |
| 次级按钮 | 悬停时边框加深，与背景 hover 双重反馈 |
| 入口页分组 | `index.html` 14 个入口按 IA 三域分组（交付与验证 / 验收与证据 / 治理与发布），组标题带副题与分隔线，行悬停高亮；展示型排版保留 |

验证：`check.cjs` 860 项断言通过；app.js 语法检查通过；Playwright + Chrome 实测 16 页 ×（1440×900 / 390×844）共 32 个组合 `scrollWidth == clientWidth`，横向溢出为 0；逐页截图复核空态、状态色、分组排版生效。**未验证**：真实数据量下的视觉密度、屏幕阅读器对 `title` 提示的朗读、其他浏览器。

## 验证方式与限制

1. 使用本地 HTTP 预览原型，Chrome 无头浏览器逐页测量 1440px／390px 页面宽度，采集脚本异常、禁用操作和空链接；初检与修复后各完成一轮。`index.html` 的 14 条入口另逐条检查 HTTP 可达性。
2. 运行 `prototypes/s2-console/check.cjs`：15 页、860 项 DOM／交互断言通过。另以浏览器走通“文字试用 → 确认 → 运行记录 → 对应证据”，并验证发送后刷新恢复；v0.2 新增新岗位创建与跨版本待确认请求的 Chrome 窄屏操作验证；S1 用模拟接口验证确认失败重试。
3. JavaScript 语法检查与 `impeccable detect` 已执行。检测器提示 S1 运行信息标签在浅色背景下的对比度略低，已调深；此项尚未经过独立无障碍工具复测。
4. **未验证**：S2 真正的审批／发布权限与持久化、真实模型回复质量、真实语音收发、S1 浏览器与后端完整流式运行、屏幕阅读器实机体验、其他浏览器和更多视窗尺寸。浏览器检查使用的是桌面 Chrome 的视窗模拟，不等于实体手机测试。

后续实现规划能力时，应让入口随真实服务、权限和证据门禁一起开放，并以同一条业务结果 ID 贯通运行、标注、人评与发布审查。
