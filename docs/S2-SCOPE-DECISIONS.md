# S2 范围讨论记录 v0.1

状态：**范围讨论中；以下为已确认的产品方向，不代表已设计完成或已实现**。2026-09-28。

本文件增量记录 S2 人机协同与受控改进的范围决策。阶段总目标与退出 Gate 仍以[验证路线](ROADMAP.md)为准；对象和权限边界见[架构与对象权威](ARCHITECTURE.md)。讨论结束后再形成完整设计和验收方案。

## 已确认方向

1. **发布责任：S2 采用版本级人工审批。** 系统可汇总低风险候选及其验证证据，人在一次审阅中批准或拒绝整个候选版本；高风险变更单独逐项审批。预先授权范围内的自动发布是后续探索方向，不属于 S2 承诺。
2. **候选修改范围：先覆盖表达与执行策略。** 系统可提出措辞、示例、重复内容整理、任务步骤、澄清顺序、Skill/SOP 和有限检索参数的候选修改。对硬规则、工具权限与副作用、价格或业务承诺、业务结果语义的修改不得进入该自动候选范围；以后是否扩大为独立的待审建议，另行决策。
3. **人的坏例标注：确认业务真值，不要求配置归因。** 标注者确认期望业务状态、必须做与禁止做的动作；原因可选填。系统负责先分析运行证据并建议失效环节与修改位置，但其归因不代替人工审定的真值。需要持久副作用和结果 ID 的案例仍按[产品定义](PRODUCT.md)中的评测规范补足。
4. **坏例来源：人工标记与系统提名并行。** 系统可根据可观察的运行失败、反复纠正或配置冲突等信号提名可疑案例；提名不等于确诊。进入正式评测集之前，业务真值仍须人工确认。
5. **提案组织：按共同原因归并。** 系统把相关案例及运行证据关联到一处尽可能小的候选修改，并保留每个来源案例的追溯关系。允许候选删除或合并重复的表达与执行策略内容，而不只是追加配置；必须用旧案例回归检查退步。

## 仍待细化

- 低风险与高风险的可操作分类，以及版本级审批界面需要展示哪些证据。
- 自动提名的信号、归并依据、误报处理与案例优先级。
- 候选版本的回放门禁、质量与成本阈值，以及审批后的发布和回滚操作。

上述方向不改变 S1 退出 Gate，也不意味着自动发布、真实外部写入或生产适用性已经得到验证。公开案例只使用原创虚构或明确获授权的材料。
