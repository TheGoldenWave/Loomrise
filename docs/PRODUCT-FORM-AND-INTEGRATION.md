# 产品形态与开放接入规范 v0.8

状态：产品方向已确认，新增能力均为规划，2026-10-16；本版补充专家版本内任务／主动服务配置、最小语义工具面及贯穿 Harness 的渐进式披露原则，具体合同名、字段和 UI 待实现验证。S1 已有最小执行切片、本机试用入口和三段式上下文选择，未实现任务工具或动态工具披露；S2 目前只有工作台本地原型。完整网页客服、服务端接入、评测发布和用户自有云快捷部署尚未实现。样例仅使用原创虚构或明确获授权的材料。当前分期与验收见[网页客服交付计划](CUSTOMER-SERVICE-DELIVERY-PLAN.md)。

## 决策与交付物

**已确认**：Loomrise 采用**交付工作台 + 官方网页客服应用 + 统一执行内核 + 分类适配器**。目标覆盖本次已核的 Knocket 网页客服能力，再提供业务执行、验收、受控持续改进和部署到用户自有云的能力。Knocket 是网页客服产品参照，不是 TRTC 实时语音方案；其标为 PLANNED 的渠道不计为已上线能力。S1 仍固定单场景、单模型、单模拟写入、双入口和单次回放，执行以单 Agent 为主。

工作台服务搭建者与策略运营，官方客服应用服务访客与一线坐席。两类操作面共享已发布版本、业务执行和事件事实，不另建一套审批或任务权威。工作台串联配置、试用、验收与发布；客服应用承载日常会话、人工接管和反馈。业务方仍可扩展或替换应用前端，完整客服操作面不再要求业务方全部自建。

计划交付三个相连的体验，而非三个独立平台：

1. **可选的示例体验**：进入明确标注虚构的课程咨询场景，文字入口完成一次咨询和经确认的模拟预约，展示可核验的结果 ID；网页语音通过最小链路验证后使用同一业务请求。初次试用不要求自备业务资料或接入真实系统，模型费用与限额需在启动前说明。
2. **B 端交付工作台**：用户可完整手动创建，也可使用可关闭的初始化助手整理获授权资料和候选配置；先验证自有资料答疑，再逐步接通业务工具；在同一处完成试运行、运行证据、坏例、候选 Diff、批量回放、审批、发布与回滚。业务概览与详细配置共用同一草稿和版本，助手不代替来源授权、验收真值和发布批准；旅程由待办与操作引导承载，导航仍按对象域组织，复杂配置和 Trace 按需展开。
3. **官方网页客服应用与交付包**：基于已发布版本提供 Widget、联系页、Inbox、联系人与坐席接管，逐步补齐渠道、通知、统计和 WebView 接入。文字与语音共用业务表单、确认和结果状态。交付包包含版本化配置、模拟实现、评测集、连接需求和部署清单，支持在用户自己的云运行。导出包不包含密钥、真实客户数据或未经授权的资料。

默认初始化目标是用自己的授权资料完成客服试用，再接业务工具；虚构示例与模拟预约是可选体验，不作为创建前置。手动与助手路径共用来源、校验和发布门禁，具体体验提案见[配置后台体验优化](CONFIGURATION-UX-OPTIMIZATION.md)。真实接入前仍需字段映射、沙盒测试、权限与副作用检查；示例或试用成功不自动推定真实业务接入成功。

## Task 与用户上下文的产品补充（原则已确认，合同与页面规划未实现）

默认任务及主动服务定义属于**专家自身的 AgentSpec 配置**，与目标、Skill、资料、工具和承诺一起演进；建议以 `AgentSpec.task_blueprints` 和专家内稳定 `blueprint_key` 表达，由 `AgentVersion` 冻结并沿既有评测、审批、发布和回滚链路生效。不建设跨智能体共用策略库，不让另一个专家的策略修改隐式改变本专家行为。

建议专家配置内提供“任务与主动服务”，按业务摘要到高级合同分层展开；以下是待实现的交互需求，不是当前原型已完成的页面：

| 配置深度 | 面向业务的内容 |
|---|---|
| 业务摘要 | 默认要做什么、对谁适用、何时触发／停止、为什么等待；主动触达是否启用及其限制可见 |
| 条件与决策 | 默认蓝图、依赖、内部登记／触达候选采用条件、允许改期／选择步骤的批准包络、人工锁定与升级条件 |
| 高级合同与证据 | 精确字段、专家版本／蓝图键、Skill／ToolManifest 引用、Schema、来源、预算和变更影响；完整查看不扩大权限 |

**蓝图编辑与用户事项管理分开**：前者改变专家候选版本；后者管理具体 TaskItem 的计划、负责人、阻断和取消请求，允许范围内的改期只生成实例 revision，不能误保存为全体用户的新默认策略。Agent 不能扩大渠道／权限／频率上限、改承诺或覆盖人工锁定。客服应用让获授权坐席查看、承接、改期或提名当前义务，不因此取得蓝图发布或画像真值权；完整人工路径独立可用。

“创建专家”不等于为所有潜在用户批量建任务。服务初始化只在确定的 `tenant + agent + subject + service_cycle` 内评估命中定义并幂等登记：身份、条件与记录权限齐备的低风险内部 TODO 可直接形成 TaskItem；任何触达意图先形成 TaskProposal，经已有批准规则／人工采用，执行前再检查最新许可。重复初始化、重连或专家换版本不能重复建项，也不因候选或事项已存在而获得触达权。在途迁移与回滚不得复活撤回许可、已取消事项或重置频次，详见[Task 设计](TASK-SYSTEM-DESIGN.md)。

运营来源与会话 TODO 通过同一应用用例归一，实际执行及结果仍交原 `ServiceRequest/Outcome`。用户记忆、派生画像与本次上下文共用身份／来源／用途／版本／撤销治理，按任务读取，不自动互相升级，也不授予主动联系权。模块职责见[用户上下文设计](USER-CONTEXT-DESIGN.md)，建设依赖见[联合计划](TASK-MEMORY-INTEGRATION-PLAN.md)。首次创建仍以获授权资料 FAQ 答疑为第一成果，不增加必填记忆、画像或主动服务配置；助手与高级模块均不是手动路径前置条件。

## 前后端责任

| 前端呈现和操作 | 后端必须保有的权威 |
|---|---|
| Widget、联系页、Inbox、联系人、人工回复与接管、通知及渠道设置 | 客服应用的会话与坐席占用状态；关联同一 `ServiceRequest/RunEvent`，不把会话或通知状态当成业务结果 |
| 示例入口、文字/网页语音业务界面、结构化表单、确认与结果状态 | 同一 `ExecutionService`、`ServiceRequest`、权限重验、结果持久化和 `RunEvent` |
| 场景/连接向导、字段映射、授权状态、沙盒检查和可用能力目录 | 场景与版本合同、连接凭据引用、能力发现、权限/来源检查和模拟适配 |
| 专家内任务／主动服务蓝图、用户事项清单、改期与取消请求 | 专家版本冻结与评测审批；Task 采用、revision、幂等、当前授权和执行停止确认；实例不改蓝图，事项不授予触达权 |
| 坏例、逐例/汇总测评、候选 Diff、审批、发布与回滚 | `Case/EvalSet/EvalResult`、确定性规则、机评记录、发布门禁、审计与版本状态 |

工作台负责把上述流程连贯地呈现给交付者，不承担绕过后端确认和发布门禁的判断；客服应用只使用对应已发布版本的授权能力。一个会话可以关联多个业务请求，`Conversation` 不等于 `ServiceRequest`。人工接管、回复与坏例反馈经同一事件体系回流；一线反馈是提名，策略运营审定后才成为案例真值。

## 分类接入规范（规划）

| 类型 | 负责什么 | 最小合同和边界 | 首次交付范围 |
|---|---|---|---|
| 渠道 / 媒体 | 网页文字、网页语音、Telegram、Email，后续其他 IM 与授权电话 | 身份与同意、入站事件、发送/播放回执、去重、取消和人工接管映射到同一 `ServiceRequest/RunEvent`；渠道不拥有业务终态 | S2-a Widget/Inbox 最小闭环；S2-b Telegram/Email 授权沙盒与 WebView；S2-c 完整文字/语音应用验收；其他渠道与电话在 S4 独立验收 |
| 外部信息源 | API、文件或事件流提供的结构化业务事实和变化 | 来源 ID、权利范围、身份映射、时间/有效期、增量或快照、撤销与删除；事件须先标准化再决定是否唤醒任务 | 模拟数据与一种只读接入方式作验证 |
| 知识检索 | 本地或外部知识库查询可引用的资料 | 查询范围/权限、来源引用、版本或抓取时间、有效期、无结果与超时；不将检索结果自动升级为业务事实或长期记忆 | S2-a 网页 FAQ/URL/File 摄入、解析与索引状态；运行时只读检索不限制知识管理侧的上传、版本与撤回 |
| 业务工具 | 查询或写入业务系统、产生可验证副作用 | 见下方 `ToolManifest`；执行前重验权限、参数、预算、确认和任务代次 | S1 模拟预约；S2-c 增加真实工具的授权沙盒联调，生产写入不因沙盒通过而默认开放 |
| 运行与观测 | 模型/运行 SDK、事件展示和 Trace 导出 | 供应商格式封装在 Adapter 中；`RunEvent` 是业务事实，外部 Trace/前端协议只是投影 | 固定版本的最小运行/事件适配 |
| 主动触达 | 在用户未持续输入时，针对已采用的具体服务义务按条件发送业务消息 | 专家任务蓝图内的 `OutreachPolicy` 约束条件、优先级、冷却、许可、去重、停止和回执，随 AgentVersion 冻结；不建共享策略库、不授予联系权或拥有业务终态 | S1 不实现；后续先候选／采用，再经最新授权检查进入同一 `ServiceRequest/RunEvent` |

每个连接先声明能力、权限范围和协议版本，再通过“连接 → 映射 → 试读/试写到沙盒 → 撤销与异常检查 → 启用”。凭据只在受控后端或密钥管理中保存，页面和交付包只持有引用。连接断开、授权撤销、引用失效、超时或回执未知时应呈现明确状态；不得把不可确认的结果写成成功，也不得悄悄提升权限。

S2-a 的知识管理入口覆盖网页 FAQ、URL 和 File 摄入；CLI 保留为可选的批量和本地接入通道，MCP 受限草稿／候选写入方向已确认、具体接口未实现，见[初始化与摄入通道](INTAKE-AND-INITIALIZATION.md)和[Agent 接入计划](AGENT-INTEGRATION-PLAN.md)。摄入与运行时检索共用同一条硬约束：没有 `source_ref`、权利范围、有效期和撤销入口的资料，不得进入 `ContextSnapshot`。摄入成功、索引可用、答复送达与问题解决分别留证。

接管合同至少区分请求交接、承接确认、Agent 暂停、人工释放和恢复。静默或超时只触发占用与恢复检查；满足已登记条件后，系统可以切换接待所有权并使旧占用失效。人工和 AI 在发送或写入前均核验当前占用代次，恢复时重验业务事实、任务代次、权限和确认。静默不能证明人工已经处理完，也不能作为取消确认；接待恢复不自动重启有副作用的业务请求。停止当前 Agent 执行不等于取消整个业务请求，通知送达不等于人工承接。

电话外呼不是网页语音的一个开关。将来接入外呼供应商时，需独立验证触达授权和适用规则、号码/时段限制、发起/振铃/接通/结束/转写回执的乱序与去重、录音与数据保留、人工接管和撤销。`call_id` 关联媒体事件与业务请求；供应商报告“已接通”不等于目标请求完成。批量营销外呼不是首版目标。

## 工具、Skill 与任务的最小规范（规划）

`TaskItem` 管具体服务义务与计划，不覆盖 `ServiceRequest` 的跨轮业务目标和执行状态；任务步骤只描述下一步行动及依赖；`SkillManifest` 是有版本、有适用条件和退出条件的局部执行策略；工具是经过授权的读写能力。Skill 可引用知识和工具，却不授予权限，也不替代 `ExecutionService`。不要求每个步骤都生成 Skill，不为每个外部 API 创建一个子 Agent。

上述专家内蓝图采用与执行合同以[Task 设计](TASK-SYSTEM-DESIGN.md)为准：服务周期幂等初始化，触达先候选再采用/执行检查；实例调整不改蓝图，升级不默迁在途事项，回滚不复活取消/退订或重置频次。

- **复用工具或增加适配器**：业务动作、权限和结果语义不变，仅供应商接口、认证或字段不同；工具合同不包含供应商私有字段。
- **新建工具**：出现不能由现有合同表达的新业务动作、风险/审批方式或可验证副作用；先证明无法通过参数、字段映射或适配器复用，且提供模拟实现与验收案例。
- **新建 Skill**：一段可独立命中、复用和验收的处理策略具有不同适用/退出条件；仅措辞或参数变化时修改已有 Skill 的版本，不复制 Skill。
- **拆出子 Agent**：默认一个执行 Agent 按需加载一个适用 Skill；只有独立子任务需要隔离上下文或专长、能限定输入输出/工具/预算、可由主任务复核并有失败回退时才引入。子 Agent 不拥有发布、审批或越权调用权，首版不建设多 Agent 群体编排。

`ToolManifest@v1` 的拟定最低字段为稳定 ID/版本、用途及副作用类别、输入/输出 Schema、所需权限和数据范围、超时/预算、幂等键策略、确认与审批要求、错误与未知结果、模拟实现、适用时的外部结果 ID 和审计字段。读操作也要受数据范围约束；写操作执行前重验权限与确认版本，异步动作须区分“已提交”“执行中”“已确认结果”“失败/未知”。模型声称动作完成不能代替持久业务结果。

MCP、OpenAPI 等可以作为导入自定义工具声明的候选入口，但导入后必须映射为上述业务工具合同并通过沙盒验证；外部声明不能直接授予模型权限，也不能将供应商私有状态写进 Loomrise 的 `ServiceRequest`。已发布 `AgentVersion` 固定可用工具与 Skill 的合同版本，替换底层供应商时仍须重新做连接与结果语义测试。

`SkillManifest@v1` 的拟定最低字段为稳定 ID/版本、适用事件与条件、所属任务/步骤（可选）、目标、执行与退出条件、可引用资料和工具 ID、失败/转人工策略、关联评测案例。任务可由消息、授权的业务事件或到期触发唤醒，但同一业务请求不得因多渠道事件重复执行副作用；高风险或关联状态失效时退回完整判断或人工处理。

线上业务中常见的阶段目标、条件路由、历史去重、停止规则和未完成目标跟进，不能全部塞进自然语言 Prompt。公开产品将其分为上下文快照、任务路由、Skill/SOP、模型外硬规则、工具策略和业务结果；上下文加载是横切执行机制，按常驻基线、当前任务/Skill、按需证据渐进加载，并保留加载/跳过证据。S1 只验证这六层和最小加载机制在被动响应中的闭环。未来主动触达先由规则或 Agent 在允许范围内提出候选，再由已批准规则／人工采用；发送权限、频控、停止和撤销始终由平台控制，执行前重验。

渐进式加载不是把规则藏起来：全局/任务/Skill 三级硬规则仍由模型外的 `DecisionPolicy` 统一裁决，模型只接收当前有效的约束摘要。新增规则前应先判断 badcase 属于路由错误、资料缺失、上下文未加载、Skill/SOP 不清、工具语义错误还是硬规则违规；只有最后一种才应直接增加硬规则。每条规则保留稳定 ID、作用域、优先级、来源案例、有效期和冲突处理，避免把修复历史堆成不可维护的 Prompt。

### Harness 的最小工具面与渐进式披露（原则已确认，未实现）

系统按本次主体、目的和角色直接装配有界 `task_workset`，覆盖当前相关、即将到期、逾期／待对账／阻断事项及近期相关完成／发送摘要；不要求 Agent 先调用 get-list Tool。建议 `inspect_context` 作为共用受限读取／展开能力，按获准引用补充事项、精确蓝图／Skill、有效事实或证据；建议 `manage_tasks` 是唯一任务管理意图 Tool，以类型化 `propose/adjust/request_cancel` 携带 revision、幂等键和依据。两者名称及 Schema 尚待登记，不拆 CRUD，不允许任意改终态、硬删除或写 cron／代码。实际业务查询、发送和写入仍保留语义明确的 `ToolManifest + ExecutionService`，禁止万能 `invoke/execute/RPC`。

| 层级 | 提供给模型的内容 |
|---|---|
| L0 常驻 | 身份与必要安全／确认／停止摘要、有界任务工作集和少量能力描述，不放全目录或全量 Schema |
| L1 选中事项／Skill | 仅给所需精确蓝图、可调字段／批准包络、有效事实和当前获准工具 Schema |
| L2 按需展开 | 有界来源、历史、详细工具结果和结果证据，分页与裁剪留证 |

安全必要事实不受预算截断；缺失或无法完整提供必要摘要时缩小范围、等待或阻止相关动作。工作集之外的事项仍参与全局去重／频控／停止检查。输入快照记录实际披露 Tool／Schema 的版本和 hash、授权版本、来源、加载／跳过／预算原因；读取、披露、调用与业务结果分别留证。

外部创作 Agent、后台 harness Worker 和在线客服共用应用服务，但由服务器强制隔离可见和可执行集合：外部仅见获准来源／草稿／候选／选定证据并操作受限候选，Worker 只做后台创作／诊断／候选作业，在线客服只用已发布版本的批准能力。不能靠隐藏工具名授权；猜名、旧 Schema、跨角色／租户越权、换入口绕权或披露后撤权都不能绕过检查，正常获准用例仍可跨入口复用。Provider 不支持轮内动态工具时，每 run 固定最小许可子集，切换需显式新快照／run 边界，不退回全量目录或万能调用器。在线业务保持有限受控流程，不因披露机制改成通用开放式 harness，也不改变 AgentScope 选型。

当前 S1 [`context.py`](../loomrise/context.py)只有最小上下文渐进选择，[`service.py`](../loomrise/service.py)仍固定注册 `search_knowledge/create_booking` 两个工具，未实现上述任务工作集、动态 Schema 披露或 MCP 接入。正式职责、支持矩阵和正反例验收见[Agent 接入计划](AGENT-INTEGRATION-PLAN.md)的 AGI-02／03／08，并与[Task／上下文联合计划](TASK-MEMORY-INTEGRATION-PLAN.md)衔接；本地前端不能作为服务验收。

## Ground truth 与发布门禁（规划）

阶段限定：S2-a/b 规划提供最小沙盒发布，须冻结版本、检查来源与权限、通过固定样例并由人工批准；测试应用只引用获批的冻结版本，不直接引用草稿，业务写入工具保持模拟实现。S2-b 的授权渠道测试可以使用必要的测试域名与回调，但不等于服务已面向真实用户发行，也不计为 S3 公网发行 Gate 通过。下文的完整 `EvalSet`、旧版/候选版批量配对回放、提案、审批发布与回滚门禁在 S2-c 补齐并验收，不因前两阶段的沙盒检查而减免。S3 再验收面向真实用户的公网发行及用户自有云部署。上述新增发布能力均未实现。

受授权资料约束的 FAQ 答疑也属于可验收业务任务，不要求每次咨询都产生工单或预约。案例记录资料依据、引用有效性、事实与服务范围，以及未解决时的升级要求；生成、送达和解决是不同事实。缺少解决证据时保留未知或待确认状态，不把一条回复生成成功当成问题解决。

`EvalSet` 是随场景版本化的验收资产，`Case` 由业务方或人工审定真值。真值不是一条唯一标准话术，而是输入场景、固定的资料/连接模拟快照、预期任务状态、必须/禁止的动作、必要字段、期望持久副作用与结果标识，以及可以接受的回答范围。覆盖正常、拒绝、资料缺失、越权、重复事件、超时、取消与渠道差异。开发、验证与保留盲测样本分开，不能用盲测反馈直接调 Prompt 再宣称盲测提升。

发布候选前，用同一冻结的评测集、工具模拟和评审规则批量回放旧版与候选版，记录每例的配置/知识/工具版本、环境快照、运行证据、成本和差异：

1. **确定性裁决优先**：Schema、权限、引用、硬规则、确认、幂等、取消、模拟环境中的持久副作用与结果 ID；违规即阻断，机评不得覆写。
2. **机评只评软质量**：相关性、澄清、依据充分性与表达；记录裁判提示词/模型/规则版本和分项理由，以人工校准样本核对误判，分歧或高风险交由人工复核。
3. **门禁先于发布**：按预先登记的场景阈值比较任务成功、失败与回退案例；关键退步或证据缺失时保留旧版。通过离线回放只允许进入人工审批，不等于线上已发布或真实渠道验收。

发布记录应绑定 `EvalSet` 版本、旧版/候选版、结果与审批人。连接资料撤销或评测证据删除后，受影响的“已验证”结论必须失效。真实外部写入绝不进入离线回放；接入实际系统还要另做沙盒联调、渠道契约测试与小范围发布观察。公开样例优先使用原创虚构数据；获授权的真实运行日志或评测集不能仅凭脱敏就公开，还需单独确认分享权利。

渐进披露另做同配置的 full／progressive 对照：固定专家版本、获准能力、模型、样本、环境和预算，只改变披露方式，比较任务质量、错误放行／阻断、上下文／Schema／结果 token、额外往返、时延和失败回退。隐藏工具猜测、过期 Schema、跨租户／角色、必要安全事实缺失／预算不足及 Provider 降级为阻断性测试。阈值先登记，不以更少常驻内容直接推断更省、更快或质量提升；具体验收在 AGI／TM 工作包留证。

## 用户自有云部署（规划）

Lite 保留本地开发与试用，Server 承载客服应用、持久状态与后台任务；语音采用可选 Voice Worker。S3 提供标准 Linux 容器发行物与首个云的快捷部署配置，覆盖认证、存储、备份恢复、升级和端到端验收；S4 扩展多云模板。腾讯云、阿里云为优先候选，AWS、Azure 为后续候选，均须实测后才能列为已支持。

各云使用同一发行物和业务合同，云模板只映射计算、存储、网络与密钥。用户持有云资源和凭据；客服应用不强制依赖 Loomrise 托管控制面。模型、语音、检索和通知的数据出口需要显式配置。部署成功必须有运行版本、健康检查与持久结果，不能仅凭页面可打开作判定。当前仅有本机导出恢复证据，尚无云端快捷部署或生产适用性证据。

## 阶段和待决策项

- **S1**：冻结最小领域合同与虚构场景，按上下文、路由、Skill/SOP、硬规则、工具策略和业务结果六层建立被动响应样例，并实现“常驻基线 → 当前任务/Skill → 按需证据”的最小渐进式加载，建立人工审定的正反例、模拟副作用和单次回放样例，验证文字/语音共用任务与写入一次的事实。主动触达只保留 `OutreachPolicy` 边界，不实现调度或发送。
- **S2-a**：单租户持久化基础、配置版本、FAQ/URL/File 摄入状态、Widget/Inbox 最小闭环。
- **S2-b**：完整已核的 Knocket 配套能力，包括联系页、Telegram/Email 授权沙盒渠道、通知、统计和 WebView。
- **S2-c**：真实业务工具沙盒、版本评测、提案审批、发布回滚、持续改进与完整文字/语音应用验收；用第二虚构场景验证核心复用。
- **S3**：标准 Linux 容器发行、首云快捷部署、认证、存储、备份恢复、升级和端到端验收。
- **S4**：多云模板扩展；其他渠道、电话与多租户分别通过独立 Gate。详细退出条件见[网页客服交付计划](CUSTOMER-SERVICE-DELIVERY-PLAN.md)和[验证路线](ROADMAP.md)。

**待验证**：Adapter 与实际协议兼容性、云端部署与恢复、评测一致性、渠道授权/撤销、真实语音与电话回执。**待决策**：首云具体服务组合、后续 IM/外呼供应商、公开 Demo 承载方式、各场景发布阈值和数据保留周期。新增范围没有改变 S1 Gate 或现有代码状态；没有可重复的实测结果前不宣称多供应商即插即用、生产或企业级能力。
