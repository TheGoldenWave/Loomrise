# 验证路线 v0.1

> 阶段以验收 Gate 排序，**不承诺日期**。这是计划，不是完成记录。

| 阶段 | 要做的事 | 退出 Gate |
|---|---|---|
| S0 产品定位（当前） | 第一用户、场景包、独立边界、参考清单和两条 spike 范围 | README/PRODUCT/ARCHITECTURE/REFERENCE/NAMING 一致；未验证事项明确标注 |
| S1 底座 spike | AgentScope 文本切片、Pipecat 网页语音切片；额外最小试验 AgentScope RealtimeAgent / Qwen Audio Gateway；验证本机启动和 RunEvent 接入 | 同一虚构场景文字/语音均能完成一次咨询＋预约；记录真实安装步骤、资源、首响/打断、协议适配成本和许可证 |
| S2 独立产品 alpha | PM 向导、AgentSpec 版本、Trace、Badcase、固定集、局部改动提案、人工审批与回滚；原创教育/二手车案例包 | 非开发用户不改代码完成“建→试→看→改→回滚”；输出真实耗时和失败案例；明确数据删除/权限策略 |
| S3 可公开演示 | 登录/配额/预算、可选 BYOK、部署说明、演示视频、独立品牌与案例来源声明 | 公网小流量真实试用，语音费用与滥用护栏有效；无内部资料泄漏；可复现单机安装 |
| S4 渠道与规模 | 钉钉或企微先选一个；批量部署、隔离、监控；电话外呼单独受控评估 | 官方授权、幂等/回调、人工接管、租户隔离与审计通过真实环境验证；外呼合规/线路另行确认 |

## S1 的首批 Issue（未创建，按依赖执行）

1. 拟定两个完全虚构的 `ScenarioPack`（课程咨询/二手车预约）与一批人工复核的正反例。
2. 起草 `AgentSpec@v1`、`RunEvent@v1`、`ChangeProposal@v1` 的 JSON Schema 和可验证样例。
3. AgentScope 文本最小服务接入一个模型、一个只读知识工具与线索字段收集。
4. Pipecat 浏览器麦克风最小服务：流式对话、打断、播出确认/未知，接同一业务策略。
5. 比较 AgentScope RealtimeAgent、Qwen Audio Gateway 的接入成本与协议限制，决定保留哪一个 Voice Adapter。
6. 基于真实运行输出安装/依赖/许可证/成本/故障/首响记录，然后冻结 S2 技术路线。

## 开源传播节奏（提案）

按真实工件公开：场景包 → 单机启动视频 → 文本/语音同场景对照 → Trace 到改动提案 → 回放/回滚。公开数据需写“模拟”，性能数字需注明设备、模型、网络、样本和采集方法。首版不会宣称生产级、真实企业合作或已证明自动自进化。
