## 1. 要建什么

一个面向 **AI 产品经理 / 解决方案人员** 的 B 端交付工作台：把「场景包 → 试用 → 证据 → 坏例 → 受控改动 → 回放验证 → 人工审批 → 灰度发布 → 回滚」这条链路，从 CLI 变成可点界面。

**它不是什么**（设计时最先要守住的边界）：

- **不是 Prompt 编辑器**，是「问题 → 证据 → 决定」的操作台——人进来要回答的是「有什么问题、要不要批、要不要回滚」。
- **不是节点画布**，不追工具数量与多 Agent 数量。
- **不是终端用户的聊天壳**（那是第三条体验，S2 不建）。
- **界面文字用业务词，不用工程名**：`ScenarioPack` 在界面上叫**「专家」**，六层配置叫**「人设 / 流程 / 边界」**，**「配置」二字从界面消失**。

## 2. 规模

| 口径 | 数字 |
|---|---|
| 一级域 | **6** |
| 二级页面 | **16** |
| 面（二级页 + tab） | **22** |
| P0 可点页面 | **14** = 9 二级页 + 5 tab |
| alpha 实际交付面 | **18** = 12 二级页 + 6 tab |
| 不占菜单的载体 | **12** 项（详情页 / 指针 / 全局控件） |

**P0 是"优先级"口径，不是"交付范围"口径**——两者差在 P1 的工具与连接 / 审批档位 / 模型 / 流量 tab。

## 3. 设计原则（8 条）

摘自 IA-NAV §2。新增页面时按这 8 条判断落点，不必重开讨论。

| # | 原则 | 判据 |
|---|---|---|
| 1 | **一级 = 对象域** | 能不能用「这里管的是哪一类东西」一句话说清？不能就不是一级 |
| 2 | **单页不设域** | 只有 1 个二级页的候选一级，并入相邻域 |
| 3 | **旅程由流程条承载，不进菜单** | 顶部常驻 `建 → 试 → 看 → 改 → 验 → 批 → 滚` |
| 4 | **列表 → 详情，详情不占菜单** | **这个页面能否在不选任何具体对象时被打开？** 不能 → 不是二级页 |
| 5 | **对象必须有落点** | 每个权威对象至少一页可见，且最多一次跳转内可操作 |
| 6 | **界面文字用业务词** | 一个对象只准有一个用户可见名 |
| 7 | **归属决定位置** | 先问**作用域**（平台 / 专家）再问**性质**（规定 / 事实），合成 2×2 |
| 8 | **承载面容量上限** | 一块承载面内容块 > 5 必须拆 tab 或加页内 anchor rail |

## 4. 页面与功能总表（22 面）

三个视觉分组：**交付与验证**（每天用）→ **治理**（有审批就来）→ **平台**（极少动）。

### 4.1 交付与验证 · 专家 `experts`

| 面 | 优先级 | 一句话职能 | 主操作 |
|---|---|---|---|
| **专家列表** | P0 | 我手上有几个专家、各是什么状态 | 进入专家 / 新建 / 停用 / **点指针直达版本详情** / 导出（弹窗选版本） |
| **新建专家** | P0 | 把一个业务目标变成一包可审阅的配置 | 分步向导 → 生成**草稿版本** |
| *专家详情 · 概览* | P0 | 这个专家健康吗、有什么事等我 | 跳到待办对象（**四指标 + 待办列表**） |
| *专家详情 · 版本* | P0 | 这个专家有哪些版本、我在改哪一版、能不能提交 | **指针直达稳定 / 最新** · 打开版本 · 新建草稿 · 提交审批 · 丢弃 · 对比 · 导出 / 试用 |
| *专家详情 · 流量* | P1 | 现在哪个版本吃多少流量、要不要调 | 启动灰度 / 扩量 / 紧急停止 |
| *版本详情 · 人设* | P0 | 它是谁、怎么说、要拿到什么信息 | 编辑（写入本版本草稿） |
| *版本详情 · 流程* | P0 | 它怎么把一件事办完、用户插问时怎么答 | 编辑（写入本版本草稿） |
| *版本详情 · 边界* | P0 | 它能引用什么、调用什么、绝不能做什么 | 编辑（写入本版本草稿） |
| 〔页头〕*模型状态条* | P0 | 这个版本用哪个档跑 | 点击覆盖 / 改回默认（**进草稿**） |

> **「边界」tab 这一面的颗粒度比别的面深一层**：它的「硬性限制」不是一张平表，而是一组**可组合条件**（`when` / `verdict` / `enforce` 三段）。出稿前先读[硬规则表达模型](HARD-RULE-MODEL.md) §7——界面上要补**条件编辑器 / 冲突与覆盖提示 / 命中证据 / 有效期 / 红线标记 / 规则数告警**六件，且**条件不允许手写自由文本**（只能从已声明字段里选）。这是全部 22 面里唯一需要"半结构化编辑器"的一面。

### 4.2 交付与验证 · 运行 `runs`

| 面 | 优先级 | 一句话职能 | 主操作 |
|---|---|---|---|
| **数据看板** | P0（成本 P1） | 它干了什么、花了多少、还能花多少 | 筛运行流水 · 切成本视角 · 设配额 · 进运行详情 |
| **试用台** | P0 | 改完的东西试一遍会怎样 | 选专家 + 版本 → 发消息 / 语音 · 确认卡片 · （可选）临时换模型档 |
| **依据追溯** | P1 | 它当时凭什么这么答 | 查上下文加载状态 · 召回命中 · 兜底（**S2-a 只做运行详情内 tab**） |

### 4.3 交付与验证 · 验收 `acceptance`

| 面 | 优先级 | 一句话职能 | 主操作 |
|---|---|---|---|
| **案例集** | P0 | 我们认定什么是对的 | 审定真值 · 归档 · 切用途与批次 |
| **回放验证** | P0 | 新旧版本比，退步了没有、改善了没有 | 发起回放 · 看批次报告 |
| **案例标注** | 人工 P0 · 提名 P1 | 这条可疑运行到底对不对 | 填业务真值（期望状态 / 必须做 / 禁止做） |

### 4.4 治理 · 变更 `changes`

| 面 | 优先级 | 一句话职能 | 主操作 |
|---|---|---|---|
| **待我审批** | P0 | 有什么等我批 | 进改动详情 · 批准整个版本 / 逐项审批 / 拒绝 |
| **版本与发布** | P0 | 线上现在是什么、最近发了什么、要不要退 | 跨专家时间线 · 紧急回滚 |
| **审批档位** | P1 | 什么风险由谁批、按什么阈值 | 创建 / 复制 / diff / 设切换时间 |

### 4.5 平台 · 知识 `knowledge`

| 面 | 优先级 | 一句话职能 | 主操作 |
|---|---|---|---|
| **业务知识** | P1 | 它能引用哪些外部事实 | 上传 / 替换 / 撤回 · 看引用面 |
| **文件与物料** | P2 | 它能引用哪些物料 | 上传 / 版本 / 撤回 |

### 4.6 平台 · 设置 `settings`

| 面 | 优先级 | 一句话职能 | 主操作 |
|---|---|---|---|
| **工具与连接** | P1 | 平台上有哪些工具、连了谁、钥匙放哪 | 增删改停用 / 撤销授权 · 调沙盒 · 配渠道凭据 |
| **模型** | P1 | 平台默认用哪个大脑、贵不贵 | 切默认档 · 看两档成本对照 · 配密钥引用 |
| **系统诊断** | P2 | 这台机器对劲吗、凭据放得稳不稳 | 自检 · 干净实例恢复校验 · 查凭据存放与轮换记录 |

## 5. 页面关系

### 5.1 专家域是三层（设计上最容易做错的地方）

```text
专家列表
 ├─ 稳定版本 v3 ─┐  ← 两枚指针：跨层直达版本详情（1 跳）
 ├─ 最新版本 v4 ─┘     零新增元素，把列表上已有的两个字段升级成可点
 └ 专家详情（3 tab，不占菜单）
      概览 · 版本（默认落点）· 流量
        └ 版本详情（3 tab + 页头状态条，不占菜单）
             人设 · 流程 · 边界      〔页头〕模型状态条
```

**五条规则**（来自 IA-NAV §4.3.1）：

1. 选中专家后**第一屏是版本列表**，不是概览、更不是配置。
2. 版本列表：**草稿置顶**；无草稿时首行 = "新建草稿（从稳定版本派生）"。
3. **稳定版本只读**；要改先新建草稿。
4. 新建专家 → **直接落到草稿版本的版本详情**（向导产出 `draft`）。
5. **模型覆盖档住在版本详情页头**（不是专家页头）——它随版本冻结。

### 5.2 跨域跳转表

| 从 | 到 | 触发 |
|---|---|---|
| 专家列表行 chip | **版本详情**（人设 tab，1 跳） | 点「稳定版本」/「最新版本」指针 |
| 专家详情 · 版本 | 版本详情 | 点某个版本 |
| 专家详情 · 概览 待办 | 改动详情 / 案例标注 / 回放验证 / 版本列表 / 流量 tab | 点待办项（每条锚定**具体对象**） |
| 版本详情 | 变更 · 待我审批 | **提交审批**（草稿 → `ChangeProposal`） |
| 版本详情 / 专家列表 | — | **导出 / 试用是版本上的动作**，不占页 |
| 数据看板 | 运行详情 → 依据追溯 tab | 展开单次运行 |
| 变更 · 待我审批 | 改动详情 | 点收件箱条目（**批准在改动详情做**） |
| 变更 · 版本与发布 ＋ 专家详情 · 流量 | — | 应急动作**两处都有**（跨专家总览 / 单专家操作） |

### 5.3 七个「别再搞混」（直接决定组件边界）

1. **专家详情 ≠ 版本详情**：**选版本在专家层，改内容在版本层。**
2. **「流量」tab ≠ 「版本与发布」页**：**看分流去专家，决定发退去变更。**
3. **「待我审批」页 ≠ 批准的落点**：**收件箱用来发现，改动详情用来决定。**
4. **「试用台」页 ≠ 试用的唯一入口**：主入口在版本详情。**但只有一套试用 UI。**
5. **「设置 · 模型」≠「版本详情页头 · 模型状态条」**：**改全局默认去设置，改某个版本的档在版本自己的页头**（且必须走草稿）。
6. **「主流程」≠「应答能力」**：**要按固定顺序推进的去主流程，用户随时可能问的去应答能力**；两者可同轮加载，但**路由的"下一步"仍只指主流程**。
7. **「稳定版本」指针 ≠ 「最新版本」指针**：**要看线上现状去稳定（只读），要接着改去最新（可能是草稿）**；两枚指同一版时只显示一枚。

## 6. 不占菜单的 12 项载体（设计清单）

| 载体 | 内容 |
|---|---|
| 专家详情 tab | 概览 · 版本 · 流量 |
| 版本详情 tab | 人设 · 流程 · 边界 |
| **版本指针** `stable` / `latest` | 专家列表行 + 版本列表顶部；**指针 URL 解析后重定向**到具体版本 URL，不产生独立页面 |
| 版本详情**页头状态条** | 模型覆盖档（**不是 tab**——它高于三 tab） |
| 改动详情 | 行级 diff · 两栏证据 · 硬性限制检查 · 成本对比 · 详细轨迹 |
| 案例详情 | 真值 / 审定记录 / 归档状态 / 用途 / 批次号 |
| 运行详情 | 对话回放 · 证据四段 · 依据追溯 tab · Trace（默认折叠） |
| 审批档位详情 | 定义 · 与基线 diff · 切换历史 · 有效期 |
| 流程指示条（全局） | `建 → 试 → 看 → 改 → 验 → 批 → 滚` |
| 开发者模式（全局开关） | 配置原文 · 完整 Trace · 上下文加载明细 · 召回命中 |
| 专家切换器（全局） | 跨域筛选上下文 |
| 模板 / 导入对话框 · `DecisionResult` 只读视图 | 一次性动作 / 折叠视图 |

## 7. 设计时必须守的硬约束（会咬人的）

来自 IA-NAV §4.7「关键约束」列，取最容易做错的：

1. **列表项显示业务岗位名**（如「课程咨询顾问」），**不得出现"专家 / 专员"这类职级词**。
2. **稳定版本只读**；改必须先新建草稿；**提交即冻结**；确定性冲突在提交时**阻断**，语义冲突只给建议。
3. **流量比例只读**（由审批过的 `canary_plan` 决定）；红线命中自动归零并显示「已自动停止暴露，等待人工决定」。
4. **人设只写"是什么、要什么"，不写"不许做什么"**（后者属边界）。
5. **变量与字段的定义只在一处编辑**（人设 tab 末节），流程 / 边界只做**只读引用**。
6. **硬性限制必须在模型外执行**，按 类别 × 作用域 分组，**禁平表**；**工具授权步进给、不给"全开"**；**频控覆盖只能更严不能更松**。**规则的条件只能引用「已声明字段」与系统事件枚举——不得提供自由文本条件框**（否则规则不可校验、不可检测冲突、不可回放）。**规则数超阈值时提示"疑似该归因到状态建模或 Skill"，而不是鼓励继续加规则。**
7. **回放的「不退步」与「有改善」两栏不得合并**，基准案例通过率不得进「有改善」栏；**阈值跑前登记、运行中不放宽**。
8. **盲测按批次消费**，`consumed` 后不可再用；**不存在"因候选输出不同而回填真值"的记录**。
9. **案例标注只填业务真值**，不填配置归因；系统归因显示为「建议」，不预填。
10. **「待我审批」是收件箱不是操作台**；高风险改动**不可"批准整个版本"**。
11. **回滚只回退到上一个已发布版本**，不做跨版本搜索或自动修补。
12. **确认卡片由受约束组件生成，不执行模型产出的 HTML 或脚本**；**密钥只存引用不存明文**。

## 8. 设计阶段要产出什么

1. **22 个面的设计稿**（IA-NAV §4.7 给每个面"一句话职能 + 主操作 + 一条会咬人的约束"，可直接作为逐页设计输入）。其中**「版本详情 · 边界」一面的「硬性限制」需额外读[硬规则表达模型](HARD-RULE-MODEL.md) §7**——它是唯一需要条件编辑器的面。
2. **全局框架**：`MainLayout` · `sidebarNav`（**由 routes 表派生，不手写两份**）· 专家切换器 · 流程指示条 · 开发者模式开关。
3. **四个共用组件规格**：
   - **证据四段面板**（依据 / 动作 / 结果 / 代价）——试用台与运行详情共用；
   - **版本 diff 视图**——必须**按人设 / 流程 / 边界分段**呈现，**规则部分要按段（`when` / `verdict` / `enforce`）而非整条行 diff**；
   - **两栏证据**（不退步 | 有改善）——**严禁提供合并视图**；
   - **条件编辑器**——字段选择器（取自人设 tab 的字段表）+ 算子 + 值 + `all / any / none` 两层；**无自由文本输入**；**冲突与覆盖就地高亮**。
4. **数据形状（TS type + mock）**：`AgentSpec` 本体 · 草稿版本容器 · `ChangeProposal` · `EvalSet` / `EvalResult` · `PolicyProfile` · API 契约 —— 见[启动方案](S2-CONSOLE-KICKOFF.md) §1.2 K1–K6。
