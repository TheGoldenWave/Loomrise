### 上限 300 ms 的依据（不是从结果倒推的）

1. 浏览器侧量的是"按下打断 → `AudioBufferSourceNode.stop()` 生效"，该调用在下一个渲染量子（约 2.7–5.3 ms @ 60–120 Hz）内停止发声；
2. 剩余预算留给事件队列抖动、主线程被 JS 回收占用、以及服务端 `streaming_cancel` 的异步返回；
3. **300 ms 是宽松上限，不是目标值**。真实基线若接近它，说明主线程被阻塞，问题在别处。

按纪律：本轮**没有**停止时延采样（阻塞项已变化，见下节），所以这条上限尚未被任何数据污染。

### 阻塞说明（为什么 `M-S1-13` / `M-S1-14` 本轮不成立）

- **语料未建**：注册噪声语料需要真人录制或合法授权的音源，本轮没有。用合成音频冒充"电视声/旁人交谈"会让"0 次误停"变成自证。**2026-10-23 负责人决定：语料测试延后**，登记挂账 `G-6`（[R0 证据摘要 §5](R0-EVIDENCE.md)）。
- **播放侧已不再阻塞**：人工实测已通（`M-S1-08`，真人对着浏览器麦克风说话并听到合成回复），所以"本机自动化挂死"只影响**批量采样**，不影响**能不能测**。真正缺的是语料与人工采样轮次。

因此这两条 Gate 在本轮记 **未开始**，不记"部分通过"。补语料 + 人工实测后按本表口径执行。
