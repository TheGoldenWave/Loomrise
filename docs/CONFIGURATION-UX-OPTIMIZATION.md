## 1. 结论与方案选择

建议采用**两种创建方式、三个配置深度、同一份版本化配置**：

- 创建方式：**手动创建**与**使用初始化助手**。手动路径完整可达，不依赖助手会话或生成调用；助手可在任意阶段加入或关闭。
- 配置深度：先看业务概览，按需编辑业务配置，再下探详细配置与证据。深度是呈现方式，不是另一套配置，也不是权限档位。
- 配置权威：所有操作作用于同一个 `AgentSpec` 草稿；发布时冻结 `AgentVersion`。助手只提出候选修改，不取得授权、真值或发布权。

| 备选 | 收益 | 主要代价 | 建议 |
|---|---|---|---|
| 分组表单为主，附说明和模板 | 字段明确，人工控制直接 | 人仍需先理解全套配置，初始化负担高 | 保留为完整手动能力，优化字段顺序与默认值 |
| 对话为唯一创建入口 | 可以少填表 | 难定位配置；生成失败影响创建；用户难完全手动搭建 | 不作为唯一入口 |
| 结构化编辑器 + 可选助手 + 按需展开 | 新人可借助助手，专家可直接配置；建议与字段可相互定位 | 需要同一草稿的双向映射、冲突处理与依据展示 | **推荐，待交互验证** |

“上限高”来自可解释的结构化配置、复用与扩展合同、版本和评测能力。它不要求初次用户先学习六层，也不要求增加任意脚本执行、全功能节点画布或框架私有字段。

## 4. 创建与配置的 UI 结构提案

### 4.1 两种创建方式，共用一个编辑器

专家列表的“新建”展示两个清晰入口：**手动创建**、**使用初始化助手**；不强制弹出助手，不把手动入口藏在高级设置中。已有草稿直接继续编辑，也可从当前模块请助手协助。

手动路径提供目标、资料、服务范围和默认答疑配置；用户能手工创建、校验、试用、验收和发布，不需要生成会话。创建与配置本身可不调用生成模型；真实客服试用与运行仍需要有效模型连接，并明确用量。

助手在编辑器的可关闭侧栏/抽屉工作。用户可以中途转手动，保留资料、确认和已采用字段；助手失败、超时或被取消时，草稿仍可访问。转回助手时选择要协助的范围，不覆盖人工修改。

### 4.2 三个深度，而非三套后台

| 深度 | 默认展示 | 深入入口 |
|---|---|---|
| 业务概览 | 服务谁、能回答什么、暂不能做什么、依据资料、人工出口、试用状态和下一步 | 每块“查看/编辑配置”，定位同一版本的原项 |
| 日常业务配置 | 知识与回答、服务流程、转人工、业务字段和动作；模型与入口显示有效摘要 | 展开来源、引用影响与完整设置；可选“请助手建议” |
| 详细配置与证据 | 六层定义、依赖、默认值继承、有效值、版本差异、校验与运行依据 | 按权限编辑草稿、搜索、导出和比对；历史/已发布版本只读 |

页头始终显示专家、草稿或发布版本、环境、保存状态。主操作随状态变化为“继续补齐”“试用”“提交检查/审批”，不让“保存”承担上线语义。

保留对象职责与版本归属；新用户通过新建动作和当前草稿待办完成任务，无须先访问全部治理页。当前第二轮采用四组导航，选择专家先进入业务概览，三个深度为概览/业务配置/详细配置，均定位同一草稿或明确的只读版本。长期治理不全部铺在初始化面，不新增平行全局配置库；本次增量按 §12 设计，不恢复早期三 tab 为三套编辑器。

桌面编辑内容与预览相邻；助手与预览可切换，避免常驻三栏挤压表单。小屏按编辑、预览、助手切换，保留上下文和未保存内容。折叠不隐藏阻断项，不能仅靠颜色、悬停或禁用按钮解释状态。

## 5. 初始化的最小黄金路径

以下为目标体验，尚未实现。助手只是一条可选路径；人工采用相同检查点，流程进度可跳转并恢复，不要求按向导走完才能编辑。

### 检查点一：表达任务与提供资料

用户用一句话描述服务对象与目标，例如虚构的“回答课程问题，复杂退费问题交人工”；也可直接选答疑模板后手动修改。先不要求输入 Skill、路由、字段 ID 或完整 SOP。

资料支持 FAQ、授权 URL 和文件；允许先保存空草稿或使用明确标记的虚构示例。使用自己的资料前，确认来源及使用范围，登记有效期与撤销方式。可将同批资料的共有信息统一声明，并允许单项覆盖；默认值来自已登记策略且可查看，不能由助手推断用户拥有授权或替用户作承诺。

上传、抓取或模型处理前说明真实数据去向。URL 的抓取范围显式限定，不自动扩大到整站或登录后的页面；缺授权的资料不能进入可试用知识。

### 检查点二：形成并审阅可试用草稿

手动方式：用户编辑业务配置，系统执行结构校验与就绪检查。助手方式：解析资料后提取候选事实、服务范围、FAQ、路由和处理策略，给每项标注“资料依据/模板默认/助手建议/待确认”。

两条方式都显示服务摘要：能回答什么、依据是什么、无法处理如何结束或转人工、当前可用动作及结果证据。默认答疑不开放真实业务写入；有关权限、承诺、价格、确认和保留策略的变化显式确认。已批准规则不可被材料或模型输出覆盖。

助手只集中询问影响当前试用的缺口或矛盾，例如两份退款政策冲突；每轮只提出少量可回答的问题，允许“暂不处理此类问题”。品牌视觉、通知渠道、完整业务字段和真实工具接入可以后补；高风险缺口无法用“跳过”获得权限。

缺模型连接时可复用当前用户有权使用的服务端连接，或展示清楚标记的脚本模拟。脚本模拟只证明交互，不称为“已用我的资料进行 AI 答疑”；真实模型调用前显示连接来源、数据路径与预算。初始化助手本身也需要授权连接和预算，缺连接时手动路径仍可用。

### 检查点三：试用并得到明确下一步

提供资料内问题、资料外问题、转人工请求三个测试入口，用户也可输入自己的问题。展示答复、来源与未解原因，而不是只展示一段流畅聊天。

内部编辑试用使用冻结的临时快照和模拟工具；不发送外部消息、不安装入口、不写真实业务。配置修改后原试用记录继续留存并标记版本差异，当前就绪检查重新计算。

安装 Widget、发布联系页或启用渠道必须另走最小沙盒审批：冻结配置、检查来源/权限/固定样例、人工批准并绑定指定版本。S2-c 再补完整评测发布链路，S3 验收真实用户公网与自有云发行。编辑器中的“可以试用”不代表“已经发布”。

成功后的下一步按缺口展示：完善回答、配置人工承接、增加业务工具或接入网站。没有工具时明确“现在可以答疑，尚不能办理预约”等，不把纯 FAQ 视为初始化失败。

## 6. 详细配置的上限与边界

| 业务界面内容 | 对应权威 | 详细视图至少可查看什么 |
|---|---|---|
| 资料与当前事实 | `ContextSnapshot`、来源引用 | 原资料、片段、来源/版本/有效期/授权、检索就绪、引用和撤回影响 |
| 请求与处理流程 | `RequestRouting` | 触发条件、当前主请求、优先级、步骤/任务代次与回退 |
| 服务策略 | `Skill/SOP` | 适用范围、步骤、示例、退出/转人工、知识与工具依赖 |
| 默认任务与主动服务（后续需求） | 专家 `AgentSpec.task_blueprints` / `AgentVersion`，横切既有六层 | 业务摘要 → 条件/允许决策 → 蓝图/依赖合同；候选版本差异、在途影响与明确迁移选择，不做共享策略库 |
| 必须遵守的约束 | `HardRule` | 作用域、条件、裁决、冲突、执行位置、版本与关联案例 |
| 允许的业务动作 | `ToolPolicy`、`ToolManifest` | 输入输出、字段映射、授权、确认、预算、超时、幂等、模拟与实际结果要求 |
| 结果与验收依据 | `Outcome`、`Case/EvalSet/EvalResult` | 答复生成/送达/解决确认或未知、业务结果、失败/取消、预期动作与证据 |

模型连接、应用外观、接待时段、入口绑定、知识摄入、发布和部署提供各自完整设置与版本关系，**不增加第七个业务配置层**。全局默认、当前版本覆盖与本次试用临时值分开显示；改变平台默认不能静默改写已冻结版本，凭据撤销仍能阻断相关调用。

同一字段只定义一次，引用位置可定位；字段改名或删除先展示受影响的流程、工具、案例和已发布版本。摘要、人工字段、助手输出都从同一配置投影，保存时统一校验，不能各自维护隐藏 Prompt。

专家蓝图编辑与当前用户事项管理必须分开：改期/请求取消是实例 revision，不保存为所有用户的新默认策略；触达候选、采用与执行许可分别显示。创建专家仍先用授权资料答疑，无须先填任务蓝图。运行时上下文/工具同样先给有界摘要，再按任务披露必要事实、Skill、Schema 和证据；这不是前端已实现能力，具体合同与 Gate 见[Task 设计](TASK-SYSTEM-DESIGN.md)和[Agent 接入计划](AGENT-INTEGRATION-PLAN.md)。

“暴露完整内容”包含查看定义、依据、有效值、限制与未决项。它不意味着所有人都能修改：来源素材、密钥值、内部思维链不因此公开；无权限内容给脱敏摘要或说明。完整规则编辑依赖现有 K0 等合同决策，不在本轮偷偷确定算子或开放任意规则表达。

可编辑 Prompt/表达层遵守锁定范围；高级用户能查看其与结构化配置的关系，修改仍进入草稿校验。权限、确认、幂等和结果裁决继续在模型外，不能通过写 Prompt 或切换“高级模式”覆盖。

## 7. 助手、人工与发布的责任分工

| 操作 | 助手可做 | 人与平台承担 |
|---|---|---|
| 整理资料、起草 FAQ/SOP | 在授权范围内读取、提取、给候选与依据 | 确认事实、范围、来源与冲突；平台校验结构 |
| 生成名称、欢迎语、字段和路由建议 | 提出可拒绝的修改与引用影响 | 用户选用，人工编辑项默认受保护 |
| 建议业务承诺、权限或硬规则 | 只能作为待审提案，说明影响 | 有权人员决定；平台执行确定性门禁 |
| 连接模型、工具或云 | 说明步骤、准备非敏感配置建议 | 用户授权；服务端保管凭据；连接验证不等于执行授权 |
| 评测与改进 | 提名案例、诊断、提出候选 | 人审定真值；独立检查、评测和审批，不由同轮生成自证 |
| 发布或恢复版本 | 汇总证据、说明阻断 | 按现有发布权批准；没有授权不得生效 |

助手读写均限于当前对象和用户权限。采用修改前展示具体旧值/新值、来源、影响范围和待重验项，可按项接受或拒绝。初始化助手不获得生产业务执行权限。

人工和助手并发编辑时比较基准版本，检测过期建议并重新合并；不采用最后写入覆盖。撤回建议不撤销已发生的外部写入。对已发布版本的修改先派生草稿，任何生效路径都经过现有门禁。

后续自然语言指令如“这类退费问题直接交人工”先生成定位明确的差异。保存后，受影响的验收证据标为待重验；发布前展示当前发布版与候选版的对比。助手调用过程只展示输入范围、工具动作、结果、用量和可解释依据，不保存或展示隐藏思维链。

## 9. 设计验证与指标

下一轮先比较以下任务：完全手动创建 FAQ 客服；使用助手从资料起草再转人工；专家下探并修改详细配置。分别验证新人、业务运营和搭建者的任务理解，混用两种方式的用户不被重复计算为两个用户。

必要任务样例：

1. 从授权虚构资料得到首个有引用的答复，再问资料外问题；不接业务写工具。
2. 两份政策冲突，助手提问或人工解决；未确认的承诺不能流入可用知识。
3. 助手中途失败，用户手动继续；人工改过欢迎语/字段后再次请求建议，已有修改不被覆盖。
4. 从摘要下探字段和规则、查看来源及引用；无发布权的用户仍无法发布。
5. 保存草稿并试用，线上入口继续绑定旧批准版；新增配置使相关检查待重验。

指标先采基线再登记目标，不预写“几分钟完成”或达标结果。记录开始到首个有效**真实模型答疑**的耗时、人工活跃时间与解析/模型等待时间、完成率、求助次数、强制输入数量、澄清次数与恢复成功率；脚本模拟单独统计。

以开始创建的会话/用户作为完成率分母，并报告手动、助手、混合路径及中断原因。首个有效答复须同时有有效资料依据与测试判定，不以首个 token 或生成成功替代。再测用户是否能正确区分保存、试用、批准与发布，以及是否能找到目标详细项；权限违规和静默覆盖人工修改属于阻断问题。

## 10. 主流 Agent 对接开发事项

**AGENT-INTEGRATION-01：方向与高优先级排期已确认，具体 Provider／SDK 待验证，未实现。** 统一应用服务／API、MCP + 配套 Skills、可选 CLI 共用草稿与候选合同；S2-a 优先受限创建和首个 host 联调，S2-b 诊断与可选 Worker，S2-c 受控改进及授权例行治理。工作包与验收见[开发计划](AGENT-INTEGRATION-PLAN.md)。不增加初始化框架选择器或未经实测的“已支持”徽标。

先分清四类接入：

| 类别 | 要解决的问题 | 不得混淆 |
|---|---|---|
| 配置助手 / 外部创作 Agent | 在授权范围读取资料、建议结构化配置、提交差异 | 生成配置不等于运行客服，不授予发布或业务写权限 |

| 应用与外部接入协议 | 将试用、配置、事件或候选操作接到外部客户端 | API/CLI/MCP 不绕过身份、来源、版本、幂等和审批 |

开发验收产物应包含：主流候选的官方能力与产品使用方式、合同映射、结构化输出/错误/取消/恢复、版本与幂等、权限和预算、沙盒验证、导入导出/损失清单、无助手时的降级路径，以及实际联调证据。先一个 Provider／host，再做第二个对照；具体名单与支持矩阵待实测。现有 AgentScope 最小适配证据继续有效，不将其扩大为所有框架支持。

UI 使用统一连接引用和候选建议接口；外部 Agent 生成的草稿／候选在同一工作台可见，手动编辑与采用入口一致。后台不要求初次用户选运行框架，平台/适配器高级配置后置。MCP 受限草稿／候选写入已定 S2-a，具体字段与认证待登记，见[初始化通道](INTAKE-AND-INITIALIZATION.md)；发布继续受独立评测与人工审批约束。

## 12. 专家任务与 Harness 的后台增量设计

### 12.1 取舍与最小结构

本节为 2026-10-17 的设计与规划，**尚未实现**。基于当前原型和专家配置、运行治理、能力/上下文三个模块的只读审查，采用“**专家版本内配置 + 服务事项工作面 + 按需证据**”。不建跨专家策略库，不把 Harness 加成第七层，也不重做整套后台。

只把事项塞进配置会混淆默认规则与用户安排；只塞进运行记录又无法管理尚未产生 Run 的义务。因此保留四组导航和三种深度，在专家配置增加一个可选模块，在“运行与验收”增加一个集合入口“服务事项”。详情/编辑仍是对象工作面，不新增一级域。页面映射见[IA §8](S2-IA-NAV.md#8-taskharness-后台增量落点)。

### 12.1.1 前端配置化经验的借鉴边界

对照现有配置化前端实现后，借其**编辑和反馈机制**，不借其**业务对象与字段模型**。以下都是 Loomrise 后续设计约束，不代表相应组件/服务已经实现：

| 可借鉴机制 | Loomrise 的落点与改造 |
|---|---|
| 结构化条件编辑器按字段元数据切换控件，并即时显示规则摘要、数量、不完整项和失效字段 | 蓝图条件只消费当前 `AgentVersion` 可用的字段/事件/算子合同；用版本化字段目录驱动有限类型化表达，按值类型选控件并保留 `0`、`false` 等值类型。字段目录需声明键、标签、值形状、算子、选项/边界、多值规则及预览格式；不在通用渲染器里硬编码业务字段。目录加载失败、字段过期、协议未知或值类型不兼容时保留源值并只读阻止覆盖/提交；确切算子与数量上限仍由 Loomrise 合同确定 |
| 长列表可折叠，空态、校验、删除确认和拖动排序贴近条目本身 | 蓝图列表默认显示目标/触发/状态摘要；展开详情后再编辑。排序按稳定 `blueprint_key` 保存；仅当顺序本身有业务语义时才另存显式顺序，且键盘操作须有拖动替代。删改先显示依赖与在途影响，不能用数组下标标识或因删除定义而清除服务义务 |
| 在使用处显示依赖摘要，按需展开完整内容，并可跳回定义/来源 | 流程、Skill、工具、知识和事项详情显示精确引用及版本状态；完整 Skill/Schema/依据后置展开。显示“已登记、此版本已授权、本次实际披露”各自证据，不以名称存在、连通或绑定替代授权 |
| 编辑器提供搜索式字段/引用插入，并把展示标签与稳定标识分开 | 可借鉴光标处插入、选择器定位和帮助说明，但引用保存为类型化 `field_key`/`blueprint_key`/合同引用；自由文本编辑器只用于表达文本，不承载触发、权限、频控或结果规则 |
| 版本差异、冲突、加载/保存失败状态在提交前暴露 | 同一草稿按稳定 key 展示语义 Diff；显示基准 revision、逐项冲突与保留的人工输入。详情未成功加载时不能保存，过期预览必须重算；“保存草稿”、试用、提交评测、审批、发布及迁移是不同动作 |
| 复杂详情默认折叠、版本身份和修改来源清楚 | 首层只展示当前决策所需的摘要和缺口；L0–L2 展开的是同一对象的依据/证据，不是额外的权限档。历史版本只读，草稿/候选身份、源/执行 AgentVersion 可辨 |

条件配置要明确区分**无蓝图、空条件和条件不匹配**。每个蓝图声明空/缺省条件的效果；默认不得因此自动创建事项或触达候选，只有显式批准的广泛适用规则才可采用，并在模拟中显示影响范围。静态“条件逻辑摘要”只是表达式的纯投影，不声称某个用户命中；“模拟命中/初始化结果”必须基于固定的虚构主体、周期、事件和时钟确定性求值。任意 JSON、脚本或自由文本不能回退成为机器条件合同；未识别协议和字段以只读方式保留，须走显式迁移而非宽松 coercion。

**明确不采纳的演进模式**：把可独立修改/停用的共享策略 ID 挂到 AgentVersion 上，会令已发布版本继续读取可变策略内容；再增加组级和动作级双重关联则制造关系同步、孤儿引用和删除竞态。Loomrise 的任务与主动触达定义必须由当前专家草稿拥有并冻结在 AgentVersion 内，引用点只定位同一份蓝图，不建策略组注册表，也不让另一个页面反向改绑。可复用的跨专家资产限于经授权、显式版本化的知识/Skill/Tool 等依赖合同，具体授权仍由版本和运行检查决定。

不搬用来源项目的渠道、人群字段、策略常量、对象命名或代码；本次源码观察只能说明 UI 交互和客户端处理存在，不能证明后端事务、真实触达、发布原子性或跨用户安全。

| 后台模块 | 增量设计 | 不改变的边界 |
|---|---|---|
| 专家列表/业务概览 | 轻量展示默认任务定义、触达前提和缺口，定位当前版本蓝图 | 定义数不是运行数；初次 FAQ 无须配置任务 |
| 专家配置 | “服务流程”后新增“任务与主动服务”，与其他模块共用草稿、差异和检查 | 不独立发布蓝图；保存不创建用户事项 |
| 流程/处理策略 | 显式引用蓝图、字段、知识与精确工具合同，显示引用与授权的差别 | 路由下一步不等于未来义务；Skill 退出不等于完成 |
| 业务字段/用户上下文 | 字段定义留在配置；用户值、来源、新鲜度和冲突按当前主体展开 | 不把用户值存进 AgentSpec，不新建全量 CRM |
| 依据资料/知识/物料 | 补蓝图/Skill 引用与撤回影响、本次实际加载依据 | 知识与物料不合库；可检索不等于可发送 |
| 工具与连接/业务动作 | 区分平台注册、版本授权和本次实际披露三层 | 不把每个 CRUD 变成 Tool，不提供万能执行器 |
| 服务事项/Inbox | 一个实例服务、两个按角色投影的入口 | 不复制 TODO；接管不会自动取消义务 |
| 试用/运行详情 | 虚构情景预览与 L0–L2 输入/能力快照、尝试和结果追溯 | 模拟不发送，真实运行事实只读 |
| 案例/回放/改进 | 支持运行前事项事件、等待/避让真值、蓝图改动候选 | 事项候选不等于 ChangeProposal，blind 不给作者 |
| 版本与发布/设置 | 结构化蓝图 Diff、在途影响、独立迁移确认；角色化外部协作摘要 | 发布不默迁；设置不授予生产触达/发布权 |

### 12.2 专家版本内的“任务与主动服务”

概览用具名折叠摘要回答“通常要为用户跟进什么、何时提出、哪些必须先确认、Agent 能调整什么”。业务配置提供蓝图列表 → 详情 → 编辑的互斥工作面；详细配置在同一对象内展开合同，而不是另建技术编辑器。历史版本只读，可派生草稿。

| 字段组 | 首层业务输入/反馈 | 按需展开 |
|---|---|---|
| 服务目标 | 名称、目标、内部事项/对外触达、适用对象与服务周期 | 批准的事项类型、稳定 `blueprint_key`、来源与依赖指纹 |
| 何时提出与采用 | 初始化/事件/会话临时提议、前提摘要、采用方式与缺口 | 声明字段条件、occurrence/去重、事件引用；不提供任意脚本 |
| 何时与如何处理 | 计划摘要、可执行窗口及显式时区、依赖是否就绪 | Skill/工具精确引用、确认、预算、超时与结果要求 |
| Agent 的调整边界 | 允许调整项、范围、人工锁定、需要人决定的情况 | 调整次数、耦合变更和停止/失败出口；不捏造默认数值 |
| 怎样算履约 | 完成证据、失败/未知出口、停止条件 | 实际结果引用、送达/业务完成判据与相关固定案例 |

触达类型始终显示“**先形成候选，采用与执行许可分别检查**”，不提供“开启后自动联系所有用户”的开关。空蓝图不影响一般 FAQ 就绪；启用但缺主体规则、完成判据或授权依赖的蓝图，可保存草稿，但不能通过其版本提交检查。临时 TODO 也须匹配本专家版本已批准的事项类型，无匹配仅保留候选。

可执行条件使用有界的类型化表达和当前版本字段目录；字段类型、值形状、算子、选项/边界和摘要格式均来自已批准合同，未知字段/Schema 不能被通用 JSON 编辑器或自然语言说明绕过。自然语言清单仍可用于流程指导、说明和提示，但不承载触发、授权、频控或完成语义。精确算子集合仍受 K0/对应领域合同约束；UI 形态不等于本节替领域提前冻结合同。

同一字段只定义一次：流程/Skill/约束/工具页显示引用摘要和定位链接，不各存一份触发规则。触达节奏约束在蓝图内维护；“必须遵守的约束”只显示有效限制及更严平台上限的引用，不再并列维护第二张独立频控表。人工锁、权限、承诺或结果语义不能借自然语言编辑静默改变。

“创建专家/初始化协助”只创建或整理配置；**“服务初始化”**需要确定 `tenant + agent + subject + service_cycle`。模块内提供“初始化结果预览”：输入明确标记的虚构主体、周期、事件和时钟，显示将登记的内部事项、触达候选、条件未命中、已有事项及阻断原因。重复预览、重连或切版本不应显示成新一轮义务，预览不创建真实 Task、不启动调度。

蓝图新增/删除/重排及助手候选按稳定 key 和基准 revision 比较，不能依数组位置覆盖另一项。人工编辑和过期建议保护沿用同一草稿；新增字段必须显式登记候选范围，不简单扩大现有表达层白名单。蓝图及触达约束变化进入专家候选版本、评测和审批，不因“助手建议”降低风险级别。

### 12.3 “服务事项”与 Inbox：管理具体义务

“服务事项”回答“这个专家为哪些用户还欠什么、现在为何等待、谁可以处理”。默认查询当前专家、操作者有权访问的**全部来源/执行版本的未决义务**，不被正在编辑的草稿过滤；版本是显式筛选项，筛选时保留有其他版本未决事项的提示。主体和服务周期贯穿列表、详情与返回定位，无主体时不落公共默认用户桶。

- 集合分“事项”与“待采用候选”，按主体、目的、负责人、期限、来源、阻断筛选。区分“事项候选”与版本治理的“改动候选”。逾期、取消待确认、结果待核验与人工锁不藏进高级区。
- 行首显示业务名、用户/周期、下一步和等待原因；详情按“业务摘要 → 计划与可调范围 → 尝试/结果/证据”展开。来源版本、当前执行版本和人工锁摘要可直接找到，机器标识与完整历史后置。
- 人工“新建事项”同样走提议/采用与权限检查；有权采用不能补造缺失蓝图、主体或许可。采用失败保留候选及具体原因。
- 合法改期只写实例 revision。展示可调窗口、人工锁和操作理由；过期 revision、撤权或越界时保留输入、显示新旧差异，要求重新判断，不最后写入覆盖。
- 动作为“请求取消”，分别呈现停止中、已确认取消、取消未生效或待核验；替代事项在原事项可靠阻断前保持未激活。耦合调整整批成功或拒绝，外部停止仍需单独证据。
- 未知结果提供“核验结果/转人工”的受权入口，不默认“再试一次”。不提供任意“标记已发送/已完成”、清空义务或强制触达按钮；终态来自领域服务的持久结果。

Inbox 在当前主体下展示同一服务周期/相关周期的事项摘要与详情深链，只提供坐席获准的承接、改期建议或请求取消。会话占用、接管和事项负责人分开；接管不等于已处理所有义务。坐席不能由该入口获得蓝图编辑、真值审定或发布权。用户身份不足时展示范围缺口，不自动跨渠道合并。

### 12.4 能力、上下文与协作：三种深度不等于三档权限

平台“工具与连接”登记稳定能力、连接引用、合同版本/Schema、副作用、沙盒证据及撤销影响；专家版本“业务动作”引用精确合同并配置用途、确认、预算和结果要求。合同更新产生新版本，不能原地改写已冻结依赖；实时撤权仍立即阻断。当前原型连接页主要是模型引用，不据此宣称已有通用工具注册表。

模型侧只保留必要语义入口：系统装配的工作集不是 Tool，拟议 `inspect_context` 有界展开，`manage_tasks(propose/adjust/request_cancel)` 提交受限事项意图；实际业务动作保留独立 ToolManifest。不开放自由 `invoke/execute`，也不把平台内部查询/领取/CRUD 逐一转成模型工具。人能查看完整配置，不意味着模型每轮拿到全部 Schema。

| 披露层 | 人看到什么 | 对应 Harness 证据 |
|---|---|---|
| L0 业务摘要 | 本次目标、必要用户事实/事项、下一步、最小能力与阻断摘要 | 当时工作集、角色/版本/目的、授权摘要和预算 |
| L1 当前任务/能力 | 命中的蓝图/Skill、必要字段、允许调整、所需工具合同 | 实际加载正文、精确 Tool ID/版本/Schema hash、加载/跳过理由 |
| L2 依据与审计 | 来源、冲突、变更、尝试/结果及成本 | 可重建的输入/能力快照和受权脱敏证据；不展示隐藏思维链 |

L0/L1/L2 是信息披露，不是授权开关；运行快照只读，编辑入口明确回草稿或实例意图。**权限撤销、停止、人工锁、未知结果及关键身份缺口不能因折叠或预算裁剪消失**。猜中隐藏工具名、旧 Schema 和披露后撤权均应拒绝；不支持轮内动态工具的 host 显示“本次固定最小授权集合”，扩展时进入明确的新快照/运行边界。

当前主体的用户上下文侧栏从事项、Inbox 或运行详情按需到达：必要字段、来源/事实性质、新鲜度、缺失/冲突和相关义务。配置只管理版本化读取/用途规则，不存所有用户的值；旧运行解释使用当时实际快照，不能拿最新画像代替。更正/forget 展示依赖影响和回执，必要事项重验或等待，不自动抹去义务。无记忆 Provider 不阻断一般答疑，安全前提缺失仍阻断相关动作。

专家经验沿用[专家-用户记忆体系](EXPERT-USER-MEMORY-SYSTEM.md)与“人评与修正”的既有规划，按专家连续治理并检查版本适用性；不混入用户画像、蓝图默认规则或个人记忆。本轮不重做记忆选型和经验写入协议。

外部协作在现有设置内按需展开，分别显示外部作者、后台 Worker、在线客服的协议/技能版本、可读来源、草稿/候选操作、预算、有效期和撤销。默认不开外部协作、Worker 或例行治理；手动路径完整可用。角色切换/连通徽标不授予权限，作者不能调整生产事项、触达、写业务、修改真值或发布。不新增初始化框架选择器或“Harness 配置中心”。

### 12.5 试用、验收、版本与在途影响

试用台沿用同一视图，在普通答疑旁按需进入“服务情景预览”：虚构主体/周期、固定时钟与事件序列，比较初始化、候选采用、等待、允许调整、取消/未知和工作集。用户不必配置 cron；“推进模拟时钟”不连接调度器。预览只能使用模拟业务工具，不能发送外部消息。

运行详情关联 TaskAttempt、源事件和两种版本，分开展示计划、执行、生成、发送/送达、业务结果与取消确认。没有 Run 的初始化、采用和计划冲突以事项/候选/事件建案例，不伪造 Run。回放固定时钟、主体、周期、occurrence、revision、许可/占用及回执序列；正确等待/避让也是真值。质量和成本按同条件实测，纳入 Schema/结果 token、发现往返和失败成本，不预设渐进披露必定省钱。

除拒绝/取消/未知外，固定一个内部核查事项的正向夹具，展示“证据引用 → 确定性模拟领域裁决 → 事项结果投影”，结果与来源/执行版本关联；正式服务联调再替换为持久实际结果。原型只显示模拟裁决，不增加任意“标记完成”按钮，也不以该夹具宣称调度执行已实现。

版本页增加真正的“基准版 ↔ 候选版”结构化 Diff，蓝图按稳定 key 对齐，展示目标、触发/采用、完成判据、允许调整和依赖变化，突出权限/频次/承诺风险。草稿编辑日志不等于版本 Diff。

发布预览增加“在途影响”：新增/修改/删除蓝图、候选、等待与运行事项、受影响主体/周期及依赖，未获完整读取或影响未知明确写“未知/不可计算”，不当作 0。展示影响计算的版本、实例 revision 与权限基准，基准变化须重算。默认只更新指定入口对后续新请求/新服务周期的版本选择，**不迁移既有事项，也不因换版重新初始化同一周期**。

发布批准与迁移授权/确认分开。获权人员在明确对象范围内选择保留仍安全的旧执行版本、迁移重验、暂停或人工处理；不增加第二套蓝图发布链，不给编辑器“应用到全部用户”按钮。运行中不可切版本；删蓝图不删除义务；恢复为草稿不冒充线上回滚。回滚不重置频次、退订、取消、删除或外部结果事实，失效旧权限不能复活。
