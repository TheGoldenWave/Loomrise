# S2 范围讨论记录 v0.6

状态：**范围讨论中；以下为已确认的产品方向，不代表已设计完成或已实现**。2026-09-28。

本文件增量记录 S2 人机协同与受控改进的范围决策。阶段总目标与退出 Gate 仍以[验证路线](ROADMAP.md)为准；对象和权限边界见[架构与对象权威](ARCHITECTURE.md)。范围讨论已收口，设计展开见[S2 设计草案](S2-DESIGN.md)。

## 已确认方向

1. **发布责任：S2 采用版本级人工审批。** 系统可汇总低风险候选及其验证证据，人在一次审阅中批准或拒绝整个候选版本；高风险变更单独逐项审批。预先授权范围内的自动发布是后续探索方向，不属于 S2 承诺。
2. **候选修改范围：先覆盖表达与执行策略。** 系统可提出措辞、示例、重复内容整理、任务步骤、澄清顺序、Skill/SOP 和有限检索参数的候选修改。对硬规则、工具权限与副作用、价格或业务承诺、业务结果语义的修改不得进入该自动候选范围；以后是否扩大为独立的待审建议，另行决策。
3. **人的坏例标注：确认业务真值，不要求配置归因。** 标注者确认期望业务状态、必须做与禁止做的动作；原因可选填。系统负责先分析运行证据并建议失效环节与修改位置，但其归因不代替人工审定的真值。需要持久副作用和结果 ID 的案例仍按[产品定义](PRODUCT.md)中的评测规范补足。
4. **坏例来源：人工标记与系统提名并行。** 系统可根据可观察的运行失败、反复纠正或配置冲突等信号提名可疑案例；提名不等于确诊。进入正式评测集之前，业务真值仍须人工确认。
5. **提案组织：按共同原因归并。** 系统把相关案例及运行证据关联到一处尽可能小的候选修改，并保留每个来源案例的追溯关系。允许候选删除或合并重复的表达与执行策略内容，而不只是追加配置；必须用旧案例回归检查退步。
6. **提交校验的阻断权：确定性优先。** 硬规则冲突、越权或缺少必要证据等确定性问题阻断版本提交；模型识别出的重复或语义冲突先作为建议，交由人审阅，不直接阻断。
7. **审批证据与差异展示：版本级可审阅。** 审批页至少展示改动摘要、关联案例、旧版与候选版的配对回放对比、硬规则检查结果和成本变化；版本差异采用类似 VS Code 的 diff 形式，详细运行轨迹按需展开。
8. **编辑与审批责任：区分记录，按团队规模加强。** 系统分别记录编辑者与审批者；单人项目允许自审，多人团队可启用强制复核。确定性的安全门禁始终有效，不因单人自审或人工豁免而绕过。
9. **评测门槛：人登记初始值，阈值本身受版本管理。** 系统在跑候选版之前读取已登记的阈值，不得在运行中为了让本次通过而临时放宽；系统可以提出阈值调整建议并附证据（如机评与人工校准的一致率、误报率、成本漂移），但阈值改动必须与候选版本走同样的审批流程。硬规则违规、关键退步和缺少必要证据**不是评分项**，而是一票否决项，不进入打分阈值体系。
10. **回滚：确定性红线自动回滚，其余由人决定。** 这里「发布」指候选版本成为场景当前生效的版本。硬规则违规、重复写入、结果缺失和关键退步等可确定性判定的信号命中时，系统自动把生效版本切回上一个已发布版本并告警；软质量下降与成本漂移由人决定是否回滚。自动回滚只回退到上一个已发布版本，不做跨版本搜索或自动修补；回滚产生带证据的事件记录，人可以推翻，推翻同样需要审批。
11. **风险分类：内置默认 + 场景级覆盖，默认只能收紧，放宽以带时限的临时授权实现。** 系统内置一份低风险/高风险分类基线，场景可以在默认基础上把某类内容**升级**为高风险；内置高风险项**不能**被永久降级为低风险。业务在不同时段关注点不同，因此允许放宽，但放宽必须以**临时授权**形式存在：显式写明有效期、理由与适用范围，到期自动恢复到默认分类，不续期即失效。放宽只影响「由谁审批、是并入版本审批还是逐项审批」这一层，不影响确定性安全门禁和一票否决项。所有覆盖与放宽动作都要审批并留证，审批页需显著显示当前是否处于临时放宽窗口。
12. **策略档位（Policy Profile）是一等对象。** 一整套「风险分类 + 阈值 + 审批要求」打包为命名档位（如日常档、大促档、风控收紧档），可复制、可 diff、受版本管理；切换需审批并留证，可携带有效期自动回落。临时放宽不再是配置上的一次性补丁，而是「切换到某个档位 + 到期时间」。S2 alpha 只预置两档（默认档与一个收紧档），先跑通「切换 → 审批 → 生效 → 到期回落」链路，档位数量后续扩展。
13. **档位切换权只属于人。** 系统可以提议切换并附证据，但不能自行切换，**收紧方向也不自动执行**。允许「预设切换时间」：人提前设定切到某档与切回的时刻，到点由系统执行；这属于人工决策的延后执行，不等同于系统根据运行信号自行决定切档。
14. **预设切换到点直接生效，但带基线校验与观察期。** 授权时记录基线快照（当时生效版本、阈值、资料与工具版本）；若到点时这些已发生变化，则不直接执行，转为待审批项由人确认。切档生效后进入强制观察期，确定性红线命中照样触发自动回滚，预设切换不豁免安全门禁。
15. **评测样本分三层，人工真值集中在黄金集。** ①**黄金集**：人工审定业务真值，稳定、可复现、受版本管理，只用于一票否决项与关键回归；②**待确认池**：系统提名的可疑案例，人确认业务真值后才升入正式集；③**盲测集**：从运行中抽样，大部分只做确定性规则裁决（越权、重复写入、结果缺失），仅对涉及业务语义的部分抽检人工真值。回放报告必须写明所用案例集的版本，否则历史结论不可比。
16. **黄金集是业务真值的锚点，受控演进，可归档但不可静默淘汰。** 规模按 50+ 例规划，覆盖成功路径、资料缺失、拒绝、重复提交、工具失败、超时未知、取消点、越权尝试、承诺/敏感边界与上下文预算等维度。它的变更分三类——新增、真值修正、淘汰归档——每一类都要走审批并留证。**真值修正只能源于业务判断变化或当初标注错误，不得因为候选版输出不同而回填真值。** 淘汰只能因为业务规则变更、场景下线、案例与当前配置不再相关或被更完整的案例覆盖；**通过率高不构成淘汰理由**，简单案例是防止退步的哨兵。淘汰转为归档状态，保留历史判定，不再参与门禁。
17. **定位：受控自进化，而不是人在回路的逐轮盯守。** 系统在真实或模拟运行中收集运行轨迹与人工反馈，把可复用的方法整理为候选 Skill、把事实归入可审阅的资料，经评测与人工审批后才进入生效配置；表现退化时可回滚。三条边界不因运行频次而松动：**经验不会因出现次数多就自动生效；事实不会自动升级为知识；能力更新不会立刻全量。**
18. **能力演进路线的对应关系。** S2 只覆盖「经验技能化」与「评测驱动的自进化」两级：前者对应受控的 Candidate Skill/ChangeProposal，后者对应版本化评测、审批与回滚。任务内适应由 S1 的渐进式上下文与确认点部分覆盖；长程连续运行属于后续服务端能力；跨会话记忆已在[产品定义](PRODUCT.md)中划定为带来源、有效期和删除入口的上下文，不与知识库互相自动升级；多 Agent 集体进化不是本项目的目标。
19. **候选可包含新建、拆分与合并 Skill。** 系统可以提议这些结构性改动，与表达层改动走同一审批；Skill 的目标、适用条件、下一步、退出与转人工条件成为必填字段并做 Schema 校验；必须通过黄金集与盲测。Skill 不授予权限，新建 Skill 不获得任何新权限。
20. **人工编辑不绕过门禁。** 人在工作台里的编辑也生成候选版本，过黄金集与盲测回放、走审批后才生效；不豁免，也不额外加码。为不牺牲手感，人工编辑可先跑黄金集核心子集，完整回放异步补，退步照样触发回滚。审批页标记改动来源是「人」还是「系统归纳」，两者的失败模式不同，审批者有权区分。
21. **在线灰度分流纳入 S2 设计范围。** 不做百分比分流的原定边界取消：S2 从一开始就要为「候选版只作用于一部分流量」留出结构，包括分流单位、比例配置、灰度期的观察指标与止损、以及灰度证据的归属。它牵动回放对比、回滚粒度与证据口径，事后追加成本很高。
22. **灰度的关停与扩量只由人操作。** 系统在灰度期只负责告警与呈现证据，停止灰度、恢复灰度和扩大比例都由人决定。分流单位按会话或用户稳定划分，保证一次会话内 `AgentVersion` 不变，避免破坏[验证路线](ROADMAP.md)中「同一请求使用同一版本」的 Gate。灰度观察数据**只进盲测集与待确认池，不进黄金集**，避免带噪声的真实数据把业务真值带偏。
23. **灰度期红线命中：自动停止扩大暴露，但不切换版本。** 确定性红线命中时，系统自动把灰度比例降到 0（不再有新流量进入候选版），已在处理中的请求跑完不打断；是否回滚、是否恢复灰度、是否扩量，全部由人决定。这与第 10 条不重叠：自动回滚只处理「已成为全量生效版本」的情况。
24. **提名信号：确定性信号 + 行为异常信号，不含模型自评。** 确定性信号包括硬规则命中、工具失败/超时、未确认写入、结果缺失与重复写入；行为异常信号包括多轮自我纠正、澄清轮次异常、上下文加载异常或预算截断、成本突增、同类请求输出明显偏离。**多轮自我纠正只说明某处不一致，不等于限制不足**，归因仍由系统分析、人确认。三条约束：提名必须附可观察证据（哪一轮、命中哪条规则、加载或跳过了什么、成本多少），不能只给可疑分数；人判定的误报要被记录为提名器的负样本；提名器本身要有版本、阈值与治理，其调整走和候选版本相同的审批。

## S2 alpha 明确不做

以下为已确认的边界，用于防止范围膨胀：

1. 真实外部写入：仍用模拟工具与结果 ID，不接生产系统。
2. 真实渠道：IM、电话 / PSTN 一律不接。
3. 多租户、登录与权限体系（属 S3）。
4. 公开 Demo 与公网部署（属 S3）。
5. 自动发布：任何候选都需人工审批，预先授权范围内的自动发布只是后续方向。
6. 系统自动切换策略档位，包括收紧方向。
7. 阈值自动校准：系统只能提出调整建议。
8. 多 Agent 编排与集体进化。
9. 跨会话长期记忆优化：会话记忆仍是带来源、有效期和删除入口的上下文。
10. 插件市场与第三方 Skill 安装。
11. 在线训练、微调与模型权重改动。
12. 由模型独自裁定业务真值：机评只评软质量，必须由人工校准。

## 仍待细化

- 内置高风险清单的初始项与增减：目前为硬规则、工具权限与副作用、价格或业务承诺、业务结果语义四类，是否加入身份与授权范围、外部写入等仍待确认。
- 临时授权与策略档位的有效期上限、是否允许续期，以及窗口期内的额外证据要求。
- 观察期时长、判定信号与超期处理。
- 多人团队强制复核的具体配置方式。
- 提名器的初始信号清单、误报反馈如何反哺，以及案例优先级排序。
- 各场景质量与成本阈值的初始值怎么定，以及首批基线的采集方式。
- 盲测集的抽样方法、抽检比例，以及确定性规则裁决具体覆盖哪些维度。
- 黄金集的分层执行方式：是否区分「每次候选必跑」与「关键发布才跑」，以及两层的规模。
- 灰度分流的设计细节：分流单位（会话 / 用户 / 入口）、比例由谁定、灰度期止损权、以及灰度观察数据是否只进盲测集与待确认池而不进黄金集。

上述方向不改变 S1 退出 Gate，也不意味着自动发布、真实外部写入或生产适用性已经得到验证。公开案例只使用原创虚构或明确获授权的材料。
