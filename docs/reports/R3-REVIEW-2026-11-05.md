### 3.3 走查发现的问题

#### P1-1 编排画布在首屏不可见

- 现象：进入「更多设置 → 服务端版本 → 流程 → 编排图」，画布容器 `top = 834px`（1440×960 视口），节点 `top = 989px`。用户必须滚动近一屏才能看到图；首屏只有标题、说明和工具栏。
- 证据：`CANVAS GEO {"host":{"top":834,"h":520},"node":{"top":989},"viewportH":960,"docH":1945}`；截图 `canvas-scrolled-1440.png`（滚动后才见节点）。
- 影响：R3 的核心交付是画布，但它在产品里的首次呈现是「看不见的画布」。骨架页（`#/flow`）另有静态示意图，反而更像主入口。
- 建议：把画布提到 tab 内容首屏（压缩「版本路由」说明为一行或折叠），或让进入「流程」tab 自动滚到画布；同时评估 `#/flow` 静态图与画布的关系，避免两个「流程图」。

#### P1-2 `orchestration-browser-check.js` 已与新实现脱节，画布浏览器证据不可复现

- 现象：按官方脚本原样复跑（1440×960、course-demo、填 R1 扁平清单），卡在 `waiting for .react-flow__node`。页面先提示「画布无法解析当前草稿」，随后抛 `TypeError: Cannot read properties of undefined (reading 'condition')`，画布与「编排图/单元清单」工具栏一起消失。
- 根因（已定位到代码）：`orchestration/model.js` 的旧清单投影（无 `orchestration` 键时）构造的 edge **不含 `edgeConfig`**（`model.js:118-121`），而 `canvas.jsx:81` 起直接读 `edge.edgeConfig.condition / .window / .from / .to`。旧格式必然 TypeError。
- 影响：R3 计划与收口报告都把「画布浏览器回归通过」当作已交付证据；当前代码下这条证据**无法复现**。且落地表现是崩溃，不是脚本声称的「优雅降级」（UI 文案说有提示，实际提示后组件即崩）。
- 建议（二选一，需开发决策）：① 把该脚本的夹具改为 `unit-graph-v1`（我已用合规图验证画布本身可用）；② 让旧清单投影返回 `edgeConfig`（或把 `canvas.jsx` 的读取改为可选链 + 明确降级），保证「不可解析」时不崩。

#### P1-3 客服统计页直出工程术语

- 现象：运营者面向的「客服统计」页出现 `Run 数`、`input tokens`、`customer.reception.started → customer.reception.finished`、`server_event_wall_clock`、`记录 Provider 用量`、`T03`。
- 影响：违反项目自定的「中文优先」规范（[UI 走查计划 §2](../CONSOLE-UI-WALKTHROUGH-PLAN.md) 明确要求 Token/Trace/revision 等「首次中文解释，普通路径不显示内部标识」）。统计页是策略运营的日常页面，不是技术详情页。
- 建议：指标名与事件名改为中文业务词（如「对话轮次」「答复已生成」「接待处理时长」「计时口径：服务端事件时间」），原始事件名放具名折叠区。

#### P2-1 工作台收件箱与真实收件箱双轨

- 现象：工作台 `#/inbox` 是本地模拟（筛选为 全部/AI 接待/待人工承接/人工接待，**无「未读」**）；真实收件箱是独立页 `loomrise/customer_inbox.html`（筛选为 全部/待接管/由我接管/未读，含未读投影与提醒）。
- 影响：R3 计划 §17 描述的「全部／待接管／由我接管／未读筛选」属于后者。工作台导航叫「会话收件箱」，用户无法从界面知道两者不是同一个东西。
- 建议：在工作台收件箱页显著标出「本地模拟 · 真实收件箱见本机服务页面」并提供跳转，或直接把真实收件箱整合进工作台。

#### P2-2 英文状态直出

- 现象：收件箱详情「业务请求状态 **waiting**」。来源 `views/surfaces.js:109` 直接渲染 `active.requestStatus`，无中文映射。
- 建议：加状态词表（waiting → 待处理 / 未解决…），与 `inboxFilter` 的标签保持一致。

#### P2-3 试用台快照修订号与服务端不一致

- 现象：服务端 revision 已到 r4（联系页显示「草稿 r4」），试用台「当前试用快照」仍显示「配置 草稿 r2」。
- 判断：大概率是前端本地草稿 revision 与服务端 revision 两个口径（前者是库内计数）。若如此，属**口径未标注**而非数据错误，但会误导用户以为在试旧版本。
- 建议：明确标注「本地草稿 r2 / 服务端 r4」，或统一取服务端 revision。

#### P2-4 画布节点摘要显示「条件结构未识别」

- 现象：合规 `unit-graph-v1` 图中，退出端口 `completion.deterministic = {event:{event:"timeout"}}`（该形状被 `conditions.js` 的 `readCondition` 支持），节点摘要仍显示「done · 条件结构未识别」。
- 判断：疑似画布把整个 `completion` 对象（含 `deterministic` 外层）传给 `conditionSummary`，而它只接受条件本体。**未完全定论**，需开发复核传参位置。
- 建议：核对 `canvas.jsx` 节点摘要的传参；若属实，属 P2 文案降级（不崩、但所有事件型完成条件都显示为未识别）。
