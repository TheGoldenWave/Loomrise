## 1. 交付目标与能力基线

Loomrise 计划交付完整的网页客服应用，同时提供受控业务执行、版本验收和持续改进。交付者可以配置客服入口和授权知识，接入业务工具，让访客与人工使用同一个客服应用，并把整套单租户应用部署到自己的云。

网页客服的覆盖基线取 Knocket 已提供的能力。其公开教程和产品页描述了 Web Widget、Contact Page、Mobile Widget、知识答疑、Inbox、人工接管、Telegram 和 Email 集成。来源范围见下表，核验日为 2026-10-14。官方文档主张只用于确定建设范围，不能成为 Loomrise 的实现证据，也不等于所有功能都已在本次调研中实测。

本基线有三条边界：

- WhatsApp、Instagram、Messenger、Facebook 的消息集成不计入 Knocket 已提供能力基线。Widget 的快速联系图标是外链入口，外链与消息桥接分别验收。
- TRTC Conversational AI / Voice Agent 是另一产品。它的实时语音、打断和工具扩展不补入 Knocket 网页客服基线，Loomrise 网页语音按自身合同独立建设和验收。
- 功能覆盖采用等价行为，不要求复制品牌、页面、免费承诺、配额或供应商内部实现。来源格式、额度和限制必须在 Loomrise 规格中明确，并通过样例验证。

### 1.2 独立物料库与受控发送（新增产品范围）

业务录入常发图片、视频、文档及来源授权、有效期、可用专家/环节、标签和简介。物料库在知识域内独立导航：业务知识提供事实，物料提供可交付文件；经业务审阅的简介可以检索定位资产，但不自动作为业务答疑事实。图片/视频压缩、封面、OCR/转写/内容理解形成可核验的派生文件或简介候选，业务可直接人工维护简介，不要求等待 AI。

人工选择原件或可用派生文件；Agent 自动发送默认关闭，受物料许可、批准版专家策略、请求/适用条件、数量/渠道限制及当前 AI 会话占用约束，发送前重验版本和代次。撤回、过期、权限/范围或版本变化及人工接管使旧选择失效；消息冻结文件与简介快照，发送/送达/问题解决分别留证。

此项是已确认的 Loomrise 产品需求，不把物料处理和 Agent 自动发送归为已实测竞品能力。真实后端仍未实现；本轮前端缓存原件和元数据，压缩/理解与发送为明确仿真，详见[物料专题](MATERIAL-LIBRARY-AND-DELIVERY.md)。S2-a 建资产/授权/版本与最小人工文件交付，S2-b 补真实后处理、审阅简介检索和渠道附件，S2-c 验收自动发送的权限/占用/幂等/回执。

### 1.3 模型供应商与协议

模型连接采用后端适配器和凭据引用。OpenAI Chat Completions 兼容接入、供应商预设与当前 S1 Coding Plan Responses 路径是不同的验证对象。预设用于填入默认字段，不能证明供应商接口、模型工具调用、流式、限额和错误行为都可用。

S2 先验证首个对话模型适配及知识检索组合，再逐项增加预设。OpenAI、DeepSeek、MiniMax、混元、Moonshot/Kimi、智谱 AI、xAI Grok 是待验证的预设候选，不是现已支持清单。Embedding 的托管或自配置方式、检索供应商、语音 STT 和 TTS 组合均需另行选型与验证；S1 的既有默认模型和版本钉不因此改变。

## 2. 在客服应用之上增加业务执行与治理

客服应用由入口、Inbox 和人工接待构成，交付工作台由配置、接入、试用、证据、验收和发布构成。它们服务不同使用者，使用同一已发布 `AgentVersion`、`ServiceRequest` 和 `RunEvent`。

一线客服在客服应用中接管、回复和反馈，策略运营在交付工作台中审定案例、评价质量和提出改动。实时接管事实回流为事件，一线反馈是案例提名，不能自动成为真值。页面编辑、连接测试或知识索引完成也不能自动获得发布权限。

### 2.1 保留六层权威

| 需要增加的能力 | 原有权威 | 必须保留的约束 |
|---|---|---|
| FAQ、URL、文件引用与知识快照 | `ContextSnapshot` | 来源、授权、有效期与撤销；检索内容不自动升级为业务事实 |
| 访客入站、转人、人工回复、恢复 AI | `RequestRouting` 与 `RunEvent` | 主请求、身份、任务代次与占用状态可追踪，渠道不拥有业务终态 |
| 答疑、澄清、转人工与回复风格 | `Skill/SOP` | 策略不授予权限；摘要和草稿是待审内容 |
| 禁答、停止、权限和确认 | `HardRule` | 确定性模型外裁决，模型评分不得覆写 |
| 文件物料检索与发送 | `ContextSnapshot` 与 `ToolPolicy` | 已审摘要用于定位资产，不授予发送权；重验资产/派生/策略版本、范围、有效期、会话占用与代次，发送回执独立记账 |
| 预约、工单或其他业务动作 | `ToolPolicy` | 执行前重验权限、确认版本、参数、预算和幂等 |
| 答疑结果、人工处理与业务写入结果 | `Outcome` | 生成、送达、问题解决分开；写入需持久结果与适用的外部结果 ID |

FAQ 是授权资料的受约束客服答疑。访客问价格可以完成一次有引用、零写入的答复，不必创建工单。消息生成只证明模型产出，送达由消息或播放回执证明；问题解决按该场景已登记的验收规则、用户确认或实际业务证据判定。答复已送达或被标为 AI Resolved，不能单独证明用户问题已经解决。

会话与业务请求分别编号。一个访客线程可以依次包含咨询、预约和后续问题等多个 `ServiceRequest`，但同一轮只推进当前主请求。按渠道身份恢复会话时，需要保留线程、请求、运行、版本和消息的关联，不能把整个会话当成一个已解决业务任务。

### 2.2 从 S2-a 开始设计的治理

持久化基础、身份与最小角色隔离、凭据后端保管、版本引用、网站来源限制、来源授权、预算与结果证据在 S2-a 就进入合同和测试。完整业务写入与改进闭环在 S2-c 验收，公网发行与完整认证生命周期在 S3 验收，不能在前期临时关闭这些约束。

S2-a 计划实现最小沙盒版本发布，沿用 `AgentVersion`、`Release` 和既有发布权威。发布先冻结配置与引用，完成来源、权限和固定样例检查，再经人工批准，留下明确的沙盒环境与版本记录。Widget 和后续 Contact Page 只能绑定批准的指定沙盒版本，草稿保存不能直接改变运行入口。S2-c 才补齐批量配对评测、改进提案、审批发布与回滚全链路；S3 才验收公网与用户自有云发行。

知识摄入与知识使用分开。摄入记录来源权利、版本、处理状态和失败原因，撤回后停止检索并使受影响的版本或评测待重验。URL 读取限制来源范围，文件解析限制类型、资源和执行能力。平台不得执行上传材料或模型生成的任意脚本。

人工接管同时处理 AI 回复占用、正在执行的业务动作和待确认动作。超时触发占用与恢复检查，满足已登记条件后才能切换接待所有权并使旧占用失效。人工与 AI 发送或写入前都核验当前占用代次，不能据静默认定人工已完成、取消已确认，也不能自动重启有副作用的业务请求。恢复时按最新请求代次、来源、权限和确认状态重新校验，过期后台结果不得再次发送或写入。

业务工具在离线回放中使用模拟实现。真实授权沙盒写入单独验证成功、拒绝、错误、超时未知、重复提交和执行端取消确认；已写入后的撤销能力逐工具声明，不把取消播放当作撤销预约。

持续改进保留不可变证据、独立失败归因、受限 `ChangeProposal`、固定测评集、人工审批、发布与回滚。优化器不能静默修改权限、金额、承诺、硬规则、工具副作用或结果语义。既有评测方案的已确认决定和待决策参数见 [S2 评测门禁提案](S2-EVAL-GATE-PROPOSAL.md)。

### Task 与用户上下文的新增产品方向（2026-10-14，规划未实现）

运营预配置策略、Agent会话TODO和人工安排共享Task体系，TaskItem协调未来服务义务，实际请求/结果继续由ExecutionService持有；允许范围内调整实例，改变策略/权限/承诺仍经评测审批。独立模块统一用户记忆、画像与上下文治理，保留来源、主体、用途、有效期与更正/遗忘联动。

此范围属于Loomrise增强能力，不声称为Knocket已有功能。接口、UI和具体分期为[联合计划](TASK-MEMORY-INTEGRATION-PLAN.md)中的建议；原客服覆盖矩阵及S1证据不改。建议先内部任务/只读记忆，再授权主动服务沙盒，电话仍按S4独立Gate，新增架构不能提前证明真实主动触达已支持。

## 3. 阶段依赖与退出 Gate

按 S1、S2-a、S2-b、S2-c、S3、S4 验收。S2-c 的合同设计和案例准备可以提前，但不得据此跳过 S2-a 持久化基础或 S2-b 客服能力覆盖。阶段没有日期、工时或速度承诺。

S2-a 的重启恢复必须遵守[Task 重启裁决表 §7.1](TASK-SYSTEM-DESIGN.md#71-重启恢复裁决表2026-10-21-定)：本地 `running` 旧尝试记失败并保留中断事实；业务事项获准重试时创建新尝试，旧执行者不得复活。耐久 Adapter 的证据细化纳入既有父 Gate，不因此新增阶段退出条件。

| 阶段 | 依赖与范围 | 退出 Gate |

## 4. 用户自己的云与部署生命周期

部署目标是用户选择自己的云资源和区域，使用 Loomrise 的版本化发行包与模板完成可复核的安装。腾讯云、阿里云优先作为首云候选，AWS、Azure 作为后续候选。具体产品、资源组合和首云顺序待真实部署比较，不保证一键完成、固定速度、免费额度或生产就绪。

S3 先提供标准 Linux 和容器发行，再验证一个云模板。S4 才把模板扩到其他主流云。应用业务合同不绑定云 SDK；云模板只管理部署资源、配置和生命周期，不能另建业务状态或隐式提高工具权限。

### 4.1 部署体验

部署流程必须提供可审阅的资源与变更结果：

1. 用户选择发行版本、云、区域与单租户模式，先查看运行需求、资源清单、网络依赖和费用来源。
2. 预检确认资源权限、域名与 TLS、端口、存储、外部模型与渠道可达性。缺失项给出具体修复入口。
3. 用户确认创建或变更云资源后，模板安装固定构件，建立持久数据与密钥引用，并创建初始管理员。
4. 健康检查先验证系统依赖，再用虚构数据完成客服和业务沙盒流程。只出现登录页不能记部署完成。
5. 交付页面给出管理地址、访客分享入口、Widget 安装代码、渠道回调要求和部署诊断；代码和分享页不含后台凭据。
6. 用户可以导出配置与授权清单，在新实例恢复。凭据需在目标环境重新授权，不能随场景包搬运。

### 4.2 生命周期要求

| 环节 | 必须验收的行为 |
|---|---|
| 安装与重试 | 部分失败可诊断；再次执行不重复创建资源或覆盖现有数据；资源标识和步骤状态可追踪 |
| 认证与密钥 | 管理员、配置者、审批者与一线坐席权限明确；密钥仅在受控后端或密钥服务，支持轮换和撤销 |
| 数据与备份 | 数据目录或托管存储持久化；版本、请求、事件、幂等、知识引用、物料原件/派生、简介/权限版本与历史附件快照按保留策略备份；在干净实例恢复并校验 |
| 升级与回滚 | 固定发行版本，变更前备份；数据库迁移可检查；声明可回滚边界；已有请求与已发版本不被原地改写 |
| 停用与删除 | 停止入口与授权渠道，禁用工具和外部连接；保留或删除由策略决定；只删除应用不能默认为云资源与费用已清理 |
| 诊断与用量 | 显示发行版本、连接能力、健康状态、失败步骤和费用来源；脱敏诊断可导出，模型用量与云账单分开 |
| 迁移 | 导出与导入保持合同、版本和来源关系；云更换与数据库迁移有校验结果；不带走未授权资料或密钥 |

单租户部署不等于租户隔离已验证。用户云也不自动证明数据驻留、供应商训练用途或网络安全；须按所选服务、区域、数据流和合同说明实际边界。
