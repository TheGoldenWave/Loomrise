## 0. 结论

1. **既有本地原型不重搭，本轮按增量规划推进。** 6 域/17 页/23 面是早期工作台规格，不是当前四组原型或产品全部页面；当前基础和 Task/Harness 新工作包分别核对本轮报告与 §8，不从“IA 基本定稿”推断服务已经交付。
2. **"前端先行、后端反推"成立，但有一个前提**：必须**先把数据形状钉死**（字段级规格 + API 契约），否则反推出来的是两套。
3. **早期主要缺口是字段级规格与数据契约**：`AgentSpec` 本体、草稿版本容器、`ChangeProposal` 与 HTTP API。新增 Task 后还须主体/服务周期、稳定蓝图 key、实例 revision、事件与能力快照、迁移/核验用例等合同，完整增量见 §8.1；不能继续称“只有两处”。
4. **本轮新增三条设计约束（§3）会改到 IA-NAV §4.3.2 三 tab 的内部结构**，必须在定稿前一并决定，否则骨架与设计稿要改两遍。
5. **另有一处必须先定的形状问题**：「硬性限制」（`HardRule`）当前的表达能力**只支持"调用某工具且参数等值"**，覆盖不了跨垂直场景的多数规则需求（10 类需求形态里 8 类表达不了）。表达模型见[硬规则表达模型](HARD-RULE-MODEL.md)，列为 **K0**——**它比 D3 更靠前**，因为规则的字段形状是 D3 里「边界 tab」那一节和 K1 `AgentSpec` 的共同输入。

## 2. 启动顺序

### 2.1 横向前置（引自 IA-NAV §5.1）

T0 本文档定稿 → **T1 前端骨架与路由** → **T2 只读 API 壳** → **T3 草稿版本读写**。

**补一条 T0 的产出定义**：T0 的产出**不只是**"IA-NAV 升 v1.0"，还包括 **D3 字段级配置规格**落定——否则 T3 没有输入。

### 2.2 起步路径（建议）

```text
0  IA-NAV 定稿（关 32–35 / 37–39）                          ← 纯决策，无代码
1  K0 硬规则表达形状（六问裁决 → 定 `when`/`verdict`/`enforce`）  ← 只影响「边界」一节，但拖住 D3 与 K1
2  D3 字段级配置规格（三 tab 逐字段表）                      ← 设计稿与契约的公共输入
3  K6 API 契约（TS type + mock）                            ← 一个文件锁死数据形状
4  T1 骨架（路由表派生菜单 + expertScoped 页壳 + 指针路由）    ← mock 下即可点
5  T2 只读 API 壳（接 S1 真实数据）
6  T3 草稿读写（真正的后端工作量集中在此）
```

**为什么 3 排在 4 之前**：菜单是路由表的派生物（IA-NAV §1.1-6，菜单与路由写两遍必然漂移），而路由表要引用数据形状。先钉数据形状，骨架才不用返工——这正是"前端反推后端"唯一正确的方向。

**为什么 1 排在 2 之前**：D3 要产出「边界 tab」的逐字段表，而字段表的样子由 K0 的规则形状决定。**顺序反了会白写一遍**——若先按现行三值 `behavior` 出字段表，K0 一落地字段表就要重来。

页面铺开顺序（B1–B8）与交付边界见 IA-NAV §5.2，本文不重复。

## 3. 本轮新增设计约束（提案，待确认）

> 来源：一轮针对「**测评 / 审计 / 自迭代** 与 **运营持续参与**」的内部设计审计（对照成熟业务 Agent 中台的形态，方法已抽象）。
>
> 这三条**会改到 IA-NAV §4.3.2 三 tab 的内部结构**，必须在 T0 定稿前一并决定，否则 T1 骨架与三 tab 设计稿要改两遍。

| # | 约束 | 影响面 | 建议 |
|---|---|---|---|
| **A1** | **内容层与策略层分治** | 三 tab 内部结构 + 草稿机制 | 三 tab 内部再分 **`locked` 段**（合规红线 / 承诺边界 / 品牌底色）与 **`mutable` 段**（话术 / 示例 / 优先级）。**内容级改动（mutable 段 / 示例 / 知识）走"即时保存 + 异步回放告警"；策略级改动（locked 段 / 硬规则 / 权限 / 承诺）走"草稿版本 + 提交冻结"。** 现行"人工编辑一律不绕过门禁"对**日频内容劳动过重**，实际会被绕过 |
| **A2** | **审计要能回答「责任边界」** | `RunEvent` + 数据看板 + 运行详情 | 增加**归因分层**：合理静默 / 人工抢答 / 业务禁回 / 路由失败 / 工程失败。否则运营看到"没有回复"却看不到原因，会把合理静默误判为质量失败，优化方向被带偏 |
| **A3** | **补三个闭环件** | 变更域 + 验收域 | ① **被拒提案库**（拒绝理由 + 触发样例 + 影响范围；候选生成前先检索，避免重复提交已知失败方案）；② **改动量预算**（`edit_budget` + `touched_segments`，让回放退步可归因）；③ **评测体系自身的迭代闭环**（缺口发现 → 扩样 → Rubric 版本），防"只奖励旧标准定义过的能力" |

### 8.3 接现有原型时的必改面

实现不得只加 renderer。须同步显式模块/候选白名单、fixture 默认值、旧浏览器存储版本与缺省迁移、草稿 revision/历史保护、稳定 key/引用校验、变更使检查失效，以及可取消/迟到/冲突状态。条件编辑器只消费版本化字段/事件/算子元数据；不得把自由文本、任意 JSON 或脚本当作可执行规则合同，也不照搬另一业务的字段列表、表达上限和阈值。字段目录缺失、加载失败、引用已失效或表达版本不支持时，以只读方式保留原值，阻止覆盖及相关蓝图通过检查；不得宽松转换 `0`/`false` 等基础值。无蓝图、空条件和不匹配须有不同语义，默认空条件不自动扩大到全体主体。

新增 `tasks` 导航从路由表派生；配置页仍三深度，列表→详情→编辑互斥；右侧预览/协助切换，不增加常驻第三栏。共用证据组件分别接实际运行快照和明确标记的模拟快照，不能共用一个模糊“成功”徽标。

测试文件名可按 `tests/task-*.test.js` 拆分（未来新增）；具体实现任务与命令在启动该轮时登记。现有前端合同/交付报告在真实实现后再更新，**本轮不把这些计划写成已采纳/已通过**。

### 8.4 原型验收与真实 Gate 分开

1. 无任务蓝图仍可手动建立/试用 FAQ；创建/保存/预览不会启动真实服务初始化。三深度同草稿、切专家/历史不串数据。
2. 同主体/周期重连、重复事件或换版不增重复义务；缺身份/类型/许可不采用；触达先候选，Agent 和人工使用同一校验。
3. 来源/执行版本分别可查，当前草稿不隐藏旧义务；事项候选与改动候选不混。
4. 人工锁、过期 revision、越界和撤权都有保留输入的冲突页；取消与替代不半成功，未知不自动重试，不任意勾完成。
5. L0–L2 按需查看但不扩权，阻断/停止/未知不可隐藏；隐藏名、旧 Schema 和披露后撤权的 mock 拒绝可复现，非动态 host 有明确降级说明。
6. Diff 按稳定 key；发布默认不迁移；影响无数据/无权不写0；基准过期重算；删蓝图不删义务、回滚不复活退订或重置次数。
7. Inbox 同源事项和权限视图、小屏/键盘、返回筛选/焦点、刷新恢复、助手关闭/失败与保存失败均可继续操作；详情未加载成功不能保存，失败后保留输入并可重试，切换历史版本只读。
8. 结构化条件的字段/算子/值摘要一致；条件不完整、字段目录缺失、旧字段或未知协议均可定位并阻断且不覆盖原输入；`0`/`false` 类型保持不变。无蓝图、空条件与未命中按明确语义展示；只有固定虚构输入的模拟求值才可显示命中，纯规则摘要不得冒充执行结果。
9. 多人修改导致基准 revision 变化时展示冲突字段与新旧依据，要求重新检查候选；重试同一保存请求不重复创建候选或改变关系。

以上本地断言只验证交互和投影。TM-03/07/08 的持久恢复、双 Worker、跨事项额度原子预留、停止/未知对账与真实渠道；AGI-02/03/08 的实际工具发现、不可见拒绝、输入快照与 host 降级；S1 音频/SSE 以及 S3 云恢复，均须各自运行证据，不能被模拟页面关闭。
