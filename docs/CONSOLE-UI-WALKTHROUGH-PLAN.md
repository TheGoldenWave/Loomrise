## 1. 范围与结论

本轮检查目标为 [第二轮本地工作台](../prototypes/console-next/index.html)（`prototypes/console-next`），覆盖代码结构、现行产品/交付边界、设计评估，以及专家列表和知识资料页的有内容/空内容浏览器状态。知识资料页另检查 390×844 移动视窗。未逐路由重跑全量交互测试；运行证据和局限见[第二轮前端交付与评审](S2-FRONTEND-ROUND2.md)。

**结论**：第二轮已经具备较好的结构化后台基础，尤其知识资料与物料库采用列表、详情、编辑互斥工作面，FAQ 行直显问题和标准解答，空态提供针对性动作。本轮不建议推倒重做。主要缺口在全局优先级与跨模块的一致性：七组导航和十个配置模块之间缺少清楚的“先处理什么”；概览首屏的主次不够鲜明；运行、案例、候选等列表需要进一步验证是否可快速比较，而不是滚动阅读多张完整详情；模拟/本地状态披露存在重复呈现。

**评审分数**：Nielsen 十项启发式 30/40（良好但仍有明显优化空间）。较弱项为帮助与任务指引（2/4）；选择负担、概览首屏竞争、导航优先级和新手术语理解均是本轮重点。

**已确认事实与边界**：`console-next` 是本地交互原型。浏览器本地保存、脚本模拟、模拟审批/绑定/部署不等于真实服务端持久化、模型、权限、渠道送达或发布。这里的优化建议只针对前端呈现，不变更产品范围、六层合同、权限或阶段 Gate。

### 中文优先文案抽查

本次对 `views/` 中可见的导航、标题、状态和操作文案作了定向静态抽查；这是源码审阅，不是完整的逐路由浏览器文案盘点。整体句子以中文为主，但高频概念仍混用多个有直接中文替代词的英文标签，增加不熟悉相关技术的客服运营者理解成本。“中文优先”针对用户可见文案，不要求翻译代码、协议、品牌或文件格式。

| 页面/区域 | 当前可见词 | 建议文案 | 判断与边界 |
|---|---|---|---|
| 客服应用导航、页面标题、空态 | `Inbox`、`人工 Inbox` | `会话收件箱`、`人工会话` | “收件箱”表达集合入口；页面标题按实际任务称“人工会话”，避免导航和页面名各说一套 |
| 客服应用导航、预览、物料入口 | `Widget`、`网站 Widget` | `网站客服窗`；首次帮助中说明“可嵌入网站的客服窗口” | Widget 是实现类别词，不是用户必须掌握的协议名；设置说明可称“嵌入式客服窗口” |
| 配置、知识、客服试用及辅助入口 | `Agent`、`Agent 协助`、`Agent 自动发送` | 面向用户按语境改为`智能客服`、`外部智能助手协助`、`智能客服自动发送` | “专家”是本项目既定配置对象名，不应全局替换成 Agent；若明确指外部 Agent，可首次写“外部智能体（Agent）”，后续用中文简称 |
| 知识资料类型 | `FAQ`、`问答 FAQ` | `问答`或`常见问答` | FAQ 是可直接中文表达的内容类型，不应与技术字段枚举混为一谈 |
| 知识资料录入 | `URL`、`授权页面 URL` | `网页`、`授权网页地址` | 地址输入仍保留实际网址示例和 URL 字段类型，界面标签无需英文缩写 |
| 业务动作、状态徽标、详细配置 | `Mock`、`Mock · 无外部写入` | `模拟`、`模拟操作 · 不会写入外部系统` | 用户需要知道副作用边界，不需要掌握 Mock 术语；不能只翻译标签而删掉事实说明 |
| 详细配置中的策略名称 | `Skill / SOP`、`ToolPolicy`、`ContextSnapshot` | `服务策略`、`业务动作权限策略`、`本次资料快照` | 中文业务名优先；英文合同名放在折叠后的技术定义中对照 |
| 模型预算与运行证据 | `token`、`Trace`、`revision`、`ID` | `模型用量单位（Token）`、`运行追踪`、`修订号`、`标识` | 首次确有必要时中文解释并括注标准术语；普通使用路径不显示内部标识 |
| 文件录入与支持格式 | `Markdown`、`JSON`、`PDF`、`DOCX`、`XLSX` | 中文描述搭配标准格式名，如`纯文本（TXT）`、`表格文件（CSV）`；格式列表可保留扩展名 | 扩展名、协议和代码/API 名称可保留；说明与限制用中文讲清楚实际可做什么 |

相同概念的命名也不够统一：同一产品并用“客服试用 / 试用台 / 脚本模拟”，客服应用中又同时出现 `Inbox`、`Widget` 和中文页面名。建议先维护面向用户的术语表，再沿完整任务路径统一导航、标题、按钮、状态、空态、屏幕阅读器名称和帮助文案。不要只替换单词而留下中英夹杂，或因翻译删掉关键事实。

**中文优先规范**：默认使用简体中文、直接业务词和具体动词；高频导航、主动作、状态、错误、空态及授权说明不得只用英文简称。仅在不可替代或确有互操作价值时保留英文，包括 Loomrise 等品牌、AI、标准协议/接口名、代码/API 标识、文件扩展名和用户输入的原文；需要向业务用户解释的术语采用“中文名称（英文标准名）”首次说明，之后使用中文。英文不能单独承载关键状态、阻断原因、权限或操作后果。技术详情可在具名折叠区内保留原始合同名和标识。

范围限制：表中替换项是设计建议，不代表已完成产品术语决策，也没有在本轮修改 UI。“专家”“智能客服”“智能体”分别指配置对象、运行中的业务助手和外部协作主体，不可为了追求纯中文混成一个概念；领域含义可能变化的词，应先在术语表中确认对象定义。

## 3. 全局交互原则

1. **集合对象先列表，单对象再详情，修改进入独立编辑工作面。** 列表首屏优先支持扫描、比较、筛选和进入下一动作。正在执行的工作区（客服对话、部署步骤等）不为统一样式而强制改成列表。
2. **先设计有内容状态，再设计空内容状态。** 有内容是运营者反复使用的主状态；列表列顺序、摘要密度和行级动作先服务快速识别。空态随后区分“集合为零”“搜索/筛选无结果”“内容存在但待处理/受限”三种情况，并提供与当前缺口相符的下一步。
3. **首层呈现决策必需信息。** 名称/内容摘要、当前状态、负责人/范围（适用时）、更新时间/版本和主动作可直接扫描。来源授权、机器 ID、完整差异、处理 trace、技术映射和稳定说明按需展开。
4. **隐藏方式有层级。** 低频但会影响判断的内容用具名折叠区或详情页；短辅助说明可用 tooltip；hover 只能补充提示，不承载键盘/触屏用户必须知道的信息、状态、阻断原因或关键操作。
5. **一个主任务、一个主动作。** 概览突出当前阻断项与直达修复动作；完成主要动作后的次级维护、演示边界和长期治理信息不得与其争夺同等视觉权重。
6. **状态只说一次，事实边界就近。** Shell 保留一个稳定的“本地原型”环境标识；某项模拟操作/结果在该操作附近标清模拟含义及其未证明的事实。避免侧栏、顶栏、上下文条反复出现相同的“本地演示”提示。

## 4. 子功能现状与两态优化方向

“有内容”与“无内容”不是简单的非空/空判断。每个集合应至少区分：真实/示例记录存在、无记录、筛选无结果、记录待处理或不可用；详情型任务则区分未选择对象与对象缺项。以下是下一轮设计和原型任务，不是已实现变更。

| 子功能 | 有内容状态优先级与现状 | 无内容/无结果与待处理态 | 优化计划 |
|---|---|---|---|
| 专家列表 | 已是表格列表；显示目标、草稿修订、可引用资料、入口绑定和继续配置 | “尚无专家”有手动创建动作；“无匹配专家”另有搜索恢复提示 | 保留为专家集合默认页；评估行内主动作与资料/绑定摘要是否足以判断优先级；避免每行重复长解释 |
| 业务概览 | 当前展示服务摘要、依据资料、业务动作、就绪状态和预览等多个首层区块 | 资料/配置缺项有直达修复入口 | 将“当前状态 + 最重要缺口 + 下一步”置于首屏；稳定摘要和低频预览细节按需展开。确认选中专家后先到概览还是版本/草稿列表，避免与 IA 草案冲突 |
| 业务配置/详细配置 | 同一草稿提供三种深度、十个模块；完整编辑能力和定义可达 | 各模块已有独立空态或添加引导；空白草稿可继续配置 | 模块目录显示状态（缺项/待确认/可用/可选）并按当前任务排序；保留完整目录，默认定位最高优先缺口；业务词为首层，六层/ID/合同映射在详细层 |
| 知识资料 | FAQ 列表直接显示问题、标准解答、可用状态和操作；搜索覆盖答案；桌面表格、手机标签行 | 空集合与搜索无结果分开；浏览器已验证 FAQ 有内容和网页为空两态 | 作为跨集合列表样板；维持内容摘要可读，过长回答折叠但行内可展开；授权、版本与处理细节保留在详情/折叠区，不重复展开稳定说明 |
| 物料库 | 已采用列表/详情/编辑分离；行摘要涵盖文件、简介/可用性与操作 | 空集合及无匹配有各自提示；授权/处理/撤回等状态存在 | 复核多类型列表的行间可比性：名称、类型、简介、范围/可用性、版本、主动作的稳定顺序；派生版本、后处理候选和自动发送策略继续折叠 |
| 客服 Inbox | 当前为队列 + 会话并排工作面；符合持续处理单条会话场景 | 未选会话和无会话分别给出创建入口；筛选无会话有恢复提示 | 保留队列工作面；优先检查队列的最近消息/时间、接待状态、未承接优先级和筛选效率。业务请求状态与接待占用分开呈现，详细证据收起 |
| 客服试用 / Widget / 联系页 | 以对话或预览为主的工作区，不是集合列表；Widget 与联系页配置旁有预览 | 空会话与未配置/未绑定状态需区分；FAQ、字段、入口缺项应分别给动作 | 保留工作面优先；把当前快照、模拟方式、数据/送达边界集中成轻量状态条；试用证据和安装诊断按需展开，缺口动作紧邻预览/对话 |
| 运行记录 | 运行是可检索、可定位的集合；记录详情用于审查单次证据 | 无运行、无筛选匹配、未解决/未知应区分 | 下一轮核查默认列表是否为可比较的紧凑行/表格；首层放结果状态、时间、版本、来源/问题摘要与证据入口，Trace/完整事件序列进详情 |
| 验收案例 | 案例为集合对象，单个案例含输入、期望业务状态、真值、来源和回放动作 | 无案例应指向从运行提名或手工新增；待复核与不可回放需显示原因 | 避免默认把每个案例展开成完整卡片长文；先列表/筛选/优先级，再进入单案例编辑/复核；真值与规则约束保持显式，不藏进 hover |
| 改动候选 | 候选集合适合按状态/基线/来源比较；单项含差异与回放 | 无候选指向运行提名；过期、待评估、受保护需分别说明 | 列表首层展示状态、基线、影响范围、来源和是否可采用；旧值/新值、逐案例对比与诊断折叠或进入详情，主动作随状态变化 |
| 版本与绑定 | 已有冻结版本表格；当前草稿检查/审批与绑定状态也需可扫读 | 无冻结版提示如何进行检查；不满足条件须直达修复项 | 保留版本列表；首屏分清当前草稿状态与历史版本记录，弱化演示说明重复占位；对比与恢复细节进入版本详情，禁止让模拟“已发布”被误读为真实上线 |
| 模型连接 / 自有云交付 | 连接是可复用对象集合；云交付当前更接近单次向导 | 空连接可引导创建声明/测试；没有部署实例不等同于部署失败 | 连接页按连接列表优先，密钥/协议诊断进详情且从不在前端展示凭据；部署保留任务流，未来存在多实例/历史计划后再加列表，不为迎合“列表优先”虚构对象 |

### 4.1 知识资料列表的严苛复核

这是本轮要求重点复核的既有优化，不因上一轮已完成而默认通过。

| 设计/体验维度 | 当前实现与证据 | 评审结论 |
|---|---|---|
| 内容优先 | FAQ 列表以问题、标准解答、可试用状态、行内编辑/详情为主；长答案默认三行摘要，可展开；搜索覆盖问题、答案和来源 | **基本通过**。相比标题优先或只显示问题的列表，更适合快速判断答复口径；仍需用长短混合数据验证行高和纵向扫描效率 |
| 信息层级 | 问答内容在首层；来源/授权、处理过程、修订与撤回在详情及具名折叠区 | **通过但需守边界**。授权是否可用、当前状态和失败原因不能再下沉；实现中状态理由已就近显示 |
| 计数与分类口径 | 在现有三条 FAQ 夹具下，FAQ Tab 显示 3，网页 Tab 显示 0；顶部摘要始终按全部类型显示“3 条资料 / 3 条可试用”，类型下方再显示“显示 0 / 0 条” | **P1 明确问题，且本轮浏览器实际走到该组合**。顶部数字本身是全局统计，但没有“全部类型”标签；用户在网页/文件空列表时会看到“有 3 条可试用”和“当前 0 条”，作用域冲突。必须给汇总标“全部资料”，或改为随当前类型变化；Tab 数、汇总数、筛选结果数三个口径需清楚区分 |
| 操作密度 | 每条 FAQ 同时提供“编辑问答”和“详情”；另有页面级“添加资料”、类型 Tab、搜索和状态筛选 | **P2 待可用性验证**。两种行内入口语义相近，12% 操作列在窄桌面下可能压缩文本列或增加行高。验证用户是否需要列表快编；若不需要，收敛为单一“查看/编辑”入口，在详情里保留修订 |
| 空态模型 | 当前类型零条显示“还没有…资料”及添加；搜索/状态无匹配显示调整筛选提示，不混为集合为空 | **通过**。新增“无结果”时不能再诱导重复创建；只读态要解释为何不能添加，而不是仅留下禁用按钮 |
| 交互连续性 | 列表、详情、表单互斥；返回保留搜索/筛选并聚焦发起行；取消修订不写入；类型切换清理旧条件；Tab 键支持方向键/Home/End | **行为证据较强**。既有浏览器脚本包含上述断言；本轮 92 项 Node 状态测试全过，但不能代替重新跑浏览器和辅助技术 |
| 响应式与可达性 | 390px 下转为带字段标签的纵向条目，主内容仍在；移动行操作最小高度 44px；摘要支持键盘焦点样式 | **部分通过**。本轮浏览器已观察 390px FAQ 与网页空态且无页面横溢；未重新逐项测高缩放、屏幕阅读器朗读、展开状态公告和长答案/长标题极值 |

据此，知识列表模式整体为**有条件通过**：主要内容优先、两态结构、基本键盘流和返回恢复有实现与测试证据；当前不能宣称“知识列表验收通过”。计数范围歧义必须修订或通过可用性验证排除；操作列取舍、长列表密度、辅助技术和只读空态仍缺验收。

相关实现与现有断言：[知识列表视图](../prototypes/console-next/views/knowledge.js)、[知识列表样式](../prototypes/console-next/knowledge.css)、[知识工作区浏览器检查](../prototypes/console-next/tests/knowledge-workspace-browser-check.js)。现有浏览器脚本验证筛选、搜索、三工作面、回退焦点和部分断点；**没有断言顶部计数作用域、操作列是否冗余、200% 缩放/屏幕阅读器或 20+ 条列表密度**。这些缺口应进入下轮验收用例，而不是沿用“9/9 通过”推断整体通过。

## 5. 优化优先级与计划

| 优先级 | 工作项 | 交付与验收重点 |
|---|---|---|
| P0 · 先定方向 | 冻结工作台一级导航分组、选中专家后的默认落点、集合页/详情页边界 | 对照 `S2-IA-NAV.md` 草案、第二轮路由及交付范围，形成单一 IA 决策；不要只做视觉微调后让两个层级继续并存 |
| P1 · 扫描效率 | 为运行、案例、改动候选及连接等集合统一列表首屏和行摘要合同 | 有内容时可在不进入详情的情况下识别状态、来源/版本和下一步；筛选无结果与集合为空有不同恢复路径 |
| P1 · 决策聚焦 | 重排业务概览与配置模块目录 | 概览主区先显示阻断/待确认项和直达动作；配置目录保留全量能力但突出待处理和必需项，避免十项同权 |
| P1 · 两态覆盖 | 建立后台状态矩阵并逐域补查 | 每个集合至少覆盖：有记录、零记录、无匹配、待处理/不可用、只读；每种状态均有清晰恢复/下一步，不把“空”与“不可用”混为一谈 |
| P1 · 知识计数口径 | 标清知识汇总数字按全部类型还是当前类型计数 | Tab 计数、汇总状态数、过滤后显示数三者定义一致、标签明确；切 FAQ/网页/文件和筛选时无歧义 |
| P1 · 中文优先 | 统一高频英文 UI 词和同义命名 | 先确认术语表，再统一导航、标题、操作、状态、空态、帮助与无障碍名称；可中文化的 `Inbox/Widget/Agent/Mock/FAQ/URL` 不再作为独立英文标签，AI 等保留项依规范解释；事实边界和操作后果不得因翻译丢失 |
| P2 · 知识行操作 | 验证“编辑问答”与“详情”是否都应常驻每行 | 以快速修订真实任务验证是否需要列表快编；操作列保持扫描友好，窄屏触控可达，避免重复入口 |
| P2 · 信息渐进 | 统一折叠/tooltip/详情使用规则 | 技术标识、完整 trace、来源授权、长差异默认收起；阻断原因和关键授权/状态不依赖 hover 才能获取；键盘及触屏均可达 |
| P2 · 文案与提示 | 减少首层术语和重复本地演示标记 | 导航与主操作使用直接业务词；如“专家”等领域名保留，则在首次/关键位置说明所指对象；同一环境标签只常驻一处，模拟含义在具体操作附近解释 |
| P3 · 效率补齐 | 对长列表验证分页/排序/批量操作、键盘效率和状态持久 | 依据真实目标数量与角色决定是否加入；不要先加筛选器、快捷键或批量操作再寻找使用场景 |

## 6. 下一轮验证门槛

- 用固定虚构夹具覆盖每个集合的有内容、零记录、筛选无结果、待处理/不可用和只读；至少包括低数据量与长内容。
- 知识列表验收至少满足：FAQ 行可直接读到问题和标准解答；长答复有不超过三行的默认摘要且可完整展开；搜索确实命中答案正文；Tab 数、汇总数字和当前显示数具有不同且清楚的作用域。
- 知识状态筛选中，可试用/待处理/不可用互斥且覆盖当前集合；空集合、零结果、只读和资料待处理不共享同一空态文案或无解释的禁用动作。
- 知识详情/编辑必须与列表互斥；取消不得修改数据；返回保留原类型、搜索、筛选和滚动位置并将焦点返还发起行；类型切换不携带无关搜索和详情。
- FAQ 列表在 390px、200% 浏览器缩放及长问题/长答案下不发生页面级横溢或内容遮挡；关键状态和阻断原因无需 hover，键盘可展开答案与到达全部操作；至少做一次 VoiceOver 或 NVDA 实测并记录朗读顺序。
- 使用 20–50 条混合长度、混合状态的虚构资料核查纵向密度、排序/筛选的可理解性和操作列拥挤；该数量是建议压力夹具，不是对真实客户数据规模的假设。
- 桌面 1440×900 和窄屏 390×844 逐个抽查代表性的列表、详情、编辑工作面；列表在窄屏转行卡片时仍保留字段标签、状态和主要动作。
- 检查键盘顺序、焦点返回、折叠可达性、tooltip 不承载唯一信息、状态不只靠颜色表达；不把静态检测器干净作为可访问性通过证据。
- 建立并核对面向用户的中英术语表；逐路由抽取用户可见的导航、按钮、标签、状态、错误、空态、帮助和无障碍名称。除 AI、品牌、标准协议/API 名、代码标识及文件扩展名等必要保留项外，界面不出现可直接替换的孤立英文词；首次保留术语有中文解释，后续表达一致，技术定义折叠显示。
- 在专家列表、知识资料、客服会话、物料库、试用、运行、验收和版本等代表性页面核对术语统一；验证窄屏/200% 缩放下中文可完整换行，英文括注不会挤压主要内容。记录术语清单与逐路由复核结果，不以源码搜索或全局替换代替语境判断。
- 检查列表到详情再返回后搜索、筛选、滚动位置与焦点保留；主动作在空态、待处理、只读、失败和过期状态下均有合理可恢复路径。
- 复跑对应 Node 行为测试和浏览器任务；把新增断言与实际路由/状态写入对应轮次报告。只报告本轮真实执行的视图与结果。
- 继续明确标记本地演示、脚本结果和后端待接能力；前端优化不能关闭 S2 服务端、授权、消息送达、评测发布或云交付 Gate。
