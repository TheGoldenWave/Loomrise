# 配置化后台启动方案 v0.1

状态：**执行方案，待确认**。2026-10-12。

本文回答三件事：**S2 配置化后台现在能不能起、起之前还差什么、按什么顺序起**。

- 信息架构与页面规格的唯一权威：[S2 平台信息架构与主菜单定义](S2-IA-NAV.md)（下称 IA-NAV）。
- 设计立项用的汇总文档：[S2 前端设计启动简报](S2-FRONTEND-DESIGN-BRIEF.md)。
- 本文**不改变 IA-NAV 的任何结论**，只补它没有覆盖的**启动前置与执行口径**。

---

## 0. 结论

1. **能起，而且设计与开发可以并行前半程。** IA 已基本定稿（6 域 / 16 二级页 / 22 面 / P0 14 / alpha 18），文档自陈「信息架构、页面清单与优先级可以现在定稿，不依赖执行内核」。
2. **"前端先行、后端反推"成立，但有一个前提**：必须**先把数据形状钉死**（字段级规格 + API 契约），否则反推出来的是两套。
3. **真正的缺口只有两处**：① **字段级配置规格**——IA 回答的是「配什么」，没回答「字段长什么样」；② **数据契约**——`AgentSpec` 本体、草稿版本容器、`ChangeProposal` 与 HTTP API 契约。
4. **本轮新增三条设计约束（§3）会改到 IA-NAV §4.3.2 三 tab 的内部结构**，必须在定稿前一并决定，否则骨架与设计稿要改两遍。
5. **另有一处必须先定的形状问题**：「硬性限制」（`HardRule`）当前的表达能力**只支持"调用某工具且参数等值"**，覆盖不了跨垂直场景的多数规则需求（10 类需求形态里 8 类表达不了）。表达模型见[硬规则表达模型](HARD-RULE-MODEL.md)，列为 **K0**——**它比 D3 更靠前**，因为规则的字段形状是 D3 里「边界 tab」那一节和 K1 `AgentSpec` 的共同输入。

## 2. 启动顺序

### 2.1 横向前置（引自 IA-NAV §5.1）

T0 本文档定稿 → **T1 前端骨架与路由** → **T2 只读 API 壳** → **T3 草稿版本读写**。

**补一条 T0 的产出定义**：T0 的产出**不只是**"IA-NAV 升 v1.0"，还包括 **D3 字段级配置规格**落定——否则 T3 没有输入。

### 2.2 起步路径（建议）

```text
0  IA-NAV 定稿（关 32–37）                                  ← 纯决策，无代码
1  K0 硬规则表达形状（六问裁决 → 定 `when`/`verdict`/`enforce`）  ← 只影响「边界」一节，但拖住 D3 与 K1
2  D3 字段级配置规格（三 tab 逐字段表）                      ← 设计稿与契约的公共输入
3  K6 API 契约（TS type + mock）                            ← 一个文件锁死数据形状
4  T1 骨架（路由表派生菜单 + expertScoped 页壳 + 指针路由）    ← mock 下即可点
5  T2 只读 API 壳（接 S1 真实数据）
6  T3 草稿读写（真正的后端工作量集中在此）
```

**为什么 3 排在 4 之前**：菜单是路由表的派生物（IA-NAV §1.1-6，菜单与路由写两遍必然漂移），而路由表要引用数据形状。先钉数据形状，骨架才不用返工——这正是"前端反推后端"唯一正确的方向。

**为什么 1 排在 2 之前**：D3 要产出「边界 tab」的逐字段表，而字段表的样子由 K0 的规则形状决定。**顺序反了会白写一遍**——若先按现行三值 `behavior` 出字段表，K0 一落地字段表就要重来。

页面铺开顺序（B1–B8）与交付边界见 IA-NAV §5.2，本文不重复。

## 3. 本轮新增设计约束（提案，待确认）

> 来源：一轮针对「**测评 / 审计 / 自迭代** 与 **运营持续参与**」的内部设计审计（对照成熟业务 Agent 中台的形态，方法已抽象）。
>
> 这三条**会改到 IA-NAV §4.3.2 三 tab 的内部结构**，必须在 T0 定稿前一并决定，否则 T1 骨架与三 tab 设计稿要改两遍。

| # | 约束 | 影响面 | 建议 |
|---|---|---|---|
| **A1** | **内容层与策略层分治** | 三 tab 内部结构 + 草稿机制 | 三 tab 内部再分 **`locked` 段**（合规红线 / 承诺边界 / 品牌底色）与 **`mutable` 段**（话术 / 示例 / 优先级）。**内容级改动（mutable 段 / 示例 / 知识）走"即时保存 + 异步回放告警"；策略级改动（locked 段 / 硬规则 / 权限 / 承诺）走"草稿版本 + 提交冻结"。** 现行"人工编辑一律不绕过门禁"对**日频内容劳动过重**，实际会被绕过 |
| **A2** | **审计要能回答「责任边界」** | `RunEvent` + 数据看板 + 运行详情 | 增加**归因分层**：合理静默 / 人工抢答 / 业务禁回 / 路由失败 / 工程失败。否则运营看到"没有回复"却看不到原因，会把合理静默误判为质量失败，优化方向被带偏 |
| **A3** | **补三个闭环件** | 变更域 + 验收域 | ① **被拒提案库**（拒绝理由 + 触发样例 + 影响范围；候选生成前先检索，避免重复提交已知失败方案）；② **改动量预算**（`edit_budget` + `touched_segments`，让回放退步可归因）；③ **评测体系自身的迭代闭环**（缺口发现 → 扩样 → Rubric 版本），防"只奖励旧标准定义过的能力" |

## 4. 待确认问题（启动前需拍）

### 4.1 来自 IA-NAV §6.4

### 4.2 来自 §3 的新增约束

对应 A1 / A2 / A3 是否采纳。

### 4.3 需明确的五项

| # | 问题 | 为什么必须现在回答 |
|---|---|---|
| **Q1** | **人机协同面是否进 Loomrise 范围？** 还是明确"只做交付者工作台，协同面留给业务应用" | 决定"运营持续参与"是否需要 Loomrise 承载；也决定 `CaseNomination` 要不要新增「人主动反馈（点踩 / 撤回 / 改写）」这一来源 |
| **Q2** | **是否引入 locked / mutable 段落协议？**（= A1） | 直接改 §4.3.2 三 tab 内部结构，**T1 之前必须定** |
| **Q3** | **表达层是否降级为免审批？** | 与现定"所有人可改、安全靠审批、**人工编辑不绕过门禁**"（`S2-SCOPE-DECISIONS` §20）**直接冲突**，必须二选一 |
| **Q4** | **是否引入内容所有权矩阵**（标准回复归谁 / 参考话术归谁 / 硬规则归谁） | 与"所有人可改"冲突。**注意：S2 明确不做登录与权限体系**（属 S3），故此项可能只能记入 S2-b / S3 |
| **Q5** | **评测体系迭代 Loop 是否纳入 S2** | 决定验收域要不要加"评测缺口"入口 |

### 4.4 来自 K0（硬规则表达形状，六问）

全部见[硬规则表达模型](HARD-RULE-MODEL.md) §9。**六问都是"改形状"级别**，不是措辞级别，回答后要同步 D3 字段表与 §4.3.2「边界 tab」：

| # | 问题 | 建议 |
|---|---|---|
| K0-1 | `Behavior.ALLOW` 是否移除、统一为四类（**修掉文实不一致**） | 移除，统一四类 |
| K0-2 | `when` 条件嵌套上限确认为 2 层 | 确认 |
| K0-3 | 条件是否允许引用**平台级**事实（非专家字段） | 允许只读引用，须显式声明来源 |
| K0-4 | `state`（计数 / 窗口）原子的窗口取值 | 先 `session` / `24h` / `forever` 三种 |
| K0-5 | `RuleTemplate` 首批骨架覆盖哪些场景 | **已定**：客服、销售各一套（见[产品定义 §定位](PRODUCT.md)） |
| K0-6 | 规则数告警阈值 | 建议 30 条 / 专家；超阈值必答"为什么不用 Skill 或字段表达" |

> K0-1 / K0-2 / K0-4 属于**定形状**（回答后 D3 才能写）；K0-3 / K0-5 / K0-6 可延到 S2-b，不阻塞。

## 5. 验收口径

沿用 IA-NAV §5.3 的四条（一次点击内可达 / 流程指示条正确 / 返回不丢状态 / 指针与逐层点进同一 URL），另加三条：

5. **字段级配置规格与实现一致**——三 tab 的每个配置项都能在**设计稿 · `AgentSpec` · API 契约**三处对上。其中「边界 · 硬性限制」还须与[硬规则表达模型](HARD-RULE-MODEL.md) 的 `when` / `verdict` / `enforce` 三段一致。
6. **未实现的入口一律置灰并标注目标版本**（已含在 §5.3-1，此处再强调：不得出现死链）。
7. **试用只有一个视图**——版本详情的"试用这一版"与运行域「试用台」必须落到同一 URL / 同一组件。
